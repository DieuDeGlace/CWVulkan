The bounded client block, column, zone-pointer, ray and indexed static-object queries inspected here use resident source data. An absent source-map entry and an entry containing a null zone pointer take their documented fallback or stop paths. These query bodies do not synchronously generate a source zone, enqueue missing-zone work or insert a null placeholder merely because a lookup misses. A separate model-lookup category remains unresolved; the results below are not generalized to it.

The source-map lookup helper 0x12700 searches an eight-byte coordinate key in the map supplied by its caller and writes a found-entry pointer or the map sentinel to its result storage. Its inspected body does not allocate, insert, create a source zone or post a task. The query paths below use this helper or equivalent inlined resident-map searches. Their map is World+0x460, with the sentinel at World+0x468 and a zone pointer in map-entry+0x18. A successful map-key lookup and a non-null source-zone pointer are separate tests.

The whole-block getter 0xE9A0 accepts signed 32-bit world X/Y/height coordinates. It floors horizontal division by 64 to form the signed zone X/Y key and calls the map lookup at 0xEA28. A missing key or null source-zone pointer copies six current bytes from the fallback record at image RVA 0x54DCB0 into the caller's result and returns that result pointer. The missing-zone branch does not test the requested height and does not use procedural colour/material generation.

Initializer 0x1100 writes the fallback record as RGB 200,200,200, fourth byte 0, type byte 1 and final flags byte 0. In hexadecimal byte order this is C8 C8 C8 00 01 00. The query copies that record, rather than synthesizing air or returning a null block-result pointer. This is the proved initialized fallback and its direct consumer; a complete census of later writers to those globals is not supplied.

The fixed-point getter 0xEAB0 accepts signed 64-bit X/Y/height components with 65536 units per whole block. It floors each component to signed 32-bit whole-block coordinates, including negative fractional values, then calls 0xE9A0 at 0xEB73. Its missing-source result is therefore the same six-byte record. It does not have a separate generation or queued-request branch.

When a non-null zone is present, 0xE9A0 delegates to zone getter 0xEB90. That getter validates the zone's horizontal half-open 64 by 64 block extent. It returns the same type-1 fallback for an invalid horizontal coordinate or a height below the stored column start. Inside the stored six-byte-record interval it copies the stored record through 0xE770. Above the stored interval at a positive world height it returns the initialized record FF FF FF 00 00 00 from 0x54DCB8; above that interval at nonpositive height it returns the initialized water record FF FF FF 00 02 00 at 0x54DCC0. Within the stored interval, an empty type-0 record at nonpositive height also becomes that water record when its final flags byte does not include bit 1. A nonzero stored type, a positive height or that flags bit instead preserves the copied record. The corresponding initializer bodies are 0x10E0 and 0x1120. These loaded-column fallback cases do not change the unconditional type-1 result for an absent/null source zone.

Column getter 0x935E0 also floors signed horizontal block coordinates by 64 and searches the resident source map. It returns null for an absent key, null zone pointer or a coordinate outside the selected zone's half-open horizontal extent. With a valid loaded zone it returns the corresponding column address in the array beginning at zone+0x518, whose columns have stride 0x58. It neither requests the missing column's zone nor substitutes a procedurally generated column.

The small zone-pointer getter 0x16E00 accepts a pair of 32-bit zone coordinates directly. It returns null on a missing map key and otherwise returns the stored zone pointer, including null if that is the entry's value. No load-region, view-distance, meshing or generation admission is performed by this getter. It can query a resident zone outside the separate source loader's current demand window without creating one there.

A limited mutation comparison is also proved. World block-edit wrapper 0xA37D0 searches the same resident map and calls 0x31C1C0 only when the entry and zone pointer are present. Its absent/null branch returns without making that call. It is directly reached from Game update 0xA5A50 at 0xA80FA. Wrapper 0x91160 calls column getter 0x935E0 and writes through 0xA36E0 only when the column exists and the signed requested height lies within its stored record interval; otherwise it returns. These missing-data branches do not create a source zone. Their complete loaded-data mutation effects and other callers are not re-audited.

The inspected ray-distance families are 0x12B10, 0x2A0D40 and 0x2D1D20. They first obtain the source zone containing the initial whole-block location, then step through loaded cells while their individual cell/flag predicates and step limits allow. When crossing a zone boundary, their inlined searches obtain the next resident zone pointer. If the initial source zone is absent/null, the traversal does not start. If a later source zone is absent/null, traversal stops at that reached point. There is no missing-source call to 0x2AE0C0, source-map insertion helper or task submission on these paths.

For a positive finite requested maximum distance, an initially missing source returns distance zero from these ray paths. Missing source encountered after traversal returns the accumulated distance, capped by the requested maximum. The returns converge at 0x1300D for 0x12B10, 0x2A1206 for 0x2A0D40 and 0x2D2216 for 0x2D1D20. Their distance state and return value are 32-bit floats. This is a traversal stop caused by a null source pointer, not a call to the six-byte block fallback. Their loaded-cell predicates differ, including flag-controlled cases, and are not replaced here with one universal solid/empty test.

The indexed static-object lookup is independently established as 0x2C3150. Its input identifies a source-zone key in the first eight bytes and a signed 32-bit object index at offset 8. It searches World+0x460. It returns null when the source-map entry is absent, its zone pointer is null, the index is negative, or the index is at least the number of 0xE0-byte records in zone+0x60/+0x68. Its common failure return is 0x2C31E6. On success it returns the selected record's address in that loaded array. The complete inspected getter has no source generation, enqueue or insertion path.

A concrete client static-object consumer is Game-side routine 0x98180: at 0x99A2D it calls 0x2C3150 with Game+0x8 and the reference at Game+0x1E7C. At that reached call's null-result branch the caller returns 0. This establishes a client-side missing-static-reference outcome, without classifying all earlier or alternative interaction branches. The 0x13830 physics caller has its separate static lookup at 0x14A5D and skips the reached handling when the getter returns null. A static-object reference does not itself cause the source zone to be loaded.

The explicit source-generating routine remains a different category. At entry 0x2AE0C0 returns a previously loaded non-null zone; a miss reaches random seeding, source-zone allocation/construction and 0x2FF6F0 generation, followed by source-map installation through 0x299640 at 0x2AE34A under World+0x3F0 and +0x3C8. That routine itself does not check the separate source loader's spatial demand region. Calling it with an outside coordinate would therefore be materially different from calling the inspected getters. This does not prove that an ordinary client query makes such a call.

The directly resolved client invocation category for that generator is the separate source-loader batch, through 0x7D5C0 and the reached 0x858E0 chores. The host's direct generator call at 0xF2CBE operates on the separate embedded host World. The loader's spatial admission occurs when it collects its candidate batch. The generator's final source-map installation does not recheck the player's then-current centre or settings; this audit therefore does not guarantee that an earlier admitted batch remains inside the current demand window when it completes. No new ordinary client block, column, ray or indexed static-object query producer of source-map entries outside the loader demand region was established in this audit. This is a bounded positive-path result, not a global absence-of-writers or absence-of-callers claim.
