The two output pairs are position X/Y and size X/Y, each pair consisting of two binary32 words. The index parameter of both 0x352310 and 0x351650 is a signed 32-bit integer carried in R8D. A floating type printed for this parameter in the C export does not describe the native call interface. Text is an original 0x20-byte string object: length and capacity are unsigned 64-bit fields at +0x10 and +0x18; capacity below eight selects inline storage, otherwise the first eight bytes are a storage pointer. The metric and wrapping loops use the low 32 bits of length with signed comparisons. Units are unsigned 16-bit code units loaded individually; these owners do not combine surrogate pairs or perform an independent Unicode-character conversion.

The complete wrapper at 0x352310 first enters the critical section at F+0x168, then calls configuration 0x354600. Its inputs after F, text, signed index and a matrix pointer are five binary32 operands, called A, B, C, D and W here, the two output pointers, a 32-bit flag word and a byte-valued option. The wrapper computes the vertical scale by dividing A by the current F+0x134, then the horizontal scale by dividing A by the current F+0x130. When the byte option is nonzero it divides W by the horizontal scale. These are distinct binary32 divisions in that order; no equivalent reassociation is asserted.

Flag bit 0x10 selects a temporary copy of the whole text, followed by wrapping at 0x354F20 with the adjusted W. It then calls 0x351650 on that copy with the original signed index and flag word, and frees the copy's external storage when its capacity is at least eight. Without bit 0x10 it calls 0x351650 directly on the supplied string. The normal continuation multiplies and stores position X by the horizontal scale, position Y by the vertical scale, size X by the horizontal scale and size Y by the vertical scale, in that order, then leaves F+0x168. The matrix is used by configuration; this wrapper does not subsequently transform the returned point by that matrix.

The reached freeing helper 0x33B10 checks the supplied size and, on its large-allocation path, pointer alignment and the stored allocation-base displacement before calling the runtime free boundary. Configuration 0x354600 has three distinct routes. With F+0x148 nonzero, it first stores D at +0x140, then A at +0x130, A at +0x134, B at +0x138, C at +0x13C and zero to the byte at +0x160. The short setup entry 0x354190 passes its first binary32 operand as both size dimensions and its second operand as expansion, tail-reaching 0x3541A0. It has no independent lock. The finite-input behavior of 0x3541A0 first replaces a nonpositive Y by X, then replaces a nonpositive X by the resulting Y, rejects if the resulting sizes remain nonpositive, and rejects a negative expansion. Zero expansion is accepted. Native comparisons also admit some unordered operands: the initial Y comparison retains an unordered Y, the corresponding X admission can admit an unordered X or replacement Y, and the expansion rejection is only the ordered-negative branch. This is not a general nonfinite sanitizer.

On admission, 0x3541A0 stores the size X, size Y and expansion at F+0x130/+0x134/+0x138 in that order. The complete helper 0x354740 writes matrix-derived state before its A admission check. It copies matrix word zero to F+0xC0, word one to +0xC4, word five to +0xD4 and word four to +0xD0, in that order. It separately multiplies matrix word zero by 65536 and truncates to signed 32 bits for +0xB0; multiplies word one by 65536, truncates and negates for +0xB8; multiplies word five by 65536 and truncates for +0xBC; and multiplies word four by 65536, truncates and negates for +0xB4. For finite A, this helper returns after those writes when A is nonpositive. An unordered A follows the admission side if execution continues with floating exceptions masked. On admission it writes zero to +0x160 and A to +0x130 and +0x134. It computes the vertical norm first and the horizontal norm second. The vertical two components are formed by multiplying matrix word one by zero and adding word five, and multiplying word zero by zero and adding word four. The horizontal components use word five times zero plus word one, and word four times zero plus word zero. For each norm it squares the Y component and X component separately, adds the Y square to the X square in the native association and calls sqrtf. Those zero multiplications remain operations for nonfinite operands. The finite smaller norm is selected; the comparison selects the horizontal operand on equality or unordered comparison. B is multiplied by the selected norm and stored at F+0x138.

This route calls 0x3993A0 using the A size rounded by multiplication by 64, addition of 0.5 and signed truncation for both dimensions, then 0x399610 with F+0xB0 and zero. Its F+0xA0 cache key contains the rounded A word, an expansion key word, and a copied vector of the four signed words at +0xB0, +0xB4, +0xB8 and +0xBC. The primary expansion key is zero. Once the collection is selected, the secondary provider call uses the current scaled F+0x138. Nonpositive or unordered B makes F+0x108 null. Temporary vector storage is cleaned up after the selected calls. Provider statuses do not cause a rollback in this owner.

The complete derivation helper 0x354CF0 has an alternate generic branch that simply returns A, A, B, C and D when F+0x148 is nonzero. The dispatcher described above does not reach that branch. Its zero-field branch computes the horizontal norm first, then vertical norm, using the same four matrix words and explicit zero products. Each norm is multiplied by A. Each quantized dimension strictly greater than 1000 is capped to 1000; an unordered comparison does not take that cap.

Only after those caps does the helper divide the current Y by A and then the current X by A. It adds those two ratios, multiplies by 0.5 and then by B for the derived expansion. The core metric owner 0x351650 first derives a carried factor of one when F+0x148 is zero. Otherwise it subtracts the binary32 word F+0x154 from F+0x15C and divides the current H by that rounded difference. It clamps the signed index down to the signed low 32-bit text length only when the index is greater. It does not clamp a negative index up to zero. In order it stores position X as zero, position Y as the sign-bit-flipped current H, size Y as current H, and size X as zero.

Before examining the requested index, it always calls bounds owner 0x350EB0 for the whole text with zero flags, signed start -1 and auxiliary byte zero, and again for the first line with the supplied flags, start zero and auxiliary zero. It carries the first call's whole lower and upper X values. The line-width correction is formed by subtracting the line lower X from its upper X, subtracting the carried whole upper X and then adding the carried whole lower X, with a separate binary32 operation at each step. Flag bit one multiplies this correction by 0.5 and subtracts it from position X; otherwise bit two subtracts the full correction. Bit one takes priority when both are present.

A negative effective index skips the indexed loop, but still has the preceding bounds calls, their glyph/provider/cache effects and any final alignment. For a nonnegative index, the loop visits code units from zero through the effective index inclusively. A line feed, numeric unit 10, is a line transition only when it is before the target index. That transition resets position X to zero, queries bounds from the following unit using the supplied flags, derives the same width correction against the carried whole values and applies the one-half/full correction selected above. It then adds F+0x140 to the current F+0x134 first, and adds that rounded result to the current position Y. It does not advance Y by adding the three operands in a different association.

On the other branch, a zero code unit stops this indexed loop before glyph lookup. Otherwise 0x352090 is called for that unit. A nonnull G contributes its binary32 +0x10 advance multiplied by the carried factor. For a unit before the target, that product is added to position X; at the target it is stored to size X. A missing glyph contributes neither update, leaving the existing/default outputs in place.

The gap and pair-metric continuation is admitted only when the current signed 32-bit loop counter is strictly less than the effective target index minus one. It therefore does not run for the target or for its immediate predecessor. When F+0x148 is zero, it maps the NEXT code unit through 0x3961F0 first, maps the CURRENT code unit second, then calls 0x396210 with current mapped value, next mapped value and an output pair of signed 32-bit words. Only its first word is consumed. With F+0x160 nonzero the call's mode is zero; the returned signed word is arithmetically shifted right by six, converted to binary32 and added to position X. With F+0x160 zero the mode is two; the signed word is converted to binary32, multiplied by the current F+0x130, divided by the binary32 conversion of the unsigned 16-bit field at current face+0x68, and then added to position X. Returned status is ignored.

After that conditional pair contribution, including when F+0x148 was nonzero and no pair query occurred, the current F+0x13C is added to position X. If the current mode byte is nonzero, the resulting X is truncated to signed 32 bits and converted back to binary32. Size X is not subjected to that truncation. Values read after a provider boundary are current reads where the native owner reloads them; the carried factor and carried whole X bounds are not a promise that all receiver state was sampled atomically.

With a zero flag word the core returns after this loop. Any nonzero flag word causes another whole-text bounds query with flags zero, start -1 and auxiliary zero. Bit one subtracts the whole lower X plus whole upper X, rounded as an addition and then multiplied by 0.5; otherwise bit two subtracts whole upper X. Bit four similarly subtracts the averaged whole lower/upper Y; otherwise bit eight subtracts whole upper Y. One takes priority over two and four over eight. Other set bits can cause the extra query without directly shifting either coordinate. These final operations do not change size X or size Y.

For a stable valid string whose nonnegative length fits signed 32 bits and whose terminator is present, index equal to length reaches that terminator and retains size X zero. An index greater than length is clamped to that case. For empty text, any nonnegative index is clamped to zero, so the outputs before optional alignment/scaling are position zero/sign-flipped H and size zero/H. A negative index also retains those defaults before optional alignment/scaling, while still executing bounds. A line feed at the target takes the ordinary glyph branch; its target width can therefore depend on a glyph record, and it does not yet advance the line. Only passing beyond that line feed takes the Y transition. Carriage return, numeric unit 13, is ordinary in this indexed loop. A space, numeric unit 32, is also ordinary. An embedded zero unit stops this loop even when the stored length is larger. These distinctions do not prevent the earlier bounds or wrapping passes from having already called providers for the same text.

The complete bounds owner 0x350EB0 is needed to determine both alignment and the side effects of those early queries. Its two output pairs are lower X/Y and upper X/Y. A negative signed start selects the whole range beginning at zero and ending at the signed low 32-bit length. A nonnegative start is retained; when it is at most length, a preliminary scan through the length position stops at the first line feed and uses that position as the end. That preliminary scan does not stop at an embedded zero. A start beyond length has no forward range. With auxiliary zero, the iteration excludes the end index; with auxiliary nonzero it includes that end index through a 32-bit increment.

The owner stores lower Y as the sign-bit-flipped H, lower X zero and the upper pair as eight zero bytes. Its pen starts at zero/zero and its first-box marker is set. It independently derives the same one or H/span factor as described above. For every visited unit it obtains a glyph BEFORE its line-feed, carriage-return or zero-unit progression decisions. On the nonzero F+0x148 route it searches F+0x110 by the zero-extended 16-bit unit represented as a signed 32-bit key; a hit writes one to G+0x38. On the zero route it selects 0x351B20 when the mode byte is nonzero and 0x3524F0 otherwise, using F+0x100 and secondary-option zero.

If F+0x138 is strictly positive, bounds then replaces that result with the corresponding lookup/production using F+0x108 and secondary-option one. It does not fall back to the primary G if this second result is null. A nonpositive or unordered expansion skips this replacement. This route can therefore obtain primary and secondary glyphs even for control units before suppressing their boxes.

With auxiliary zero and a nonnull glyph, line feed and carriage return suppress the box contribution. On the zero F+0x148 route, each box lower coordinate adds the pen to G's corresponding origin, then adds one; each upper coordinate adds the pen to that origin, then the corresponding G size, then subtracts one. On the nonzero route, lower X first adds G+0x18 to G+0x0, multiplies by the factor and adds pen X; lower Y uses +0x1C and +0x4. Upper X/Y similarly use +0x20/+0x24 and the same origin words. No box normalization or positive-size admission is present here. The first admitted box replaces all four output coordinates. Later boxes select the lower minimum and upper maximum for ordinary ordered finite values. The actual compare-and-branch selection can choose the new operand on unordered comparisons; a general library-style NaN-minimum rule is not asserted.

Auxiliary nonzero suppresses all boxes and instead compares the current pen against upper X/Y before progression. Lower defaults remain. It still obtains the glyph records. Including the end position permits the ending pen to participate, which is a distinct interface from the auxiliary-zero queries used by 0x351650.

For progression, a line feed resets pen X and increments pen Y by first adding current F+0x140 and F+0x134, then adding that rounded line step to pen Y. A zero unit stops after the preceding potential glyph/box work. Otherwise a nonnull G adds factor times G+0x10 to pen X. If the current index precedes the final visited index AND the next code unit is not line feed, it then performs the same next-map-before-current-map pair query and mode-dependent conversion when F+0x148 is zero, adds the pair result to pen X, adds the current gap F+0x13C, and truncates through signed 32 bits when the mode byte is nonzero. A next line feed skips both that pair and gap continuation. Carriage return can advance and participate in gaps despite having no box. Thus the bounds pass and the indexed pass have different end/gap/control-unit rules.

After its pass, any nonzero bounds flags recursively request whole-text bounds with zero flags and the same auxiliary byte. It applies the selected whole X and Y alignment shifts to BOTH lower and upper output pairs. The X/Y bit priorities are the same one-over-two and four-over-eight described above. This particular recursion ends because the recursive flag word is zero. It is distinct from arbitrary recursion through external callbacks or cyclic object graphs.

The complete wrapping owner 0x354F20 uses signed low 32-bit length and derives its factor before returning for a nonpositive length. For positive length, the carried width and saved boundary width start at zero and the previous boundary index starts at signed -1. At each code unit it first admits a boundary decision for a space, line feed, carriage return or the last stored unit. That decision compares the carried width with W BEFORE obtaining the current glyph or adding its advance. The finite greater-or-equal side replaces the PREVIOUS boundary unit by numeric line feed 10 when the previous index is nonnegative, then subtracts the saved boundary width from the carried width even when no previous unit was replaced. It then records the current index as the next previous boundary and records the current carried width. The less or unordered comparison side skips the replacement/subtraction but still records the current boundary.

A current line feed or carriage return next resets carried width and saved width to zero and skips glyph/gap work. Every other current unit, including a zero unit, is looked up through 0x352090. Its local advance starts at zero and is replaced by G+0x10 on a hit. Before the last stored unit, and only on the zero F+0x148 route, the next mapped code, current mapped code and pair query occur in that order. The mode-converted pair value is added to the LOCAL ADVANCE here. Before the last unit the gap is separately added to the CARRIED WIDTH even on the nonzero F+0x148 route. With mode byte zero, local advance is multiplied by the factor and added to the carried width. With mode byte nonzero, local advance is added to carried width, truncated to signed 32 bits and converted back to binary32; that branch does not multiply by the carried factor.

Wrapping does not stop at an embedded zero, append or remove units, or change the stored length. It can replace a prior boundary unit, rather than the current boundary. A run with no previous eligible boundary has no arbitrary internal split. The last glyph can raise final width above W after the last comparison without another test. In the outer metric wrapper these modifications are to its temporary string; direct alternate callers of 0x354F20 can supply other ownership.

Glyph entry 0x352090 is only 127 native bytes and must not be enlarged to match a decompiler-expanded tail. With F+0x148 nonzero it searches F+0x110 by code-unit key, returns null on a miss and marks G+0x38 on a hit. Otherwise it takes the primary collection F+0x100, passing secondary-option zero, and tail-reaches 0x351B20 for nonzero mode or 0x3524F0 for zero mode. On the 0x351B20 miss route, 0x3993A0 is called with rounded current horizontal/vertical sizes. The produced record is 0x40 bytes and is zero-initialized on allocation. Its pointer is published into the selected tree entry BEFORE the later metric stores. The reached stores convert capture+0x20 minus one to the X origin, the signed 32-bit bitwise complement of capture+0x24 to the Y origin, and the extended capture dimension counts to the size words. The 0x3524F0 miss route calls 0x3993A0 and then calls 0x399610 with F+0xB0 BEFORE checking the size-call status. Only a zero size status reaches 0x396C00 with numeric flags ten. On success, this owner derives transformed provider-geometry corners using the current signed fixed-matrix words converted by 1/65536 and provider size words converted by 1/64, obtains the finite extrema through its reached comparisons, multiplies the resulting spans, calls sqrtf and divides 500 by that return. It then captures, optionally configures/transforms the secondary state using current expansion times 64 times the factor followed by addition of 0.5 and signed truncation, converts, builds the bordered temporary buffer when dimensions admit it and calls the same resource-provider slot. Its G+0x10 instead uses the CURRENT signed 32-bit field at current face+0x78, then +0x40, converted to binary32 and multiplied by 1/64. That advance is not divided by the temporary factor. G+0x14 is zero. Resource, mark and capture cleanup follow. The +0x18..+0x24 operands of records already present on the nonzero F+0x148 route have untraced producers in this audit.

The selected original face mapping interface 0x3961F0 returns zero for a null face or null face+0x88; otherwise it tail-calls the object at face+0x88 through virtual offset +0x18. The selected pair interface 0x396210 returns numeric status 0x23 for a null face WITHOUT initializing the output pair, and status six for a null output pointer. For a valid face and output pointer it first initializes eight output bytes to zero, then conditionally reaches the callback under face+0x90, its +0x28 object and that object's +0x90 slot. An absent callback leaves zero output and returns zero. A nonzero callback status returns that status with whatever output it has written. On success, mode two bypasses the later normalization; other modes can reach original internal scaling helpers not expanded here, and the mode-zero selected continuation includes six-bit quantization. Metric callers ignore the status and use the first output word. Therefore a null face is not proved to supply a zero pair contribution.
