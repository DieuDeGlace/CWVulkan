Native Steam mesh-worker concurrency addendum — 2026-11-07

For mesh worker RVA 0x842D0, a detected change of Game+0x1BA0 to zero configures minimum concurrency 1 and maximum concurrency 4. A detected change to any nonzero value configures minimum 1 and maximum 8. These are the arguments of the worker's explicit scheduler-creation branch. The native option defaults to 1, while the worker's remembered value also starts at 1, so its ordinary default first cycle skips that branch. This audit does not assign an effective initial runtime maximum to that skipped-creation path.

Evidence is the original x64 Steam image binary/cubeworld.original.exe.unpacked.exe under C:/Users/DieuDeGlace/Documents/decompiled cube world steam: preferred base 0x140000000, PE timestamp 0x5D93AB0D, SHA256 7AF18CB28C8BF848F355287428C6390B2EA2A682CA466190F5EB9859C5D6F244. All addresses below are RVAs. Only individually identified original per-routine files, the original-owned assembly listing and image bytes were inspected. No SDK/dependency source, reconstruction, replacement implementation, tests, exporter, outputs, captures, logs or project history were read. Earlier held contracts remain unchanged.

Game+0x1BA0 is the 32-bit option at offset 0x18 within the options block beginning at Game+0x1B88. Its persisted native key is cpuPerformance. Options constructor 0x13A9E0 writes its default value 1 at 0x13AA01. The startup initializer at 0x2AA0 applies that constructor to the global options block. Startup routine 0x1355A0 then loads options through 0x13AA50 at 0x135BA8, writes them through 0x13B1D0 at 0x135BB0, and supplies that block to Game constructor 0x7EA80 at 0x136331. The Game constructor's copy at 0x7ECDA includes this field. A saved option can therefore replace the constructor default; no current options.cfg contents were inspected.

The reader recognizes cpuPerformance and extracts a signed integer into options+0x18 at 0x13ACDC. The writer emits that field at 0x13B337–0x13B33A. The options editor uses an embedded options block at offset 0x310, placing this field at editor+0x328. Its callbacks at 0x28B160 and 0x28B170 write 0 and 1, respectively. Display routine 0x288C50, at the decision around 0x2897DC, labels zero REDUCED and nonzero FULL under the caption CPU Usage. Thus the UI's FULL value is 1 and its REDUCED value is 0; the worker itself accepts the broader zero-versus-nonzero distinction.

Apply callback 0x28B350 passes the editor block to 0x89C10. That routine acquires world+0x3C8 at 0x89C29, copies the supplied options into Game+0x1B88, including the CPU field in the copy at 0x89C3F, saves through 0x13B1D0 at 0x89C61, and releases the world guard through the exit at 0x89CAB. The worker samples the preference under the same guard, acquired at 0x84360. The setting is sampled during an unpaused outer cycle; this does not introduce an immediate cancellation or reconfiguration inside a running mesh batch.

At worker entry, 0x84315 initializes the remembered raw 32-bit preference to 1, also retained in local storage at 0x8431B. At 0x84496–0x844A0, the worker compares the current Game field with that remembered value. Equality bypasses all priority and scheduler-policy operations. A difference records the new raw value and enters the change branch. This is a raw-value comparison: changes between two unequal nonzero integers can reenter the branch even though both choose the same concurrency limits.

The exact limit selection is at 0x844CC–0x844E2. The second limit begins as 4 and changes to 8 for a nonzero preference; the first limit is 1 in both cases. The value 8 is established at worker entry by 0x84332 and restored for subsequent cycles at 0x84ED3. The same change branch submits a worker-thread priority argument of minus 1 for zero and 0 for nonzero at 0x844BB. Scheduler policy identifier 6 receives the 32-bit value 0xFFFFFFFF for zero or 0 for nonzero at 0x844F5. No SDK enumeration name or wider priority guarantee is assigned to that numeric policy identifier here.

The original image's CONCRT140.dll imports independently identify the scheduler operations. The worker constructs a temporary SchedulerPolicy at 0x844C5, sets its concurrency limits at 0x844E2 and policy value at 0x844F5, calls CurrentScheduler Create at 0x844FF, and destroys the temporary policy at 0x8450A. Destruction of that temporary policy is not an observed destruction of the created scheduler. The worker body and its direct thread-entry wrapper 0x890C0 contain no explicit current-scheduler detach or scheduler-destruction operation. Repeated detected changes issue further Create calls; replacement, attachment-stack and final runtime reclamation behavior remain outside the inspected original game code.

The default value 1 therefore has a material timing distinction. If it remains 1 from entry, 0x842D0 performs no explicit scheduler creation before the first batch or subsequent unchanged cycles, and this branch also supplies no initial thread-priority adjustment. If the option later becomes zero, the worker creates the 1-to-4 policy. A later change back to 1 creates the 1-to-8 policy. Runtime defaults, automatic initial scheduler creation, inherited context and the effective initial processor allocation were not established from these original calls.

The configuration branch precedes the ordinary cycle's retirement, candidate selection and selected mesh batch. The batch call is 0x84C19 through 0x7D680. Zero selected entries schedule no mesh work there; one entry reaches the mesher directly at 0x7D6CE; multiple entries enter 0x77120 at 0x7D6F8. That helper queries the current scheduler's virtual-processor count at 0x77194, schedules chores at 0x77358, and reaches RunAndWait at 0x773F3. The reached chore helper 0x85DC0 also uses task collections and RunAndWait at 0x861A3, without selecting a separate policy. This is the directly proved batch/task path following the worker's configuration call.

Normal batch return, preparation, publication and cleanup precede the next preference sample. An unchanged sample skips Create, so scheduler construction is not performed once per batch. Task collections are completed and destroyed at their own batch boundaries; that does not prove that the current scheduler ends there. The independently selected maximum of eight zone coordinates also does not establish eight simultaneous tasks, eight worker threads, or the actual runtime concurrency. Those quantities are not inferred from a configured maximum or minimum.

Routine 0x84F70 is a separate worker path that also reads this option. Its explicit initial policy creation at 0x8500F uses limits 1 and 4 before its own remembered-value comparison. That call is not part of entry to mesh worker 0x842D0 and does not establish the mesh worker's initial scheduler. The work performed by that separate worker is outside this small addendum.
