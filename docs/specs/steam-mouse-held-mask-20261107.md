# Steam held-mouse-button field: bounded original-evidence contract

FINAL / STABLE / HELD. This contract concerns only the original Steam x64 image with preferred base 0x140000000, PE timestamp 0x5D93AB0D, and SHA256 7AF18CB28C8BF848F355287428C6390B2EA2A682CA466190F5EB9859C5D6F244. The image hash, timestamp, and base were checked directly. Evidence consists of that image and its original decompiler, assembly, and call-list outputs under the assigned original Steam evidence directory. No reconstruction or replacement-engine evidence is used.

The field at engine offset 0x1A8 is a stored 32-bit button mask. Button number 0 corresponds to bit 0, button number 1 to bit 1, and button number 2 to bit 2. The mouse handler at RVA 0x97880 reads bit 1 for its two right-button-dependent motion branches and bit 0 for its left-button-dependent camera condition. Its engine pointer comes from game offset 0x20. The field is distinct from the per-game action-state bytes described below.

The base-engine constructor at RVA 0x339B70 initializes the entire 32-bit field to zero; the specific initialization store is at RVA 0x339DA6. The derived-engine constructor at RVA 0x38E100 invokes that base constructor on the same object. This establishes construction-time initialization, rather than an assumption that allocated memory happens to be zero. It does not establish all subsequent possible reinitialization or destruction behavior.

The directly identified button producers modify one bit while preserving the other 31 bits. The button-0 down helper at RVA 0x340EC0 sets bit 0, with the store operation at RVA 0x340ECF. Its up helper at RVA 0x3410E0 clears bit 0 at RVA 0x3410EF. The button-1 down helper at RVA 0x3415F0 sets bit 1 at RVA 0x3415FF; its up helper at RVA 0x341780 clears bit 1 at RVA 0x34178F. For comparison, button 2 uses RVA 0x341300 to set bit 2 at RVA 0x34130F, and RVA 0x3414A0 to clear it at RVA 0x3414AF. These operations occur before the helpers' subsequent widget lookup and dispatch. The mask update is therefore not conditional on finding an eligible widget in those helpers.

The common game down callback at RVA 0x94900 passes its original button number to the UI down dispatcher at RVA 0x101020. The assembly at RVA 0x94953 confirms this argument even though the down callback's decompilation omits it at that call site. The dispatcher reaches the engine through its owning-game backpointer at UI offset 0x5C0 and game offset 0x20, then selects the down helper for button 0, 1, or 2. The embedded UI object begins at game offset 0x118; its owning-game backpointer is initialized by RVA 0xF8690, called during the game constructor at RVA 0x7EA80. The common game up callback at RVA 0x965E0 reaches dispatcher RVA 0x101120 at call site RVA 0x96767, which selects the corresponding up helper through the same pointer chain. Thus invoking these common callbacks does reach mask-producing operations; they are not merely unrelated game notifications. The down dispatcher is reached before the down callback's later early-return checks.

The window procedure at RVA 0x133C70 handles left-button down/up messages 0x201 and 0x202 with common callback button number 0, right-button down/up messages 0x204 and 0x205 with button number 1, and middle-button down/up messages 0x207 and 0x208 with button number 2. The down paths acquire window capture before the callback, and the up paths release capture before the callback. These window-procedure branches do not directly store to engine offset 0x1A8, but their common-callback chain does set or clear the corresponding mask bit as described above. In particular, describing these paths as callback-only must not be taken to mean that they leave the mask untouched.

The input loop belongs to RVA 0x1355A0. After draining window messages, an eligible foreground pass polls the keyboard state and a separate 16-byte physical mouse-state buffer; the physical mouse poll call is at RVA 0x136672. The four button-state bytes are buffer offsets 12 through 15. In the branch where predicate RVA 0x9AE50 is false, mouse bindings numbered 0 through 3 are read from those newly polled bytes, converted to booleans, and passed to the action-state setter at RVA 0xA36C0. That setter writes only the selected byte within game offsets 0x1A70 through 0x1A86. The original mouse-binding read is at RVA 0x1367B5. These physical-state reads and the action setter do not assign the newly polled mouse bits to the engine mask and do not invoke the common down/up callbacks in this action-refresh path. The alternate branch uses transitions between the previous and new physical state for binding-selection notifications, which are separate calls from the common mouse down/up callbacks. The inspected direct calls for that branch are at RVAs 0x8A120 and 0x8A4F0; this contract does not claim to audit every transitive effect of binding-selection code.

The normal action-refresh path then calls the mouse handler at RVA 0x13683E. XInput polling and any controller-synthesized mouse callbacks occur afterward, with the controller poll at RVA 0x136881. The physical mouse-state buffer is copied to its previous-state snapshot near RVA 0x137B72. Consequently the newly polled physical button bytes and the engine-held mask are separate inputs in this loop: the polled bytes do not replace the mask before that mouse-handler invocation. A controller callback generated later in the same pass changes the stored mask after that invocation. The inspected direct loop contains no per-pass clearing or reconstruction of this mask from the physical bytes.

Controller A, X, and Y correspond here to controller button-word masks 0x1000, 0x4000, and 0x8000. Their synthesized mouse callbacks are gated by successful controller polling and the branches in RVA 0x1355A0. When game offset 0x668 is nonzero, A transitions invoke common button-0 down/up, X transitions invoke common button-1 down/up, and Y transitions invoke common button-2 down/up. The A callback sites include RVAs 0x1374AE and 0x1374DC, X includes 0x137511 and 0x137541, and Y includes 0x137576 and 0x1375A6. These are transitive writes to mask bits 0, 1, and 2 through the same common callback and engine-helper chain as the window messages. They are not a separate controller-only held mask.

When the UI predicate at RVA 0x1014F0 is true and game offset 0x668 is zero, the cursor-oriented controller branch synthesizes button-0 callbacks from A transitions only while the stored elapsed-time accumulator at image RVA 0x551CC0 exceeds 200. Relevant A down/up call sites are RVAs 0x1372D6 and 0x137334. X transitions still synthesize button-1 callbacks, including sites 0x13738D and 0x1373C6. This branch does not synthesize a button-2 callback from Y in the inspected direct code. When that UI predicate is false and game offset 0x668 is zero, A, X, and Y instead activate per-game action-state bytes through RVA 0xA36C0 in the inspected branch; those action writes are distinct from the engine-mask producers.

A and X transition history is stored in separate bytes at image RVAs 0x551CBD and 0x551CBE after successful controller processing, including passes whose branch or A timing gate prevented a mouse callback. Y history is updated at RVA 0x551CDC in the game-offset-0x668 branch. Therefore these history bytes are not aliases for the engine mask. In particular, an A transition suppressed by the timing gate still advances the A history in this processing path; the code does not defer that transition until the accumulator later exceeds 200. The controller-poll failure branch near RVA 0x137ADE resets the two controller motion vectors through RVAs 0xA38C0 and 0xA3900 and does not generate common mouse-up callbacks or directly clear the held mask in that branch.

Focus-gain message 7 and focus-loss message 8 return 1 directly from the window procedure at RVA 0x133C70. Those message branches neither write this mask nor synthesize common button-up callbacks. In the main input loop, a failed foreground-window check near RVA 0x136638 skips physical polling, the mouse handler, and controller synthesis and reaches the short sleep path at RVA 0x137B83. That skip route contains no held-mask clear or synthetic release. This proves the absence of an automatic release in these particular focus and foreground-gating routes. It does not prove the absence of other engine updates, dispatched messages, callbacks, or writers elsewhere in the program.

Within the identified producers, the mask is stored on the engine object rather than reconstructed from the newest physical state. A down operation leaves the selected bit set until an observed clearing operation or another writer changes it; the cited direct code does not restore a previous value when the callback returns. Each identified up operation clears its selected bit regardless of whether a window event or a controller event most recently set it. No source ownership or press count participates in these particular bit operations. These statements do not establish global writer completeness, universal focus-loss persistence, or a complete lifetime analysis of the engine object. No exhaustive audit of wider writes or indirect widget callbacks was performed, and no broader writer absence should be inferred.
