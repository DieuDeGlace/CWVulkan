# Native Steam retained source-field lifetimes

This bounded contract covers the coordinate-keyed retained state at World+0x10, the directly reached fresh-record construction, retention at RVA 0x2D3E20, restoration at RVA 0x2AE0C0, and the directly identified flag writers and selected count consumers. It applies to the original x64 Steam image binary/cubeworld.original.exe.unpacked.exe, image base 0x140000000, PE timestamp 0x5D93AB0D, SHA256 7AF18CB28C8BF848F355287428C6390B2EA2A682CA466190F5EB9859C5D6F244. Evidence consists solely of individually identified original function files under decompiled/functions, the original decompiled/assembly.txt listing, and that image. The image hash was verified for this audit. This is native-derived prose, not runtime capture evidence; all earlier held contracts remain unchanged.

The retained map key is a pair of signed 32-bit source-zone components. In a retained tree node, that key begins at node+0x20 and the 0x60-byte retained payload begins at node+0x28. The offsets in the following table distinguish the payload from its containing node. The two selected arrays hold 0xE0-byte records; their broader gameplay categories are not assigned from their size or offset.

| Source state | Retained payload offset | Retained node offset | Direct retention/restoration identity |
| --- | --- | --- | --- |
| Source byte +0xF9 | Flag byte +0x00, bit 0 | Byte +0x28, value 1 | Selects replacement of the array at source+0x30 |
| Source array +0x30 | +0x08 | +0x30 | First selected 0xE0-record vector |
| Source byte +0xFA | Flag byte +0x00, bit 1 | Byte +0x28, value 2 | Selects replacement of the array at source+0x60 |
| Source array +0x60 | +0x20 | +0x48 | Second selected 0xE0-record vector |
| Source edit list +0xD8, count +0xE0 | +0x38 | +0x60 | Ordered edit records copied and replayed |
| Source collection +0x4D8, count +0x4E0 | +0x48 | +0x70 | Two-component keys with 32-bit counts in reached consumers |
| Source 32-bit scalar +0x490 | +0x58 | +0x80 | Selected count scalar in reached consumers |

The lookup-or-create helper at RVA 0x299560 returns an existing equal-key record without reinitializing it. Its missing-key path calls the construction wrapper at RVA 0x295EC0, from RVA 0x2995FD. That wrapper copies the key, clears all 0x60 payload bytes at RVA 0x295F16, then calls the container constructor at RVA 0x147770 from RVA 0x295F1F. The separately identified wrapper at RVA 0x146B60 performs the same payload clear before calling that constructor. Its caller categories are not closed here.

The fresh-record defaults therefore include a zero flag byte, zero scalar and empty containers. The constructor at RVA 0x147770 itself explicitly initializes the two vector descriptors to zero and constructs empty edit-list and count-collection sentinels at payload+0x38 and +0x48. It does not itself write the flag byte or scalar: their zero defaults in these proved construction paths come from the preceding payload clear. Returning an already existing record through RVA 0x299560 does not reapply those defaults.

The source object has its own separate constructor defaults. RVA 0x2F9400 initializes the selected source vector descriptors to empty, constructs the source edit list and count collection empty, and initializes source+0x490 to zero at RVA 0x2F9664. The word write of one at source+0xF8 at RVA 0x2F94FF makes source byte +0xF8 one and byte +0xF9 zero; the explicit byte write at RVA 0x2F9508 makes +0xFA zero. Source creation at RVA 0x2AE0C0 subsequently calls generation at RVA 0x2FF6F0 before considering retained restoration. Constructor emptiness must therefore be distinguished from the generated contents present at that later decision. This audit does not enumerate every generated array member or every transitive generator write.

Retention at RVA 0x2D3E20 processes the first selected array, the second selected array, the edit list, the count collection and finally the scalar, in that order. It has no internal World+0x358 gate. It also does not erase the loaded source map or delete the source object. Its copying and conditional creation of retained state are separate operations from physical source retirement by a caller.

The first array is processed only when source byte +0xF9 is nonzero, tested at RVA 0x2D3E39. The helper obtains or creates the coordinate record, ORs value 1 into its flag byte at RVA 0x2D3E7D, then assigns the current source+0x30 vector into retained node+0x30 through RVA 0x29BCB0 at RVA 0x2D3E9E. The second array follows the source byte +0xFA test at RVA 0x2D3EA3, ORs value 2 at RVA 0x2D3ED9, and assigns source+0x60 into retained node+0x48 through RVA 0x29BAF0 at RVA 0x2D3EFA.

These are whole-vector replacements of the used elements in source order, not append operations and not transfers that empty the source descriptors. Both vector-assignment bodies set the destination used end back to its beginning when the source vector is empty. Thus a qualifying empty source array clears the retained array while preserving its replacement bit. An unset source flag leaves that retained array and its already stored bit unchanged. The OR operations do not clear a previously set bit. The directly inspected retention body contains no reset of the source flags or consumption of the saved replacement bits.

The edit-list decision next tests source count +0xE0 at RVA 0x2D3EFF. A nonempty list causes the coordinate record to be obtained or created. An empty list causes a lookup first, and is processed only if a coordinate record already exists at that point. When processed, the list at source+0xD8 replaces retained node+0x60 through RVA 0x299950, called at RVA 0x2D402B. That helper assigns the incoming ordered records, creates any needed destination list nodes and removes leftover destination nodes. An empty incoming range clears the destination list. It is not an append-only accumulated edit history.

The count collection follows the same existence-sensitive admission. A nonzero source count +0x4E0 permits creation; a zero count performs replacement only when a retained coordinate record already exists. The branch begins at RVA 0x2D4030. Once admitted, retention clears the destination collection at node+0x70 through RVA 0x509E0 at RVA 0x2D4141, then copies the source+0x4D8 tree through RVA 0x6F000 at RVA 0x2D4151. Copying an empty source collection leaves an empty retained collection; previous entries are not merged into it.

The scalar decision starts with the zero comparison of source+0x490 at RVA 0x2D4156. A nonzero scalar permits creation of the coordinate record. A zero scalar is written only if a coordinate record already exists. The admitted write at RVA 0x2D4264 replaces retained node+0x80 with the current 32-bit source value, including zero. There is no corresponding replacement bit for this scalar, the edit list or the count collection.

Each of these existence tests occurs in order against the map as it then stands. A record created by an earlier flagged-array or nonempty-state step is therefore visible to later empty or zero replacements in the same retention call. If there is no preexisting record, both array flags are zero, both relevant collections are empty and the scalar is zero, this routine creates no coordinate record. If a record is created only by a later nonempty collection or nonzero scalar, the earlier untouched empty fields retain their fresh-record empty defaults. Conversely, once a record exists, empty edits, an empty count collection and a zero scalar clear their previously saved values. The helper does not remove a coordinate record merely because its contents become empty and zero.

For example, a true first-array flag with an empty first array records an explicit empty replacement, even if the entire rest of the source state is empty. A false first-array flag with nonempty generated first-array contents does not by itself save that array. A false first-array flag on a later source does not revoke an already retained first-array replacement bit. These are consequences of the proved branch and assignment rules, not claims that every ordinary mutation can produce every flag combination.

Restoration is reached only after the source factory's initial loaded-map test and generation. An already loaded nonnull source takes the fast-return branch at RVA 0x2AE129 and does not run this restoration sequence. On the newly created route, World byte +0x358 is compared with zero at RVA 0x2AE17E. A nonzero value branches at RVA 0x2AE186 directly to the installation sequence beginning at RVA 0x2AE31A, skipping retained lookup and restoration. A zero value permits lookup of the coordinate record at World+0x10. No remote-only or loader-complete label is assigned to this byte.

When that zero-gated lookup finds a record, the first replacement-bit test occurs at RVA 0x2AE264. A set bit writes one to source+0xF9 at RVA 0x2AE26A and replaces source+0x30 from retained node+0x30 through RVA 0x29BCB0 at RVA 0x2AE279. The second test at RVA 0x2AE27E similarly writes one to source+0xFA at RVA 0x2AE284 and replaces source+0x60 from retained node+0x48 through RVA 0x29BAF0 at RVA 0x2AE293. The array assignments have the same empty-clearing behavior described above. A clear retained bit skips that array replacement and skips that source-flag write, leaving that array's then-current generated state in place.

Restoration next replaces the source edit list from retained node+0x60 through RVA 0x299950 at RVA 0x2AE2B1. It then traverses that retained list in order and calls the terrain-write routine at RVA 0x31C1C0 once per visited record, from RVA 0x2AE2D8. The three 32-bit coordinates come from edit-list node+0x10, +0x14 and +0x18; the value argument begins at edit-list node+0x22. The replay therefore occurs after both admitted array replacements, and preserves list order, including the order of any repeated coordinates.

RVA 0x31C1C0 checks the source's horizontal 64-by-64 block bounds and its reached column/material admission before writing column storage through RVA 0xA36E0, reached at RVAs 0x31C2E1 and 0x31C410. That column helper stores a six-byte block value and can extend its column storage. The replay should not be treated as an unconditional write to every supplied coordinate independently of those original admissions. The edit-list replacement can be empty, in which case there are no replay calls; the audit does not establish the meaning of every other byte retained in an edit record or trace every edit-list producer.

After edit replay, restoration unconditionally copies the retained 32-bit scalar at node+0x80 to source+0x490 at RVAs 0x2AE2E5–0x2AE2EB. It then clears the source+0x4D8 collection through RVA 0x509E0 at RVA 0x2AE304 and copies retained node+0x70 through RVA 0x6F000 at RVA 0x2AE315. Thus restoration orders the scalar before the count collection, whereas retention orders the count collection before the scalar. Once a record was found, these edit, scalar and count-collection replacements are not conditional on the two array bits or on saved nonemptiness. Their empty and zero values are authoritative for those selected fields.

The source is installed into the loaded map only after these reached operations. The factory acquires World+0x3F0 then World+0x3C8, at RVAs 0x2AE321 and 0x2AE32E, writes the source pointer at RVA 0x2AE354, and releases the guards in reverse order. The restoration body does not remove the retained coordinate record or clear its flags after use. Its writes of one to the source flags make the restored arrays eligible for copying again by a later admitted retention call. This describes the inspected route; it is not an exhaustive proof against other flag aliases, retained-map removals, persistence readers or alternate factory callers.

The directly identified additional source-flag writer at RVA 0x2E30B0 processes source pointers from the World+0x190 and World+0x1A0 sets. For every reached entry of the first set, it writes one to source+0xF9 at RVA 0x2E3105 and packages the current first array and source coordinates into the reached World+0xE0 list. For the second set, it writes one to source+0xFA at RVA 0x2E3286 and packages the current second array and coordinates into World+0xF0. Neither flag write is admitted by a nonempty-array test, so a selected empty array can become an explicit replacement. Later in this body the two source-pointer sets are cleared, including their counts at World+0x198 and +0x1A8; that set cleanup is distinct from resetting the source flag bytes. The producers of every membership in those sets are not enumerated here.

A further directly identified +0xFA writer is the source-local refresh routine at RVA 0x31C540. Its source+0x4F8 versus World+0x8 equality gate returns without the refresh when equal; otherwise it stores the World value before refresh work. The reached refresh copies the prior source+0x60 array, assigns source+0x78 into source+0x60 through RVA 0x29BAF0 at RVA 0x31C629, and tests the resulting size and record comparisons. The observed difference path inserts the source into World+0x1A0 at RVA 0x31C6D3 and writes one to +0xFA at RVA 0x31C6D8. After later reached refresh mutations, another comparison through RVA 0x2F83A0 at RVA 0x31D386 can insert it again at RVA 0x31D3B4 and write one at RVA 0x31D3B9. These writes show that replacement status is not limited to an externally issued terrain edit. Full refresh generation, comparison semantics and early-exit policies remain outside this field-lifetime audit.

The same source flags have a directly traced additional consumer at RVA 0xF33B0. The +0xF9 test at RVA 0xF386A admits the coordinate-and-first-array snapshot helper at RVA 0xF1AC0, called at RVA 0xF3883. The +0xFA test at RVA 0xF3946 admits the coordinate-and-second-array helper at RVA 0x9950, called at RVA 0xF395B. Those helpers read the respective source vectors and coordinates into separately constructed list-backed snapshots. This proves selection of current array state for that reached state-assembly route; its complete transport, receiver policy and delivery lifetime are not inferred.

The retained count collection is not a saved collection of live resident pointers. A directly traced rebuild within RVA 0x2E3510 clears source+0x4D8 at RVA 0x2E4473. It walks selected source+0x460 resident-template entries, requires the reached template+0x908 nonzero condition and matching identity presence in World+0x20, then increments one 32-bit count for each visited two-component key from template+0x900, through lookup-or-create RVA 0x1473E0 at RVA 0x2E450E. That helper's fresh-value constructor at RVA 0x146B10 initializes the count to zero. The keys compare as two signed 32-bit components; no universal gameplay names are assigned to those components here.

The same rebuild resets the 32-bit scalar source+0x490 at RVA 0x2E45D1, then walks the identities in source+0x480 and increments the scalar at RVA 0x2E4632 for each reached identity found in World+0x20. This establishes a count of those matching entries in this particular rebuild, not a total live-resident count or a complete meaning for World+0x20. Other mutations and the full admission of the selected source set are not closed by this scoped read.

These summaries are directly consumed across source residency boundaries. In a reached prerequisite-count branch of logical admission at RVA 0x2E17D0, a nonzero template field +0x920 causes a sum over the inclusive source-zone range extending eight zones in each horizontal direction. A loaded nonnull source contributes its +0x490 scalar, including the addition at RVA 0x2E1F4F. A missing/null source instead contributes retained node+0x80 when a coordinate record exists. The sum is compared with that template field before the reached admission proceeds. Separately, a reached key-count lookup in RVA 0x2E3510 uses source+0x4D8 when a source pointer is available and otherwise retained node+0x70; the corresponding loaded and retained lookups are at RVAs 0x2E5408 and 0x2E5458 through RVA 0x93730. This demonstrates why selected count summaries can matter after physical source retirement. The entire resident prerequisite and gameplay taxonomy is not audited here.

One directly proved physical retirement caller is RVA 0x2D2670. It erases a selected loaded-map node at RVA 0x2D2892, calls retention at RVA 0x2D289D while holding World+0x3F0 and World+0x3C8, releases those guards, then invokes the source deleting virtual entry at RVA 0x2D28CC. The source destructor at RVA 0x2F9940 separately destroys its own containers, including the selected vectors, edit list and source-local count collection. Retained payloads own their separately constructed destination containers; retention is not preservation of the physical source object's identity. The edit/list/vector assignment and tree-copy bodies do not move the source descriptors into the World record. This does not prove indefinite retained-record lifetime, close every destructor caller, or establish synchronization for every other user of the record.
