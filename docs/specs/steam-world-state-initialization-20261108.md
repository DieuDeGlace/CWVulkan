The state value starts at World+0x8. Its first four bytes are the day field and its next four bytes are the raw representation of the time float. The retained-map header and 64-bit count are at World+0x10 and +0x18. The two identifier-set headers and 64-bit counts are at World+0x20/+0x28 and World+0x30/+0x38. The state decoder and transfer routines therefore receive World+0x8 as their state destination, rather than the World object's beginning. These offsets are established by the World constructor's call at 0x29A183, the state constructor 0x29AF50, the initializer's call at 0x2B6632 and the decoder destination at 0x2B999D–0x2B99A1.

The constructor-only state must be distinguished from the later initialized state. World constructor 0x29A130 calls state constructor 0x29AF50 at 0x29A183. The state constructor creates three empty collections with zero counts. It does not write its first eight bytes. The inspected World constructor contains no direct day/time scalar initialization that supplies a default for those bytes. This audit therefore does not assign a usable day or time value to a World merely because those constructor calls completed, and it does not assume that the preceding allocation zeroed the object. Separately, the World constructor writes byte World+0x358 to zero at 0x29A276 and constructs an empty name string at World+0x200. The later initialization routine supplies the directly proved scalar defaults.

World initialization/configuration routine 0x2B5F20 first closes an existing backend handle through 0x66BE0 at call site 0x2B5F71. It writes the supplied 32-bit value to World+0x220 and, unless the name argument is the same string object as World+0x200, replaces the latter from that argument. It also performs procedural-seed/table work, which is outside this metadata contract. Its metadata reset occurs later in the same call, before the saved-state admission tests.

At 0x2B6632, the initializer supplies World+0x8 and a temporary state whose scalar prefix is zero and whose three collections are empty to transfer routine 0x29BE90. That routine first copies the two four-byte scalars. For each distinct destination/source collection it clears the destination, then exchanges the collection header and count with the mutable source. Its retained-map clear is 0x8A830; its identifier-set clears are 0x3D6C0. The map is handled first, then the set corresponding to World+0x20, then the set corresponding to World+0x30. The initializer subsequently destroys the temporary's emptied collection storage. This is a destructive replacement/transfer boundary. It does not preserve an old destination entry merely because no new saved blob will be loaded.

After that reset and temporary cleanup, the initializer writes day 1 at 0x2B66F7 and raw time bits 0x4C095440 at 0x2B66FF. Those bits represent the single-precision value 36,000,000. No conversion from a serialized integer or normalized fraction occurs in those stores. The intermediate zero scalar prefix and the later explicit defaults are ordered native writes; this audit does not turn that sequence into an atomic publication guarantee.

Saved-state loading is admitted only when byte World+0x358 is zero and the supplied name string's 64-bit length is nonzero. The tests are at 0x2B6707 and 0x2B6716. On admission the initializer builds the literal path Save/world.db, calls backend opener 0x67070 at 0x2B675B, and calls World loader 0x2B98B0 at 0x2B676D. The name's spelling is not inserted into this inspected path: its nonempty length admits the load, while the path itself is constant here. The opener's returned status is not used as a separate gate before the loader call. If either admission test fails, the preceding metadata reset and day/time defaults have already happened; the old metadata is not retained by skipping the load.

Loader 0x2B98B0 queries the backend at World+0x3B8 for the five-byte key state, using 0x670F0 at 0x2B991F and a temporary owned byte buffer. The backend wrapper performs the keyed value query and reports a nonzero result after copying a found blob into the output buffer. The World loader tests that result at 0x2B9987–0x2B9989. A zero result skips the decoder and leaves the destination metadata unchanged by this loader. In the ordinary initializer route that means the already reset empty collections, day 1 and time 36,000,000 survive. This is a caller-level result distinction, not a guarantee that every backend or file failure is safe, recoverable or fully diagnosed.

For a nonzero query result, the loader constructs a reader through 0x147750 at 0x2B9995. That reader points to the temporary byte buffer, sets its cursor to zero, and sets its expected World-state version field to 0x2C, decimal 44. The loader then calls decoder 0x148E90 at 0x2B99A1 with World+0x8 as the destination. Decoding writes directly into the existing World state. There is no intervening freshly decoded state value followed by one final commit/swap in this inspected route. The loader releases the temporary byte buffer after the call.

The decoder reads a four-byte version/header, then a four-byte day, then four raw bytes for time. Its successful day and time destination stores are at 0x148F43 and 0x148F6C. Only after these reads does it compare the header with the reader's expected version at 0x148F97. Consequently, a complete header/day/time prefix with a version other than 0x2C can replace the destination day/time while leaving all three collections untouched by the decoder. On the ordinary initialization route the collections were already emptied before this call. On an independently invoked loader operating on a previously populated state, the same decoder branch would leave those preexisting collections unchanged. No such alternate ordinary caller is established here.

For a matching version and complete ordinary input, collection replacement is ordered. The decoder reads a 32-bit count for the identifier set at World+0x20, clears that set at 0x148FD0, and reads/inserts the specified 64-bit identifiers. It then reads the count for the identifier set at World+0x30, clears it at 0x14908E, and inserts its 64-bit identifiers. It next reads the retained-map count and destroys the destination's prior retained-map entries and their values at 0x149163–0x1491A3. It then reconstructs retained entries from signed 32-bit coordinate pairs and their serialized payloads. The collection loops admit counts greater than zero using signed 32-bit tests. A successfully read zero count still reaches the corresponding clear and adds nothing.

Thus a complete matching-version blob replaces the destination's previous set memberships and retained-map contents, in that order, rather than merging them with the old World state. This statement concerns old destination contents. The decoder may find a coordinate already introduced earlier while decoding the same blob, and its body appends the reached array/list payloads to that found entry while assigning the directly read flag and trailing scalar fields. A repeated coordinate within one blob therefore must not be treated as proof of whole-record last-entry replacement. No general malformed-input, duplicate-producer or compatibility policy is derived from this observation.

Time is transferred as four raw bytes in the decoder and in 0x29BE90. The inspected load does not clamp it, convert units, reduce it to a day interval or derive it from the day. The format check is not an all-or-nothing transaction: the scalar writes precede it, and the collection clears and fills occur successively after it. Individual reads have remaining-length checks and can clamp the cursor without performing that particular destination store, but local count/header state and later execution do not establish a general safe default or rollback for truncated data. The ordinary complete-blob behavior above must not be generalized into a robust malformed-file guarantee.

The ordinary application path in 0x1355A0 allocates the viewed World separately, calls 0x29A130 at 0x136163, and passes the resulting pointer into Game constructor 0x7EA80 at 0x136331. That constructor stores it at Game+0x8. It constructs a separate Host object at Game+0x6E8 by calling 0xF17A0 at 0x7EB36. Host constructor 0xF17A0 constructs its own World at Host+0x8, through the call at 0xF17E1. The embedded Host World is therefore at Game+0x6F0. The Host is passed the viewed World's +0x70 service pointer; that forwarding does not make the two World state objects or their collection headers the same object.

The Host constructor initializes its embedded World through 0x2B5F20 at 0xF1969, supplying the 32-bit value 0x7B and a six-byte name consisting of one leading ASCII space followed by world. It performs that initialization before its later worker setup at 0xF19DA/0xF19E8. Later in the enclosing Game constructor, Game+0x206C is set to 0x7B and the name at Game+0x2070 is set to the five-byte word world. The Game constructor calls 0x2B5F20 for the viewed World at 0x7F279 using those arguments. Both directly constructed Worlds have the proved constructor default of zero at byte +0x358, and both supplied names are nonempty. Those shown values satisfy the saved-state admission tests; no intervening direct change of that byte is present in the inspected constructor bodies. Each uses its own backend member and its own destination metadata. The two initializations occur at distinct calls; this evidence does not guarantee that they observe identical blob contents or remain equal afterward.

No Host-to-viewed metadata copy is established inside these inspected constructor/initializer routes. Their directly proved commonality is separate loading through the same literal database path and key. A fresh constructor's empty collections, a later reset with explicit scalar defaults, and successful loading of existing metadata are separate events. Loading the retained-state map is also distinct from installing live source-zone objects or admitting residents; those subsequent consumers are outside this audit.

The separately checked copy routine 0xF1C90 copies the two scalar fields and constructs the three destination collection headers through 0x6D400/0x6D5E0, whose reached helpers copy collection counts and delegate content copying. Its directly identified caller at 0xF2EFF uses the embedded Host World's state at Host+0x10 as input and a stack state value as destination. The surrounding calls at 0xF2EEE and 0xF2F0D acquire and release that World's +0x3C8 guard; the later save call is at 0xF2F1E. This is an outward capture of the Host World's existing state, not a demonstrated startup assignment into another World. The nested retained-value clone internals, every inlined copy and every alternative caller are not re-audited here.
