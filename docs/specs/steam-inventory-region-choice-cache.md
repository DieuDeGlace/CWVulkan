# Native inventory region-choice cache

This bounded contract is FINAL / STABLE / HELD following author readback. The supported image is cubeworld.original.exe.unpacked.exe, AMD64 PE32+, image base 0x140000000, 5,757,952 bytes, SHA-256 7AF18CB28C8BF848F355287428C6390B2EA2A682CA466190F5EB9859C5D6F244. Evidence is restricted to the original binary, original native function and longer-budget frame decompilations, assembly.txt and calls.csv after the standalone author rules. No other project prose, implementation, SDK, tests, probes, captures or implementation history supplied evidence. Addresses below are RVAs. The scope is builder 0x2806a0, its observed updater 0x280a40, construction/draw and the specific storage/navigation edges described below; it is not a full writer or caller census.

The region choices are a widget-owned vector of copied coordinate pairs. They are rebuilt from one tab of the current actor's carried inventory only when the builder's mode is zero. Quantity zero is excluded; every other quantity is eligible. The player's own region is always inserted on a normally completed valid-source rebuild. Exact duplicate coordinates collapse. The resulting unique values are ordered by a player-relative distance comparison, rather than simply preserving item order. The builder does not repair the selected region, and the inspected draw body reads cached values without directly rebuilding them.

Constructor 0x27c950 establishes the relevant widget fields. The collection pointer at widget+0x1e8 initially contains zero. The selected region is two four-byte components at +0x1f0 and +0x1f4, initially both zero. The choice-vector header is begin at +0x1f8, end at +0x200 and allocation-end at +0x208, initially all zero. Each choice occupies eight bytes: two consecutive 32-bit coordinate values in the same component order as the selected pair. There is no separately retained choice count in this header; the live count is determined from the pointer span divided by eight. Widget+0x210 retains the Game pointer supplied at construction. The four-byte mode at +0x280 receives the constructor's mode argument, and the four-byte selected tab at +0x2b4 initially contains zero.

The updater's gate and the builder's source must be distinguished. Routine 0x280a40 checks widget+0x1e8 for nonnull at 0x280a46 and, if nonnull, calls 0x2806a0 at 0x280a61 before its later layout/tab checks. A null collection pointer returns from this updater without clearing or rebuilding the cached choices. This is a gate on the updater, not proof that the builder obtains its regions from that pointer.

Builder 0x2806a0 checks the four-byte mode at +0x280 at 0x2806d3. A nonzero mode returns with the cache and selected pair unchanged by this body. In mode zero it obtains Game through widget+0x210, World through Game+8, the current actor through World+0x448 and the carried inventory's outer vector begin through actor+0x9f0. It sign-extends the selected tab at widget+0x2b4 for indexing at 0x28070f and directly loads that group's 0x18-byte vector header at 0x280721 and 0x280726. It does not substitute the widget+0x1e8 collection as this source. Calling this helper directly also does not acquire the updater's separate nonnull gate.

The builder has no inspected local check that the tab is nonnegative or less than the carried inventory's group count before those header loads. A later bound check in 0x280a40 concerns its bound collection and pagination; it occurs after the cache call and cannot qualify the builder's earlier access. Therefore an invalid tab is not established as a safe empty-choice case. A zero-sized carried outer vector similarly does not supply a valid tab-zero header merely because the updater's collection-pointer slot is nonnull. This note does not assign a defined successful result to those out-of-range accesses or to null Game/World/actor/source storage.

For a valid carried group, rows have stride 0xa4. The builder tests the four-byte quantity at row+0 for inequality with zero at 0x280733. It does not require a positive signed count. Negative counts, including a stored minus one, are included by this test. There is no item-category or item-validity filter in this loop. Eligible rows contribute the two four-byte values at row+0x10 and +0x14, equivalently item+0x0c and item+0x10 because the carried item starts at row+4. Their values are copied; neither the carried-row address nor an item pointer is retained in a choice.

After scanning the eligible carried rows, the builder inserts the current actor's two four-byte region values from +0x150 and +0x154. This insertion is unconditional on the group containing items and is not restricted to tabs zero and one. A valid empty inner group, or a valid group containing only zero-quantity rows, consequently yields one player-region choice on ordinary successful completion. It does not yield an empty cache. If that coordinate pair was already contributed by an item, it remains a single value.

Temporary uniqueness is provided by 0x745e0, reached at 0x280758 and 0x2807af. This is a unique ordered tree comparing two 32-bit components with signed lexicographic comparisons, first component followed by second. The temporary nodes carry the copied pair at node+0x1c and +0x20. Equal pairs suppress an additional insertion. Thus repeated item regions and the separately inserted player region are deduplicated by coordinate value, independent of item quantity, category or source-row identity. The temporary tree is traversed in its ordered sequence when values are copied into the retained vector.

The builder resets the choice-vector end to its begin, appends the unique eight-byte pairs and calls sort helper 0x27c420 at 0x2809a0 with the widget as comparison context. The inspected comparison paths, including 0x27b780 and 0x27bd00, obtain the current actor's region through the widget's Game/World path and compare the larger of the two absolute component differences. For ordinary coordinate differences without 32-bit overflow, this is ascending maximum-axis, or Chebyshev, distance from the player region. There is no additional coordinate/name tie-break in that distance comparison.

The comparison's component differences, absolute-value operations and signed maximum comparisons use 32-bit integer operations; they are not a widened or saturating geometric calculation. Extreme coordinate overflow is not qualified as preserving mathematical distance order. For a span of at most 32 choices, 0x27c420 takes the insertion path 0x27b780, whose inspected comparisons move strictly smaller distances; with unchanged comparison inputs, equal-distance values retain their initial signed lexicographic tree order on that path. Larger spans use partition and possible heap paths. A general stable tie order for those paths is not independently authenticated here, and lexicographic secondary ordering is not part of their comparator contract. The comparison code can reread the current actor's region; no independent guarantee that concurrent writers cannot change that context is established.

The retained vector owns its allocation. Growth through 0x88520 copies existing pair values, replaces storage as necessary and frees the former allocation through 0x90e00. This can invalidate addresses into the old choice buffer. The temporary uniqueness tree is freed before the builder's normal return, including ordinary nodes and sentinel; its addresses do not become choices. A successful rebuild can reuse retained capacity, and a skipped update leaves previous live choices intact. The widget's ordinary destructor 0x27d170 frees the choice allocation through 0x90e00 and clears the three header slots. Deleting wrapper 0x27d270 can additionally free the widget allocation. These are ordinary ownership edges, not a concurrent-reader lifetime protocol.

The selected region at +0x1f0/+0x1f4 is separate from the choice vector. Constructor zeroing is not insertion or selection of the player's current region. Builder 0x2806a0 does not test selected-pair membership, replace a missing selection with the player/first choice or reset the selection after rebuilding. Updater 0x280a40 also does not perform such a repair in its inspected body. Its writes of zero, one or other values at +0x2a4 concern pagination, not the two-component selected region. No full selected-region writer census is claimed.

Two directly inspected navigation callbacks illustrate the distinction. Constructor 0x27c950 binds left-button callback 0x280170 and right-button callback 0x27f6a0. They search the stored vector for an exact match with the selected pair, then copy the preceding or following pair, using wraparound when they find a match. If the cache is empty or the selected pair is absent, the search does not install a replacement selection. Both reach 0x280a40 afterwards, but that updater's rebuild does not itself establish a selection repair. These facts do not qualify every UI initializer or event writer.

Draw 0x27d2b0 reads the cache near its entry. For nonnull left/right control objects at widget+0x250 and +0x258, it uses the selected tab's unsigned comparison with two, the choice-vector empty/nonempty state and equality with the cached first/last pair to set control-state values. These particular arrow-state conditions do not themselves check mode zero. They occur before draw's widget+0x1e8 null-source return. A null draw source can therefore still produce those control-state writes; it does not imply cache recomputation or selected-region repair.

The inspected draw body has no direct call to 0x2806a0 or 0x280a40 and no observed rebuild of the choice vector. Later region-specific row filtering and the selected-region name/header presentation are restricted to mode zero and tabs whose unsigned value is less than two. The original mode-zero tab labels include "Equipment" and "Specials". That draw/filter gate is narrower than the builder's gate: a valid tab two or greater can still rebuild choices in mode zero even though those particular region-display/filter paths do not use them. Draw uses the stored selected coordinates for its region presentation; it does not independently discover eligible regions from the current carried rows as a replacement for the cache builder.

A valid empty inner tab, an empty bound outer collection, an invalid carried tab and a null bound collection are consequently distinct observations. Only the first has the directly proved one-player-choice rebuild outcome, assuming mode zero and valid actor/source storage. A nonnull widget collection can differ from the builder's carried source, so its emptiness alone does not define the choices. If the carried source itself lacks the indexed header, the earlier builder access is unqualified. A null updater collection skips rebuilding and preserves the old cache. A nonzero builder mode likewise preserves its cache. None of those skipped paths is an observed automatic empty-cache reset.

The supplied direct-call records identify 0x280a61 inside 0x280a40 as the builder's direct caller. One observed updater call in frame 0xa5a50 is 0xaa7d9 on the receipt/UI-refresh path, inside that frame's World+0x3c8 critical-section interval entered through 0x2abb70 at 0xa6464 and released through 0x2b9890 at 0xadb23. The builder and updater do not themselves establish that general critical-section interval. Other callbacks, source bindings, mode/tab writers, generic UI effects, exception cleanup and every concurrent reader/writer are not exhaustively qualified. This is a cache layout/consumption contract, not a universal freshness, guard or thread guarantee, and it prescribes no replacement-engine policy.
