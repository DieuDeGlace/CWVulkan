# Steam dungeon gate threshold writers

This contract covers the unpacked original Steam AMD64 image `cubeworld.original.exe.unpacked.exe`, preferred base `0x140000000`, SHA-256 `7AF18CB28C8BF848F355287428C6390B2EA2A682CA466190F5EB9859C5D6F244`. Addresses are image RVAs. The threshold writers are in the initial Zone generator `0x2ff6f0`. The relevant runtime lookup is at `0x2e5352` for object types 8 and 10, with the type values written here in decimal.

## Threshold map and entrance assignment

`Zone+0x4c8` is the head pointer and `Zone+0x4d0` is the 64-bit element count. The map belongs to the particular Zone invocation, even when its generator samples neighboring terrain cells. A key has signed 32-bit world cell X and Y, in that order, in 16-block units. The threshold is a dword. Node offsets are `+0x1c` for X, `+0x20` for Y, and `+0x24` for the value. The map has no layer or Z component in the key. All four direct calls to `0x83b20` in `0x2ff6f0` use this map. `0x83b20` returns the current value slot for an exact key, inserting a missing key with value zero through `0x7c0c0` and `0x6e800`.

The entrance-associated assignment at `0x3050b5–0x3050fb` requires the current cell selector value to be `0x2e` and the Zone generation kind to be 8. The selector is the 32-bit value read from `0x69c60` for the current cell in this generation loop, saved at `0x3026a4`. It is a different value from the byte descriptor obtained by `0x2a8290`. The writer keys the entry by the current cell X and Y at `0x3050c4` and `0x3050cb`. It assigns the complete return value of `0x2c30b0`, replacing any previous threshold at that key. This write has no increment and no state test on an existing object. It occurs before the following dispatch at `0x305101`.

The two coordinate arguments of `0x2c30b0` at `0x3050f6` are the coarse X/Y pair retained at frame offsets `+0x80` and `+0x78`. They are derived by taking the floor of the Zone origin in 1024-block units. The branch at `0x2ff8b9` can align both to the lower even indices before use. The helper returns 1 or one of 3 through 6. The result uses the coordinate pair and consumes no CRT random draw. The kind-8 gate-side spawn producer also calls this helper at `0x2faa2f` for its emission count. This establishes the shared count source. The threshold assignment itself does not prove that a gate object was appended for every such cell.

## Interior dispatch and accumulation

The current layer index in the structure loop is the signed dword at frame offset `-0x5c`. At `0x30b7b8`, the negative path takes the saved structure descriptor byte at frame offset `-0x27`. The nonnegative path at `0x30b7d2` first requires the original cell selector to be `0x2d`, then uses the 32-bit result of `0x2a1d10` for the current cell with the current layer index as its fourth argument. The resulting value must be in the range 2 through 6 to reach the object dispatch.

| Dispatch value | Relevant result |
| --- | --- |
| 2 | Writes object type 8 at `0x30b836` and enters the threshold branch. |
| 3 | Writes object type 9 at `0x30b87c`. It bypasses these threshold writes. |
| 4 | Writes object type 10 at `0x30b871` and enters the threshold branch. |
| 5 | Selects an object type through `0x12a600`. The test at `0x30b8f8–0x30b906` admits the selected value to threshold handling only when it is 8 or 10. This establishes the dispatch condition. The audit does not establish that all kinds or contexts can return either type. |
| 6 | Sets the candidate type to minus one and bypasses this submission and its threshold writes. |

For an admitted gate candidate with a **negative** current layer index, the scan at `0x30b91a–0x30b9d2` covers the aligned eight by eight square of 16-block cells containing the current cell. For each axis the start is the current signed cell index rounded down to a multiple of eight. The exclusive end is eight cells later. X increases in the outer loop and Y increases in the inner loop. For each sampled pair, `0x2a8290` supplies the descriptor. An unsigned byte at descriptor `+0x00` equal to 2, 4 or 6 adds one to the threshold at the **candidate's original key**, at `0x30b9bd`. Sampled neighbor keys are not inserted. The loop does not inspect block data or other layers. With no qualifying sample it performs no threshold-map access, so it preserves an existing entry or leaves a missing entry absent.

For an admitted gate candidate with a **nonnegative** layer index, `0x30b9dc` additionally requires Zone generation kind 8. This scan begins at the lower world-block origin of the coarse pair described above, covering 2048 blocks on each axis. Conversion through `0x2f7ed0` uses floor division by 16 for the endpoints. In ordinary coordinates this gives 128 by 128 cells, with lower endpoints included and upper endpoints excluded. It visits ascending X outside ascending Y. The `0x69c60` selector at each sampled cell must be `0x2d`, `0x2e` or `0x2f`, the exact acceptance set of `0x25eb30`. For the first two values it tests layer zero. For `0x2f` it tests layers zero and one, in that order. These bounds come from `0x25f5f0` at `0x30ba6e`. Each tested layer calls `0x2a1d10` with the sampled X/Y and that layer as the fourth argument. Only a full 32-bit result of `0x0d` increments the threshold at `0x30baba`.

The nonnegative scan also accumulates into the **candidate's original key**, without clipping sample coordinates to the candidate Zone. At `0x30bb07` the caller retrieves that key unconditionally after the scan and reads its value for stream output. This creates a zero-valued entry when the key was absent and the scan did not increment it. It leaves any existing value as it was. If the kind test at `0x30b9dc` fails, both the scan and that trailing access are skipped.

The increments operate on the existing dword and do not first clear it. Repeated candidates at the same X/Y, including candidates from different layers, can therefore accumulate in one entry. The entrance write is an assignment in its own earlier code path. The observed branch and traversal order determine the final value when assignments and increments reach the same key. The distinct native outcomes of an absent key and a present key with value zero are preserved by the runtime lookup.

## Object submission and lifetime

The interior threshold handling occurs before the candidate's final object submission at `0x30bd34`. Later processing initializes the candidate position at the current cell's world X/Y origin and the selected lower height. It probes the block one unit below the current candidate Z at `0x30bbd5–0x30bc02`, using the Zone block query through `0x2fea10`. The support test through `0x31ad40` accepts when block byte `+0x04` has any bit set in mask `0xfd`. On a failed test the candidate Z moves down one block. The loop probes at most 30 times. The branch proceeds after that limit even if no support test passed. This later block search is distinct from the threshold inputs.

The appender `0x1194b0` accepts only when the submitted X and Y are each within the current Zone's half-open 64-block range. It does not roll back the earlier threshold write if it rejects the candidate. Conversely, other types or generation branches can reach object submission without these threshold writers. The runtime type-8/type-10 decision looks up the threshold in the object's owner Zone, using the cell computed from the stored X/Y. No threshold is read from neighboring Zones. Neighbor Zones supply live or retained guard counts for the same pair.

The Zone constructor initializes the threshold tree empty and installs its own head at `0x2f96d3–0x2f96ee`. The Zone destructor clears it and frees the head at `0x2f9b40–0x2f9b66`. The runtime refresh at `0x2e4473` clears the separate live guard-count map at `Zone+0x4d8`. It leaves the threshold map in place. The observed Zone eviction and restore paths copy guard counts separately and have no established threshold-map copy. Normal new Zone creation runs the generator against the freshly constructed threshold tree. A full census of indirect writers or refresh paths is outside this scope.

## Creature admission and descriptor call boundary

The gate update tests the single Creature byte at `+0x60` for zero at `0x2e3c2e`. It is a role discriminator on the verified creation paths. The Creature constructor reaches `0x4d600` with the base shifted by `0x10`, and `0x4d636` installs the default 3 at the resulting Creature offset `+0x60`. The local player setup at `0x09fa50` writes zero through the World local Creature pointer at `+0x448`. The separate character setup at `0x147989` also writes zero. On the ordinary Zone spawn activation path, `0x2e24eb–0x2e24f0` copies the low byte of Spawn `+0x1c` into Creature `+0x60`. The resident update's exact admission criterion is the zero role code in its source list. A complete role taxonomy and admission across unrelated actor paths are outside this contract.

The original gate branch places a byte with value 1 at its outgoing stack offset `+0x20` before calling `0x2a8290` at `0x2e55ac` and `0x2e5724`. The negative-layer threshold call at `0x30b986` also does this. The callee's entry uses RCX for the World, RDX for caller output storage, and R8D/R9D for the signed 32-bit world cell pair. Inspection of the native frame from `0x2a8290` through its return shows no access to, or forwarding of, the incoming fifth slot. That slot would be at entry RSP plus `0x28`, or at the allocated frame's RSP plus `0x140`. The callee's own writes to its outgoing call area do not access that incoming slot. Thus changing or omitting the caller's extra byte supplies no input to the original descriptor calculation, including the result byte at `+0x03`. The full descriptor-byte taxonomy is outside this contract.

## Threshold tree links and entrance reach

The threshold tree's first `0x1a` bytes of node layout match the spawn-cell trees. On an ordinary node the qwords at `+0x00`, `+0x08` and `+0x10` are left child, parent and right child. On the head they are minimum, root and maximum. Missing children and the root's parent refer to the head. Byte `+0x18` is the balancing color, and byte `+0x19` is the nil marker. The constructor call at `0x2f96e9` uses `0x86ae0` to allocate a `0x28`-byte head with all three links pointing to itself and both bytes set to 1. A constructed empty tree has this nonnull head and a zero count. An ordinary node begins with both bytes zero through `0x6e800`, after which `0x113200` can change the balancing color while linking it. The head has no constructed key or threshold.

The pair comparisons at `0x11553a–0x115542` use signed 32-bit order in each component. Insertion through `0x7c0c0` and `0x724c0` uses the same ordering. In-order traversal, starting at the head's minimum and stopping on return to the head, therefore yields ascending signed X with ascending signed Y for equal X. `0x534b0` shows the same native successor walk during range erasure.

The generator's main cell scan starts at `0x302575` and advances at `0x315fa0–0x315fd2`. On each axis its signed offset from the current Zone's lower 16-block cell coordinate runs from −2 through 5, inclusive. X is the outer loop and Y is the inner loop. The inside-Zone test at `0x302616–0x302632` records whether either offset is outside 0 through 3. It does not exclude the halo from the entrance write.

The entrance assignment is after the separate reach admission at `0x302877–0x3028c6`. The routine compares the selector's reach from `0x25f790` to the candidate's distance in cells beyond each edge of the four-by-four Zone core, independently on each axis. A distance greater than reach on either axis skips past the entrance write to `0x315f6c`. For selector `0x2e`, `0x25f790` returns 1. The permitted offsets on each axis are therefore −1 through 4, inclusive, within the original eight-by-eight scan. Corners at one cell beyond both edges pass this reach test.

For selector `0x2e`, the subsequent dispatch reaches `0x305094` through `0x304db2` and `0x30330c`. On that path there is no additional inside-Zone clip before the selector and kind tests at `0x3050b5` and `0x3050bb`. An admitted one-cell halo key therefore goes into the current generating Zone's own threshold map if kind is 8. The later building dispatch at `0x305101` follows the assignment.
