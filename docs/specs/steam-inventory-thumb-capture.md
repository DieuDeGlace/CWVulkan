Movement dispatcher 0x3418d0 takes the UI owner in RCX and two float coordinates in XMM1/XMM2. It copies current owner coordinates +0x180/+0x184 to previous coordinates +0x188/+0x18c before storing the supplied values. It prefers the captured scene at +0x168 over a fresh root hit test. It compares the selected event target against the previous hover scene's target, delivering the reached leave/enter virtuals and tags as needed. On the selected target it invokes enabled widget virtual +0xa8 first, then numeric listener tag twelve. The tag-twelve path requires selected-scene flag bit one clear, a nonnull event target and listener, and either an enabled target or a listener whose enable-required byte is clear. The inventory installation sets that listener byte, so its ordinary listener delivery requires the enabled target. Capture does not remove this enable condition.

The move listener is therefore reachable even without capture whenever the current hit target owns that tag. Capture extends target selection beyond the thumb's current hit bounds; the inventory callback does not itself establish or verify capture. Its explicit held condition is bit zero of the common owner's +0x1a8, rather than widget+0x2b8 or an equality test against owner+0x168. A left hold begun elsewhere and a later hit on the listener target are not excluded by the callback's own checks. Conversely capture can exist while an unbound collection or a nonpositive cached range makes the callback do no work. Capture acquisition and scrolling eligibility are separate native conditions.

The inventory callback obtains its motion through 0x32b0d0 with the inventory object as receiver. None of these class/flag-dependent geometry behaviors may be assigned to the name-matched inventory thumb without the missing type/flag evidence.

The ordinary Button leave entry at +0xb8, 0x36a2c0, changes visual state and does not release internal capture. Merely moving beyond its visible geometry is therefore different from receiving the proved up handler. If the virtual delivery is blocked because the widget is disabled, or another component overwrites capture, the ordinary enabled Button release sequence cannot simply be assumed to run.
