# Steam secondary-button dispatch after held-state updates

FINAL / STABLE / HELD. This contract describes the original Steam x64 image with preferred base 0x140000000, PE timestamp 0x5D93AB0D, and SHA256 7AF18CB28C8BF848F355287428C6390B2EA2A682CA466190F5EB9859C5D6F244. Its primary scope is right-button down/up at RVAs 0x3415F0 and 0x341780 and middle-button down/up at RVAs 0x341300 and 0x3414A0. Original decompiler and assembly evidence was checked for all four. The necessary original helper reads cover picker RVA 0x333F60, registered-callback lookup RVA 0x32A210 and its directly referenced null-value initialization at RVA 0xF6CC0, generic registered dispatch RVA 0x342560 and pointer getter RVA 0x342090, traversal RVA 0x33C360, and the four global wrappers identified below. Button-0 comparison is limited to RVAs 0x340EC0 and 0x3410E0 and their directly referenced comparison helpers and wrappers. No broader scheduling or callback implementation audit is claimed.

Each primary routine first changes the 32-bit held mask at engine offset 0x1A8. Right down sets bit 1 and right up clears bit 1; middle down sets bit 2 and middle up clears bit 2. All dispatch described below follows that update. These direct bit operations preserve the remaining bits. This contract does not amend any earlier held-state contract.

All four routines select a target node in the same way. A nonnull pointer at engine offset 0x168 is used as a capture override. Only when that pointer is null do they call picker RVA 0x333F60, starting at the root pointer from engine offset 0x140, using the two 32-bit floating-point pointer coordinates at engine offsets 0x180 and 0x184 and a zero options argument. The capture route does not run the picker as an additional validation step, and absence of an owner on the captured node does not cause a fallback pick. The picker is a separate recursive selection operation with its own state, flag, and hit-admission tests; this contract does not restate its geometry or complete selection algorithm. Both up routines perform their own capture-or-pick selection; the four routines do not use an independent saved down-target field for the dispatch described here.

The selected node's pointer at offset 0x78 supplies the owner for targeted dispatch. Its pointer at offset 0x70 is a different field, used in the down-path focused-widget comparison and later as the direct receiver during global traversal. The code does not establish that these two pointers always coincide. A null selected node skips targeted dispatch while still allowing the later global stage to be attempted.

Both down routines perform the same focused-widget cleanup before targeted dispatch. The focused-widget pointer is at engine offset 0x170, the pointer returned by original getter RVA 0x342090. It is distinct from the separate auxiliary-target pointer at engine offset 0x178 and the qualifying-down owner stored at engine offset 0x1B0. If the selected node is absent, or its pointer at offset 0x70 differs from the pointer at engine offset 0x170, they take the cleanup route. If engine offset 0x170 is nonnull, they first write byte value 1 at offset 0x15C of that object, then call helper RVA 0x342560 with the node pointer from that object's offset 0x178 and registered-event key 0x13. After that call, the cleanup route stores null at engine offset 0x170. If a selected node's offset-0x70 pointer equals the existing engine-offset-0x170 pointer, this cleanup is skipped. Neither right up nor middle up has this focused-widget cleanup in its direct body.

The generic registered-dispatch helper at RVA 0x342560 invokes a registered callback only when its supplied node is nonnull, bit 1 of that node's 32-bit flags at offset 0x80 is clear, its owner pointer at offset 0x78 is nonnull, the requested callback lookup returns nonnull, and either the owner's byte at offset 0x1A0 is nonzero or the callback object's byte at offset 8 is zero. It invokes the first virtual method of the returned callback object, with that callback object as receiver. This helper contains no additional owner virtual-hook call before the registered callback. Key 0x13 is proved numerically; this contract does not assign it an unproved user-facing event name. The direct cleanup effects must be kept separate from callback effects: the routine writes the old focused object's byte at offset 0x15C and invokes the key-0x13 helper without first clearing engine offset 0x170. Only after that helper returns does this routine store null at engine offset 0x170. The invoked callback may itself change state; no guarantee of pointer stability inside that callback is asserted. The direct cleanup body does not itself write the selected visibility/style integer or invoke the separate null-target state helper at RVA 0x342270. No hiding, visibility change, focus assignment, or other effect is attributed to the key-0x13 callback body by this contract.

Targeted dispatch first attempts an owner virtual hook. It requires a nonnull owner from the selected node's offset 0x78 and a nonzero owner byte at offset 0x1A0. The virtual-table byte offsets are 0x70 for right down, 0x78 for right up, 0x88 for middle down, and 0x90 for middle up. The owner is the receiver. These virtual-hook admission checks do not themselves inspect bit 1 of the selected node's flags. In particular, a captured node reaches these checks without the picker's earlier filtering.

After that virtual hook returns, the routine separately reads the selected node's flags and owner again and attempts a registered callback. It requires bit 1 of the node's flags at offset 0x80 to be clear, a nonnull owner at offset 0x78, a nonnull result from lookup RVA 0x32A210 on that owner, and either a nonzero owner byte at offset 0x1A0 or a zero callback-object byte at offset 8. The lookup keys are 0x5 for right down, 0x6 for right up, 0x8 for middle down, and 0x9 for middle up. The returned callback object's first virtual method is invoked with that object as receiver. An inactive owner byte can therefore suppress the owner virtual hook while still permitting a callback whose offset-8 byte is zero. Conversely, a set node flag bit 1 suppresses this registered stage even when the owner virtual hook was admitted. No callback result is used as a handled flag to prevent the later global stage. The fresh reads mean that the contract does not assume the owner or admission fields remain unchanged across an earlier callback.

The global stage follows the targeted stage and reloads the root from engine offset 0x140. At each candidate node, admission requires its currently selected 32-bit style entry to be nonzero, together with bits 2 and 1 clear in the node's flags at offset 0x80. The style-entry selection uses the record pointer at node offset 0x68, that record's signed 32-bit index at offset 0xAC, and its array pointer at offset 0xE0. A failed admission check prunes that node and its descendants from this traversal. For an admitted node, a nonnull pointer at node offset 0x70 receives the global hook before the children are traversed. A null pointer at offset 0x70 skips only that node's hook and does not by itself prevent descent. This global walker does not apply the targeted owner's offset-0x1A0 byte check or perform a pointer-position pick.

The global hook wrappers are RVA 0x33AA88 for right down, RVA 0x33AA94 for right up, RVA 0x33AAA0 for middle down, and RVA 0x33AAAC for middle up. Assembly proves that they tail-dispatch to virtual-table byte offsets 0x100, 0x108, 0x118, and 0x120 respectively on the supplied receiver. The traversal descriptor's receiver adjustment is initialized to zero in these four routines. These wrappers prove those virtual-hook identities; they do not by themselves prove numeric registered-event keys inside the eventual virtual implementations. No such further keys or callback effects are assigned here.

The root's hook is attempted first, then its children are visited in forward linked-list order from the list at node offset 0x48. Helper RVA 0x33C360 applies the same admission and own-hook-before-children rule recursively, producing a depth-first traversal. The global stage is attempted even when there was no selected target or no admitted targeted callback. It is a separate stage rather than an alternative selected by the targeted callback's result. Callback return values do not stop the traversal in the examined direct code. Callback-induced tree mutation, lifetime guarantees, and reentrancy protections are not established by this bounded audit.

For comparison, button 0 uses targeted virtual-table offsets 0x58 and 0x60 with registered keys 0x2 and 0x3, followed by global wrappers at RVAs 0x33AAD0 and 0x33AADC selecting virtual-table offsets 0xE8 and 0xF0. Its down routine has the same focused-widget cleanup at engine offset 0x170 with key 0x13, but also performs additional state maintenance absent from the four secondary-button bodies: it clears or assigns engine offset 0x1B0 according to the selected owner, owner flag bit 5 at offset 0x150, and owner byte at offset 0x1A0, and can launch the traversal wrapper at RVA 0x33AAC4, whose virtual-table offset is 0xE0. Button-0 down also checks the engine-offset-0x178 object's node against the selected node using the parent-chain relation at RVA 0x3308C0; on failure it calls RVA 0x342270 with a null target. That helper's relevant null-target effect clears engine offset 0x178 after disabling the prior object's selected style entry. Right and middle down do not perform those engine-offset-0x1B0 or engine-offset-0x178 steps in their direct bodies. These separate fields must not be conflated: the down-only cleanup at 0x170 concerns the focused-widget pointer, the null-target helper controls the separate auxiliary target at 0x178 and its selected visibility/style entry, and 0x1B0 records the owner qualifying under button 0's down conditions. The broader user-facing behavior of those states remains outside this audit.

Button-0 up additionally calls the same null-target helper when engine offsets 0x178 and 0x1B0 are both nonnull. After its ordinary targeted up dispatch, it also compares the owner of a reselected capture-or-pick target with the owner of a fresh pointer pick. A differing owner can receive an extra virtual hook at byte offset 0xB8 and a registered callback under key 0xE, with the corresponding owner and registered-callback admission checks. Right and middle up contain neither this extra owner-comparison dispatch nor that null-target state step. This comparison establishes structural differences only; it does not assign unproved names or behavior to keys 0xE or to the virtual hooks.

The scope ends at the proved dispatch calls and directly stated field effects. Virtual-hook bodies, registered-callback bodies, further global registered-event identities, complete focus semantics, capture ownership and lifetime rules, window-message delivery, game callbacks, controller/action scheduling, and all wider writer absence remain open. The routines' direct lack of a particular button-0 step is not a claim that an invoked callback cannot perform related work elsewhere.
