# Steam World daily reset and host batch boundaries

Stable bounded native-only contract for **0x2d2eb0 → 0x2c34c0**,
their World-step/time callers, and the host's output lifetime. This
supplements remaining-runtime-gaps §6 and
[World visitation](steam-world-creature-visitation.md). No replacement
code, tests, SDK, owner data or original-game execution were used.

## 1. Actor/list reset0x2d2eb0

First collect registration-list nodes whose creature **kind byte+0x60
is nonzero** into a temporary list, in existing World+0x40 next-link
order. Only after that collection finishes, destroy those creatures,
unlink/free their registration nodes and decrement World+0x48. This
is not an HP test, not a pointer comparison against World+0x448, and
not a hostile-only selection.

All **kind0** records survive, including guests, dead kind0 records
and the local player when present. Their Creature objects, registration
nodes and relative list order remain. Clear the separate ID lookup
tree World+0x450 and rebuild it from the retained list. Its index nodes
can be replaced; the retained creatures are not reconstructed.

Finally empty the separate pointer list **World+0x50**, zero its
count+0x58 and free its list nodes. This is not a walk of any loaded
zone's static objects or ground items. Source0x2d2eb0, with the
two-phase deletion/reindex procedure also in visitation §5.

No damaging hit, drop/kill-credit award or death sound is generated by
this reset path. Deleted actors' lifetimes end here. Later spawn/pet
creation constructs new actors, even when a spawn ID is reused; an
allocator reusing an address does not preserve the old actor's state.

## 2. Archive/local daily reset0x2c34c0

This partner's ordered state changes are:

|Order|State cleared|Native operation|
|---|---|---|
|1|World dead-ID set+0x20, count+0x28|0x3d6c0 at0x2c3501|
|2|Entire archived zone-state map World+0x10, count+0x18|0x8a830 at0x2c350a|
|3, if local exists|Category22 inventory records of World+0x448|Inline slot walk, type test0x2c3560|
|4, if local exists|Local personal-data map+0x88|0xb9a0|
|5, if local exists|Local personal finished-mission set+0xd8|0x50ae0|
|6, if local exists|Local personal shop-purchase map+0x138, count+0x140|0x2f2c20 plus tree-header reset|

Personal data is reached through the local Creature's **+0x1528**.
The archive clear destroys every archived value's owned storage
(0x82970), including its saved arrays/lists, before releasing the map
entries. It does not leave a partially retained archive entry.

The inventory walk visits **all existing canonical tabs and physical
slots**, including extra saved tabs, and tests category22 regardless
of quantity. Replace the item's semantic fields and inline attributes
with the native default, then write quantity0 **last at0x2c3613**.
Keep the tab/slot addresses and vector lengths; do not erase, compact,
sort or refresh them here. Equipment and the retained cursor item are
not visited. The detailed field-clearing contract is
[slot lifecycle §3](steam-inventory-slot-lifecycle.md#3-removal-and-emptied-item-contents).

The personal+0x138 clear releases each shop's nested purchase-item list
and outer map entry. These are daily purchase records, not the known
recipe list or current vendor's displayed inventory.

Only **World+0x448's** inventory/personal data is affected. This helper
does not loop over surviving kind0 guests. If World+0x448 is null, it
returns after the two world-container clears. The ordinary native host
has a separate World without a local-player pointer; its loopback and
other guests remain kind0 records. Their local daily data is reset in
their respective client worlds when the specified client day consumer
runs; do not convert this host call into a purge of every guest.

## 3. State retained by the reset pair

The pair does not traverse or regenerate loaded-zone map **World+0x460**.
Loaded zones retain their live columns, block-change logs, ground items
and static-object lists through these two calls. A later ordinary
unload can capture those surviving live changes into the newly empty
archive again. Separately, the authoritative near-player refresh
**0x31c540** can restore base static objects and add daily objects when
that zone's refresh day differs; see remaining-runtime-gaps §6.1/6.3.
That refresh is not a consequence of clearing every loaded zone here.

Also retained by these helpers are:

- World dropped-reward IDs **+0x30**, unlike dead IDs+0x20.
- Active effect list **World+0x60/+0x68**.
- The outgoing16-container event group **World+0x90 through+0x18f**,
  including the triggering sleep/reset notices at+0x160.
- World day/time, unscaled clock+0x440, loaded name/seed, role flag
  and local-player pointer; their surrounding callers may separately
  update them as §4 describes.
- Other local personal collections: recipes, discoveries, used cells,
  marked missions, note timers, flight points and region history.
  Only the three personal containers in §2 are cleared by the partner.
- Surviving players' other record fields, including raw/drawn state,
  equipment, non-category22 inventory, links and ordinary resources.
  Existing links to deleted nonplayers are not globally cleared here;
  later native reconciliation/lookup rules still apply.

The pair does not filter already queued events by whether their source
actor survived. Ordinary later event filters/consumers remain in force.
Other World-step helpers can change retained state afterward; retention
here is not a freeze of the rest of the simulation.

## 4. Time-prelude trigger0x2e2e80

Every admitted0x2da6c0 call, including dt0, first calls this prelude at
**0x2da728**. It walks the registration list and observes whether **any
kind0 actor has ability0x58 and HP>0**. A matching actor need not be the
local player. If it is the local player, the prelude also applies the
existing sleep heal: float maxHP × float stepMS, then ×float0.001, then
×float0.05, then add HP, with a fresh maxHP cap. Nonlocal sleepers
select the time rate but do not become the local healing recipient.

First add the unscaled float stepMS to **World+0x440** in float32.
For day time, multiply stepMS by **float100** if any matching sleeper
was found, otherwise **float10**, then add to float time-of-day+0xc.
The constants are0x42e5bc (word0x42c80000) and0x42e598 (0x41200000).
The unscaled clock does not receive this sleep acceleration.

If loaded-world-name length **World+0x210 is0**, overwrite day time
with **float32400000**, word0x4bf73140, before the wrap test. This is
the string length of the name at+0x200, not an active-world pointer.

While time-of-day is **strictly greater than float86400000**
(0x438028, word0x4ca4cb80), increment the32-bit day+8 and subtract
that float day length, in float32. Equality alone does not wrap.
On each wrap, **only when World+0x358 is0**, call actor reset0x2d2eb0,
then archive/local reset0x2c34c0, then append one signed32 **value0**
to World+0x160. Native **0x2e2ff0–0x2e3074** establishes this order.
A mirror can advance/wrap its local time calculation but does not
perform that authoritative pair/notice branch.

The prelude does not require positive elapsed time to wrap a stored
value already beyond the boundary. Conversely, a zero step at exactly
86400000 does not cause a wrap. No archive-reset partner itself changes
the day or time; the changes here belong to the time caller.

## 5. Late notice scan and effects/output order in one World step

The important ordered cut points in0x2da6c0 are:

1. Time prelude and its possible early reset/notice above.
2. **0x2adfe0 at0x2da730** rebuilds World+0x50 from current registration
   entries matching0x5ef10. The early reset's empty auxiliary list can
   therefore be repopulated by this ordinary helper. Other prelude work,
   authoritative spawn/cleanup and the common pet pass then occur.
3. Full-list bit0x10 clear, then each creature's admitted physics,
   ability/interaction and upkeep visits, as in the visitation spec.
4. With **World+0x358 equal0**, scan World+0x160 in list order. On the
   first record whose signed32 value is0, call **0x2d2eb0 at0x2db703**
   then **0x2c34c0 at0x2db70b**, and break. At most one pair runs from
   this scan per World call, even if it contains several zero records.
5. Later local region/history work, then the **active effect step
   0x2dba40 at0x2db933**. Apply outgoing block changes to loaded zones'
   change logs afterward, followed by the remaining final World work.

The late scanner **does not erase, pop or decrement the count of the
notice it found**. Neither reset helper clears that list. A kind0 notice
therefore remains eligible in another substep until the surrounding
caller clears the outgoing event group. A sleep/inn producer can have
changed day/time before queuing it, but this consumer does not require
a day comparison or itself increment the day.

The late reset occurs **before** the effect step, not after effects.
Active effects survive the pair and execute their ordinary rules against
the then-current World/list/ID map. Events already produced by an erased
NPC are not removed from outgoing lists by the reset pair.

## 6. Native host batch, zero residual and notice lifetime

Host tick **0xf5520** operates on its separate embedded World at host+8.
After incoming events are applied, it calls0x2da6c0 with float16 for
the ordinary integer-step batch, then **always** calls the final float
residual at **0xf692d**. For admitted integer elapsed0 this final call
receives float0; there is no zero-ms skip. The integer cap and schedule
remain camera §7.2.3 / netcode-transport §2.

It then explicitly calls **the full0x2b68e0 at0xf693e**, passing the
saved **whole capped integer host elapsed converted to float**, at
0xf6932–0xf6937. Both its interpolation and linked-placement passes
run. Absence of a host GPU draw does not omit this world-state call.
It is followed by zone output collection0x2e30b0 at0xf6947.

Next, the host scans the still-present sleep list. A zero notice causes
each guest's **known-creature update cache** to be cleared; it does not
delete that guest's kind0 Creature. Then distribute the gathered events
with0xf33b0 at **0xf69b4**. **Only afterward**, construct an empty output
group, assign it over World+0x90 using0x83640 at **0xf69e3**, and release
the temporary at0xf69ef. This assigns an empty **whole0x100-byte group
of sixteen list/count headers**, including World+0x160/+0x168; it is
not an earlier individual sleep-list pop. These are after the entire
substep loop and full drawn-state pass, not between substeps. The next
call **0x2b9890 at0xf69f8** releases World+0x3c8's critical section;
it is an unlock thunk, not a death-output collector.

Within the preceding **0x2e30b0** zone-output call, first visit the
ground-item-changed zone set World+0x190: mark each zone's byte+0xf9
and append its key/full current ground-item list to World+0xe0. Next
visit the static-object-changed zone set World+0x1a0: mark byte+0xfa
and append its key/full current static-object list to World+0xf0.
Then call the existing0x31d700 update on those changed static-object
zones. Finally empty both changed-zone sets and zero counts+0x198/
0x1a8. The broader work inside0x31d700 is not newly specified here.

Death/kill-credit outputs already queued at **World+0x120** remain in
the same outgoing group through these stages, guest-cache invalidation
and **0xf33b0 distribution**. They are sixteen-byte records containing
credited actor ID and dead actor ID, as creature-hit/netcode-packets
specify. The verified post-batch host span has no additional actor-HP
death collector between zone output and distribution. Zone collection
does not clear/reclassify kill credits, and the reset pair does not
remove them because their source/victim actor was erased. Their ordinary
production/consumer rules remain the existing hit/network contracts.
The semantic payload of the final private outgoing header at World+0x180
and any separately named presentation death stage were not retraced here;
the confirmed whole-group clearing boundary includes that header too.

Consequently an early-substep midnight notice can trigger the **late
reset in every remaining substep of that same host tick**. The normal
spawn/pet prelude may recreate nonplayers in the next substep, but its
late scan removes them again while that zero notice remains queued.
This corrects the earlier remaining-runtime-gaps §6.2 shorthand that
repopulation on the next substep was sufficient to survive the reset.
Repopulation survives only once that notice no longer reaches a late
scan, subject to other ordinary lifecycle rules.

Derived trace, not a capture: in a33-ms host batch with steps16,16,1,
one midnight wrap in the first step, and no other notice changes, the
pair runs **four times**: once in the first time prelude and once at
each of the three late scans. A queued zero also triggers the late
pair in an admitted final0-ms step. Each reset retains kind0 records;
no later step continues an erased NPC through a stale actor snapshot.

## 7. Client boundary and scope

For received time packet8, dispatcher0x3e450 calls **0x2c34c0 only**
when incoming day differs, then installs received day/time. It does
not invoke0x2d2eb0 there, and a mirror World skips the authoritative
late notice reset. Native creature removal/update packets establish
the mirror's actor population. See remaining-runtime-gaps §6.3 and
netcode-roles §2/§4 for the existing packet/output schedule.

This contract closes the reset helpers and bounded ordinary callers
above. It does not newly specify every sleep producer, unrelated
despawn policy, archive serialization field, allocator address reuse
or concurrent actor destruction policy. Loaded-zone daily generation
and subsequent archive captures remain their existing specifications.
