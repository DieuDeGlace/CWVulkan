# Native Steam source-array dirty producers

This contract identifies directly traced producers of membership in the source-pointer sets at World+0x190 and World+0x1A0, their immediate array mutations, the ordinary viewed-World replacement route and dirty-publication order, and the bounded search for source+0xF9/+0xFA resets. It applies to the original x64 Steam image binary/cubeworld.original.exe.unpacked.exe, image base 0x140000000, PE timestamp 0x5D93AB0D, SHA256 7AF18CB28C8BF848F355287428C6390B2EA2A682CA466190F5EB9859C5D6F244. That hash was checked for this audit. Only individually identified original function files and the original decompiled/assembly.txt listing were inspected. Earlier held contracts remain unchanged.

World+0x190 is a unique set of source pointers associated with the first selected array at source+0x30. World+0x1A0 is the corresponding set for the second selected array at source+0x60. The arrays contain 0xE0-byte records. The set counts are the separate 64-bit fields World+0x198 and +0x1A8. World construction at RVA 0x29A130 zeroes the counts and constructs the sets at RVAs 0x29A20A–0x29A243. These sets, the source flag bytes, and the array descriptors are distinct state.

The reached insertion helper at RVA 0x73F40 compares unsigned 64-bit pointer values and suppresses an equal value when used with the zero insertion-mode argument shown in these producers. Repeated admissions of the same source therefore produce one set membership until clearing. The wrapper at RVA 0x7D360 reaches this same insertion. A membership records a source pointer; it does not capture the array contents at insertion time or constitute a request for a missing source coordinate.

The relevant World instances must remain distinct. Ordinary Game update at RVA 0xA5A50 reaches its viewed/client World through Game+0x8. Game construction selects a host subobject at Game+0x6E8 at RVA 0x7EB24 and calls its constructor at RVA 0x7EB36. The host constructor calls the World constructor on Host+0x8 at RVA 0xF17E1, giving the host-owned embedded World at Game+0x6F0. The host update at RVA 0xF5520 uses that Host+0x8 World. A set or flag change on one of these Worlds is not automatically a change on the other, including in a locally hosted session.

A directly traced first-array producer is RVA 0x2A5B70. On its reached placement route, it converts the supplied position to a zone key and performs a loaded-map lookup at RVA 0x2A665F. Only an existing nonnull source proceeds. After the reached record and position preparation, it appends an 0xE0-byte record to source+0x30 through RVA 0x129C00 at RVA 0x2A67FC, then inserts that source into World+0x190 through RVA 0x73F40 at RVA 0x2A681E. The append helper constructs at the current used end and advances that end by 0xE0; it can also append to an initially empty vector. The dirty insertion follows the append. A missing/null source skips this reached append-and-insert route; this lookup branch does not call source generation. The helper accepts a World argument, and its complete caller and placement-policy census is outside scope.

A second directly traced family is resident action processing at RVA 0x2C3710. The routine returns immediately when World byte +0x358 is nonzero. Its zero route walks the resident's action list at resident+0xAB8 and dispatches the byte at action-node+0xD4. Ordinary World update at RVA 0x2DA6C0 calls this routine at RVA 0x2DB6BA for a reached live resident whose float +0x180 is positive. These are literal native gates, not a universal host/remote label for World+0x358.

Action value 7 selects an existing source and an index in its first array. The source must be nonnull and the signed index must be nonnegative and below the current first-array count. Further distance and record-comparison tests precede the reached interaction. When the record's byte +0xC4 does not contain value 2, the routine inserts its source into World+0x190 at RVA 0x2C3F21, then replaces the selected entry through RVA 0x837E0 at RVA 0x2C3FB6 with a constructed record whose leading type byte is zero. This is clearing a selected entry in place, not erasing the vector element or shrinking the array length. Insertion precedes that replacement, while later publication reads the resulting current array. The other action effects and full item taxonomy are not inferred from the routine name.

Action value 5 selects an existing source and a valid signed index in the second array. One reached record-kind and resident-state branch stores the resident's 64-bit identity from resident+0x8 into record+0x30 at RVA 0x2C41E0 and inserts World+0x1A0 at RVA 0x2C4205 only if that field changed. Another reached branch requires a nonzero record byte +0x38, a nonzero state byte +0x28 and its comparison admission, calls RVA 0x2D3A10 with zero at RVA 0x2C4255, then inserts at RVA 0x2C4276. The alternate admitted record-kind branch toggles byte +0x28 through RVA 0x2D3A10 at RVA 0x2C43F4, compares the resulting byte and inserts at RVA 0x2C441E only on a change. These branches preserve their original additional kind and resident-state tests; this contract does not replace them with a generic interaction rule.

Action value 2 has a further reached area interaction for action record values 0x18 and 5. It scans existing nonnull sources and their second arrays. For an admitted kind-0x10 record with nonzero byte +0x28 that passes the reached radius test, it calls RVA 0x2D3A10 with zero at RVA 0x2C474C and inserts the source into World+0x1A0 at RVA 0x2C4773 only if byte +0x28 changed. The loaded-map and selected-index paths described above do not request source creation when lookup fails. This is an immediate-producer audit, not an exhaustive audit of the action list's gameplay, radius constants or every prerequisite.

RVA 0x2D3A10 itself returns when the requested state already equals record byte +0x28. Otherwise it writes that byte, updates the adjacent record+0x2C field and can append a reached effect record to World+0xA0 according to record kind and requested state. The dirty-set admissions in its callers are therefore separate from that helper's other effects. No gameplay action is inferred merely from an effect identifier.

The ordinary record-update routine at RVA 0x2E3510 provides additional second-array memberships. World update calls it at RVA 0x2DA73C before its later action-processing call. Within the inspected source-array traversal, the following table identifies the immediate mutation and insertion links. The original record-kind, owner, prerequisite, time and proximity admissions remain attached to those branches; the table is not a replacement predicate for the full routine.

| Original insertion call site | Immediately traced relation to the second-array record |
| --- | --- |
| RVA 0x2E4C36 | A reached kind-0x0E branch directly clears byte +0x28 after its qualifying resident and coordinate checks. |
| RVAs 0x2E51D6 and 0x2E5250 | Reached zero-World+0x358 branches clear a previously nonzero 64-bit record+0x30 association after the respective resident/state or separation checks. |

These sites insert the containing source pointer into World+0x1A0. They do not themselves set source+0xFA. The routine also has other record writes and client-visible updates, so these identified sites do not establish a general rule that every write to a second-array record produces membership. The full selection of the sources and every gameplay admission in RVA 0x2E3510 are intentionally not expanded here.

Source-local refresh at RVA 0x31C540 is another directly traced producer. Its equality test between source+0x4F8 and World+0x8 can skip refresh. On the reached refresh route, it copies the old source+0x60 vector and replaces the current vector from source+0x78 at RVA 0x31C629. A detected size or reached record-comparison difference inserts the source into World+0x1A0 at RVA 0x31C6D3 and writes one to source+0xFA at RVA 0x31C6D8. A later reached comparison can insert at RVA 0x31D3B4 and set the byte at RVA 0x31D3B9. There is no positive-length admission on the replacement: replacing a previously nonempty current vector by an empty baseline is a size difference and can enter the earlier dirty path. This directly proves an empty-vector producer, separate from the action route's in-place empty entry. Detailed refresh generation and early exits remain outside scope.

The viewed Game update has a distinct input-state replacement route. The relevant coordinate-and-array input collections are at Game+0x19C0 for the first array and Game+0x19D0 for the second. This contract establishes their application by the ordinary update, not the complete transport or population history of these collections. A local host and a remote sender are not presumed to supply them by identical scheduling.

The inspected viewed-World sequence occurs while World+0x3C8 is held: Game update acquires it at RVA 0xA6464 and releases it at RVA 0xADB23. It first clears the two viewed-World source-pointer sets through RVA 0x8AAD0 at RVAs 0xA7043 and 0xA7053. It then reaches World updates at RVAs 0xA7328 and 0xA734C under the reached settings-comparison admission; the first call can repeat for catch-up work. These World updates precede the later coordinate-and-array replacements. The set clear is not a clear of source+0xF9 or +0xFA.

A separate preceding coordinate-input pass at Game+0x19E0 looks up existing sources and writes zero to source byte +0xF8 at RVA 0xA8225. That is a one-byte write. It does not zero +0xF9 or +0xFA. The original routine at RVA 0x2DA090 likewise writes one to source+0xF8 on its reached existing-source route, at RVA 0x2DA0CE; that nearby field is not interchangeable with either selected-array retention flag.

For each first-array input record, Game update calls the loaded-only source getter at RVA 0x16E00 from RVA 0xA828B. With a nonnull source, it resets the used end of source+0x30 to its beginning and inserts the supplied list range through RVA 0x7D4A0 at RVA 0xA82CF. The latter reaches the list-to-vector insertion body at RVA 0x709F0. An empty supplied range adds no elements, so the preceding reset leaves the array empty. This branch contains no insertion into World+0x190 and no direct write to source+0xF9. That is a fact about this replacement branch: membership produced earlier in the same update can still be present.

The second-array input pass looks up the existing source at RVA 0xA834B, resets the used end of source+0x60 and inserts the supplied range through RVA 0x7D420 at RVA 0xA8396, reaching RVA 0x70780. It then inserts that source into the viewed World's World+0x1A0 through RVA 0x7D360 at RVA 0xA83B1, calls RVA 0x31D470 at RVA 0xA83BD, and calls RVA 0x31D700 at RVA 0xA83C9. The dirty insertion is admitted by the nonnull source, not by a nonempty incoming range or a detected difference. An admitted empty replacement therefore still enters the second dirty set. The two following helper-call identities and their order are proved; their broader cache and rendering semantics are not assigned here.

The getter at RVA 0x16E00 queries World+0x460 and returns null for a missing entry or a stored null pointer. It does not insert a source-map entry or call source generation. Both input-array replacement branches skip their mutation and dirty insertion when that getter returns null. This establishes their immediate missing-source behavior. It does not establish whether another component retains, retries, discards or resupplies the incoming coordinate record in a later cycle.

After both input-array passes and intervening reached identity-update work, Game update calls the dirty publisher at RVA 0x2E30B0 from RVA 0xA8498. Thus an existing first-set membership can publish array contents that were replaced after the local mutation which originally admitted the source; a membership is not a saved pre-replacement snapshot. The second-array replacement directly guarantees membership for that admitted source before this publisher call. No global ordering against every other producer or transport thread is inferred.

The publisher traverses World+0x190 first in its pointer-key tree order. For each member it writes one to source+0xF9 at RVA 0x2E3105, takes the current first-array contents and source coordinates, and appends the reached snapshot record to World+0xE0 at RVA 0x2E3171. It next traverses World+0x1A0, writes one to source+0xFA at RVA 0x2E3286, takes the current second-array contents and coordinates, and appends to World+0xF0 at RVA 0x2E32F2. Its list constructors and range-copy calls run even for empty arrays. These operations append to the output lists; they do not replace them merely because a current array is empty.

Only after both snapshot traversals does the publisher traverse the second dirty set again, calling RVA 0x31D700 for each member at RVA 0x2E33E6. It then destroys the first and second set nodes, restores their empty headers and zeros World+0x198 and +0x1A8. This clears pending memberships after publication while leaving the source flag bytes set. Each set deduplicates its own memberships, but a source can be present in both sets and therefore yield one snapshot in each corresponding output list. Snapshot ownership beyond these reached container copies, full delivery lifetime and all possible concurrent mutations remain unproved.

The host-owned World uses the same publisher independently. In RVA 0xF5520, host World+0x3C8 is entered at RVA 0xF68CD. Reached World updates at RVAs 0xF6917 and 0xF692D precede the publisher call at RVA 0xF6947. The subsequent state-assembly routine at RVA 0xF33B0 is called at RVA 0xF69B4 before the World guard is released at RVA 0xF69F8. This establishes the local order within that reached host update. It does not establish synchronous delivery to the viewed World or a universal one-frame latency.

No additional live-source zero/reset writer for +0xF9 or +0xFA was established in these directly traced producer, replacement and publication bodies. The directly identified constructor clears remain the word write at source+0xF8 at RVA 0x2F94FF, which makes +0xF9 zero, and the byte-zero write to +0xFA at RVA 0x2F9508. The other source-byte writes identified here set one: restoration at RVAs 0x2AE26A and 0x2AE284, publication at RVAs 0x2E3105 and 0x2E3286, and the two refresh writes to +0xFA. The restoration writes occur only in the proved World+0x358-zero retained-state route; that body does not itself insert these source-pointer sets. Dirty membership and retained-array override status are related but separate state.

This negative finding is bounded. Direct constant-offset accesses in the original listing and the traced source-owned paths were checked, including the identified overlapping constructor word write. An untraced pointer alias, bulk copy, indirect store, deserialization path or alternative caller is not excluded by that check. Physical destruction ends the source object's lifetime and is not a proved reset of a surviving object's flags. No universal writer census, mutation-detection guarantee, missing-source retry policy or synchronization guarantee is claimed.
