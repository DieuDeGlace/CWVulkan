# Steam local death, tombstone, and map marker

## Original image and scope

The reference is the owned Windows x64 Steam Cube World executable. The installed CubeWorld.exe and the preserved binary/cubeworld.original.exe each contain 5,939,072 bytes and have SHA-256 A1EFBBD41EEB8DF08395C4D6511194D416CB70A14054B2A2000B9F5CDBCFA65B. The preserved unpacked executable used for RVA and byte checks contains 5,757,952 bytes and has SHA-256 7AF18CB28C8BF848F355287428C6390B2EA2A682CA466190F5EB9859C5D6F244. Its preferred image base is 0x140000000. Addresses below are RVAs in that image. Offsets preceded by a plus sign are relative to the object identified in the prose.

The evidence is the original decompiled function export, the original Game frame's longer-budget function export, and selected original byte windows and data in the unpacked image. The audit follows ordinary local gameplay, its map model submission, and the selected character database save and reentry route. Creature denotes the current locally controlled creature, reached through Game +0x08 for the current World and World +0x448 for that creature. A fixed-point block contains 65,536 coordinate ticks.

## Lethal event, corpse, and the revive input

In the selected local damage path, Game frame 0xA5A50 applies a damage record to a creature whose health was positive. The local damage subtraction writes creature +0x180 at 0xA8ED5. A strictly negative result is clamped to zero and triggers a separate position capture at 0xA8EE7–0xA8F4D. This copies the three physical signed 64-bit coordinates at creature +0x10, +0x18, and +0x20, in that order, through 0xCB840. A World +0xA0 presentation event carries these exact coordinates, 32-bit kind 0x1B, the local creature's 64-bit identifier, and initialized unit scalars. Its sound consumer calls 0xA0420 at 0xAA58F and resolves kind 0x1B to destroy2.wav through 0xA3A40. An exactly zero subtraction bypasses this particular event branch and still meets the subsequent dead-health predicate.

The creature also has a distinct presentation position at +0xB10, +0xB18, and +0xB20. The selected scene-side creature culling call at 0xA9084 uses this presentation tuple. The exact coordinates in the lethal event and in the map marker have their own physical-position reads. The rendered body, camera, and map cursor have no role in those captures. The selected lethal event queues sound data and leaves the character's tombstone slot alone.

The ordinary marker is created by an accepted Revive action. Game frame 0xA5A50 runs the selected World step at 0xA7328 or 0xA734C, then the local damage window, then the input pass 0x8AE50 at 0xA9B2C. That pass calls 0x98180 at 0x8DF69. The outer input call requires World +0x210 to be nonzero, a creature action state outside 0x9C and 0x9D, and permissive visibility checks through Game +0x118, +0x130, and +0x170. The selected frame holds the current World's critical section at +0x3C8 across these operations and scene submission, entering at 0xA6464 and leaving at 0xADB23.

At 0x981D0–0x98239 the interaction routine samples Game +0x1A7B, a byte, and recognizes an edge when it is nonzero and the prior sampled byte at image RVA 0x5515B4 was zero. It saves the current sample before testing the routine's local blockers. A nonzero Game byte +0x1A7A or +0x1A7D, or a blocking UI state reached through Game +0x418, prevents the action. A visit to the routine can consume the edge even when a subsequent check prevents Revive. Earlier Fall and Climb branches can claim the interaction before the dead branch. A frame that skips the routine performs no sample through this path.

At 0x9868E–0x98734 an ordinary creature with binary32 health at or below zero receives the Revive text in the info overlay. The map record changes only if the newly pressed interaction is accepted. Holding the action across a death does not create a new edge while the previously sampled byte remains nonzero. Waiting on the prompt or failing input admission leaves an existing marker subject to its ordinary timer and distance tests.

## Marker ownership and accepted revive order

The single map marker belongs to a 0x300-byte record attached to the local creature through creature +0x1528. This record also contains character progress.

| Field | Offset | Stored value |
| --- | --- | --- |
| Remaining lifetime and active predicate | +0x28C | IEEE binary32 milliseconds. Strictly positive admits the marker to the map. |
| Anchor X | +0x290 | Signed 64-bit absolute fixed-point coordinate. |
| Anchor Y | +0x298 | Signed 64-bit absolute fixed-point coordinate. |
| Anchor Z | +0x2A0 | Signed 64-bit absolute fixed-point coordinate. |

The attached record's constructor at 0x7FF20 initializes the marker's timer to zero at 0x8020D. It supplies no initialized anchor value in the three marker fields. The World step can read the tuple before the first activation, with its proximity write limited to clearing the already inactive timer. The map requires the positive timer before reading the anchor. The attachment is initialized on the selected startup and new-character paths at 0x7F627 and 0x9FC44, and is also constructed during character deserialization.

On the admitted branch at 0x98734–0x987EF, 0x65FB0 first resets transient creature state while preserving its physical position. The branch copies the creature's current physical X, Y, and Z into the one attached marker slot at 0x98756–0x98770. It copies all 64 bits for each coordinate. The anchor records where the revivable creature is when the interaction is accepted. Any physical displacement since the earlier damage event is reflected in this capture. The operation makes no whole-block conversion, terrain height adjustment, facing copy, or render interpolation at this capture. At 0x98789 it sets the lifetime to 300,000 milliseconds. The next operation, at 0x987A7, asks 0x2C2860 for the revive destination using the creature's still-current physical position. The returned tuple replaces the creature's physical position at 0x987AF–0x987BF. The branch sets the creature's +0x140 scalar to minus 0.5 and restores health from its current maximum-health calculation at 0x987E6–0x987EB.

The accepted action overwrites the one coordinate tuple and renews its countdown on successive revives. A subsequent death alone leaves the previous marker in place for as long as its timer and distance gate permit. The selected revive writes this local character attachment and updates the same creature. The model submission is derived later from the attachment. The revive branch creates no world actor, collision object, zone object, or entry in a collection of death markers.

## Destination selection and the absence of a shrine

The bounded destination selector is 0x2C2860. Its initial candidate is the 16-block XY cell containing the physical corpse position, with negative fractions rounded down when deriving signed whole blocks and then the signed cell indices. It first checks the local attachment's +0xA8 ordered set of known cell coordinates. The keys are signed 32-bit pairs, sorted by X then Y. For a candidate it evaluates the center at eight blocks into the cell along each axis. The region key returned by 0x2ADA20 at that center must match both signed 32-bit words already on the creature at +0x150 and +0x154. The site check through 0x69C60 requires kind 0x35, identified as ShrineOfLife by 0x16C7E0. The selector ranks eligible sites by squared horizontal distance from the live physical corpse position to the center, in binary64 block units. A later candidate replaces the current best only when strictly closer, so the first candidate at an equal distance is retained. An eligible known site ends the search after this pass.

If the known set yields no eligible shrine, the selector scans the inclusive 1,024-block bins containing each axis's two endpoints at corpse position minus and plus 8,192 blocks. It visits ascending X with ascending Y inside each X. One deterministically placed candidate cell in the interior of each such bin is checked with the same site-kind, creature-region, and strict distance rules. There is no separate circular distance cutoff in this selected scan.

Both successful shrine selection and the no-shrine case reach destination construction at 0x2C2F33–0x2C2F94. With no eligible shrine in either pass, the selector still holds the initial cell containing the corpse. The returned X is six blocks into the chosen cell, the Y is eight blocks into it, and Z is the signed integral site or terrain height returned by 0x2D87F0 for the chosen cell with the kind selector supplied as zero. That helper resolves the actual kind for that cell. All three destination coordinates are returned in the same signed 64-bit fixed-point units. The two candidate-center offsets are used for the search, and the six- and eight-block offsets are used for the destination. The branch completes the teleport and health restoration on the no-shrine path. There is no caller-level unsuccessful-search return or rollback of the newly placed marker. The initial-cell destination can put the player inside the marker's proximity radius at the next update, depending on the destination height. This can also happen with a sufficiently close shrine. The marker itself stays at the exact pre-teleport anchor.

## Active lifetime and reentry while playing

The World step 0x2DA6C0 owns the countdown and proximity clearing. Its selected local branch requires a local creature and nonzero World +0x210. The branch is skipped for creature action bytes 0x98, 0x9C, and 0x9D. Creature action byte 0x99 passes this check. At 0x2DB589–0x2DB5BE it subtracts the actual binary32 World step interval in milliseconds, then clamps a nonpositive result to zero. The Game frame subdivides an interval above 16 milliseconds into 16-millisecond steps and a final remainder of at most 16 milliseconds. Marker duration therefore follows the admitted simulation steps.

At 0x2DB5C6–0x2DB642 the step takes each signed 64-bit difference between anchor and current physical creature position. It converts each difference to binary32 blocks, squares the three components and sums X and Y then Z. A squared distance strictly below 400 clears the timer, including when the player is dead or when the revive destination itself is that close. At a computed squared distance of exactly 400 the proximity test leaves the timer alone. An expired timer or one cleared by proximity suppresses the marker without erasing the stored tuple. The test is three-dimensional and precedes the later general creature movement pass. Returning within range removes the marker automatically when the admitted step next observes that position. The map display requires no click or collection action.

Map visibility is independent of gameplay ownership. Opening, closing, panning, or crossing a zone boundary supplies no new owner or marker state in the reached draw path. The marker can continue to appear on later map submissions for the same attached record while its timer remains positive. It is consumed from the local character attachment even when the character's model or the marker's original zone is outside the view. This claim concerns retention of the attachment and the display path. Recreating the attachment follows the initialization and load rules below.

## Exact anchor and displayed map model

The selected scene submission is 0xE2E00, called at 0xAD9D4 after local input. With World +0x210 nonzero and scene flags bit 0x20 clear, its map branch calls 0xE64B0 at 0xE41A2 and the map renderer 0x2F44A0 from 0xE65C1. The map reference position comes from Game +0x1E20, passed at 0xAD98A–0xAD991. The frame has a player-follow initialization for this tuple at 0xA7E8E–0xA7EE7 and a distinct path that moves the map reference toward a pan target. This reference can differ from the live creature's position. The frame can submit the newly created marker in its current map pass before the next simulation step evaluates proximity.

In 0x2F44A0, 0x2F6227–0x2F6411 adds one temporary 224-byte map draw record after the ordinary map collection steps when the local creature exists and its timer is strictly positive. The record carries the exact stored signed 64-bit X, Y, and Z at its own +0x00, +0x08, and +0x10. It carries a zero-degree binary32 yaw at +0x18, signed 32-bit kind −1 at +0x1C, and the default map appearance initialized through 0x4D1F0 at +0x24. The binary32 +0xD4 model scale is first initialized to one and then set to 0.4 divided by the scale factor computed by the map view for this call. That scale factor is formed in binary32 by multiplying the incoming view scale by 0.6 and then by 80, dividing by 120, multiplying by 16, and dividing by the map image's extent setting, whose initial value is 8. The +0xD8 view-depth scalar derives from the exact anchor relative to the map reference and the map view direction. Its depth-only conversion applies the truncated fixed-point reciprocal of the map divisor to the signed differences before conversion to floating-point blocks. The temporary records are sorted from larger to smaller depth before submission. The character's attached coordinates are unchanged by these calculations.

At 0x2F64CF–0x2F6569, record kind −1 selects the map tombstone model from the current World's model table reached at World +0x70. The pointer is in zero-based slot 0xDE7, decimal 3559, with a table length check against 0xDE8. In resource registration 0x177F50, the window at 0x1E0300–0x1E0365 loads the original resource name tombstone.cub into that slot. A missing model pointer skips submission. The native actor kind named Tombstone is a separate identifier, 0xEE, whose appearance selector at 0x53E80 also uses model slot 0xDE7. The local death marker's signed kind −1 takes the temporary map draw path.

The renderer may shift the marker toward the display boundary. At 0x2F67B9–0x2F6BC5 it checks the magnitude of each horizontal difference truncated toward zero to signed whole blocks, first X and then Y using any adjustment already applied. The horizontal limit is the map divisor times the image's map-cell factor and current map extent. The divisor is at least one and otherwise is the truncated binary32 product of four and two raised to the selected map level, with level constrained by the available map levels. The map-cell factor and full extent initially are 16 and 8, and the small-extent branch uses half the full extent. At or beyond an axis's limit the renderer scales all three components of the displacement toward the boundary using the magnitude of that truncated axis difference. The display displacement is computed in binary32 blocks and converted back to fixed-point ticks toward zero. This is a view-local operation. The exact revive anchor and proximity test still use the character record.

For submission, the map subtracts the reference position from the resulting display coordinates and converts the difference to binary32 blocks multiplied by the map divisor's reciprocal. It applies the temporary record's uniform scale and zero local yaw, then translates the voxel model by negative half of its dimensions on each axis in model space. This centers the model on the display anchor. The map's own view transform determines the orientation on screen. The selected map draw calls at 0x2F6DB6 and 0x2F6E27 use 0xEE2F0. They submit 26 offset instances with zero RGBA and a highlight amount, then the centered instance with unit RGBA and zero highlight amount. The highlight amount is half of one plus the cosine of 0.006 times World +0x440, the current World's millisecond clock for this purpose. The draw effect does not start or stop the marker's lifetime.

## Character save and reload

Startup opens Save/characters.db through 0x67070 at 0x7F32E. In the selected save path 0xA27B0, the World lock protects the snapshot of the current character. The record copy through 0x7FBB0 at 0xA28B7 preserves the in-memory marker timer and the three coordinate fields, as shown by 0x7FE28–0x7FE57. After releasing the World lock, 0xA27B0 serializes the snapshot through 0x149760 at 0xA29CF, compresses the data and writes the character entry with the character database lock held. The character serializer writes the snapshot's current physical tuple and health and persists the known site coordinate set from attachment +0xA8. The serialized format omits the tombstone timer and all three anchor fields. A pre-revive save can therefore record the creature's dead position and health. A post-revive save can record the creature's destination and restored health, with the old location and countdown absent as tombstone state.

On successful lookup, 0x9BB20 reads and decompresses the character entry and invokes 0x147800 at 0x9BCDA. The loader restores the saved physical tuple and health and constructs fresh attached progress storage, with constructor calls at 0x14788B and 0x147CF8. It restores the persisted progress fields, including the known coordinate set. The marker fields have no deserialization, leaving the timer at its constructor value of zero. The selected return to the menu through 0x9FDF0 saves the active character and reloads the selection entries. The existing-character selection through 0x9F7C0 reloads the selected entry into the local creature. Reentry through this successful load starts with no active tombstone, even when the saved character's current position is the revive destination. This establishes the loader's inputs and restored fields. Later adjustments to character health and placement depend on the entry route.

## Evidence boundaries

The verified frame and owner windows cover the ordinary local interaction, one ordinary lethal damage event, the destination selector's two searches and initial-cell fallback, the attached record's ordinary tick and map read, original model registration, and character database reentry. Selected instruction windows were compared with the unpacked image. Direct image data checks included the asset and registered names, the fixed-point conversion and distance constants, and the map scale and extent defaults. The direct stored-timer references were resolved by following their owning objects. An unrelated record with the same numeric offset establishes no tombstone behavior.

The physical control binding, the full set of lethal health changes, exceptional animation and movement modes, exceptional database reads, network peers, and alternate world or state transfer routes are outside this bound. The selected sound event and creature culling establish their own position sources. They leave the full corpse animation and asset geometry unresolved.
