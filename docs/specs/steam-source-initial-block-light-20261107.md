Each stored block record has six bytes. The first three are the color bytes supplied by the color-to-block converter; byte +4 is the type, with zero and two the air/water cases distinguished by the reached original terrain paths. Byte +5 contains flags. The fourth byte, +3, is separate metadata and is not assigned a broader meaning here. The mesh lighting prepass later replaces byte zero of stored type-zero and type-two records; that is the same physical byte initially receiving the first color component, not a separately allocated source-zone light array.

Zone constructor RVA 0x2F9400 constructs 4096 column objects at zone+0x518, stride 0x58, using the column constructor at RVA 0x6CBD0. That column constructor initializes its stored start height at +0x3C to zero and its six-byte record vector’s beginning, end and storage end at +0x40, +0x48 and +0x50 to zero. A newly constructed column therefore has no stored block records. This is not a full-height array filled with prelit air.

When the normal column store needs to grow or prepend records, RVA 0xA36E0 reaches resize RVA 0x6D030. The new storage is built through RVA 0x6CB30, whose initialization helper RVA 0x6CAF0 writes all six bytes of each new record to zero. Existing records are copied into their appropriate positions and their six bytes are preserved. Any new gap not subsequently overwritten therefore begins as bytes 00 00 00 00 00 00: stored type-zero air with byte zero equal to zero. This is a default construction value, not the result of a neighborhood lighting solve. It does not establish that every air record in a completed generated zone came from an untouched gap.
