## Ordinary call and seed owner

The interaction routine at RVA 0x98180 resolves the selected entity ID from the game field at +0x1E58 by looking it up in the world's entity table at +0x450 through RVA 0xE720. The lookup uses a full 64-bit key. For the nearby friendly NPC branch, the entity byte at +0x60 is 3 and the squared distance is below the square of its interaction range. A petrified target follows the separate Examine branch. For Talk, the routine submits the literal control label Talk with the info label key at RVAs 0x98C93–0x98CC9 and records the entity ID in the game's prompt field at +0x1E68. The prompt itself submits no phrase seed. The action requires a new press detected from the current use state and its previous sampled state.

The class byte at speaker offset +0x14C is tested before fresh speech. Values 0x80, 0x81, 0x82 and 0x9C take the vendor menu route and reach the inventory refresh at RVA 0xB75D0. Values 0x83 and 0x9A take the analyzer panel and flight map routes, respectively. Those branches return before the ordinary dictionary call.

The ordinary branch also checks active speech entries against the full speaker ID at speech-entry offset +0x210. A match uses the existing entry. It sets the read-time field at +0x200 to the current dialog duration if the read time was shorter. Otherwise it adds 100,000 to that field. The match returns before script construction, formatting, or a new interaction event. The duration routine is at RVA 0x290430 and the increment constant is at data RVA 0x43800C.

For fresh ordinary speech, the script builder at RVA 0x2D9480 receives the world and the selected speaker at call site 0x98E07. An empty returned script skips phrase formatting. With a nonempty script, the caller reads eight bytes from speaker offset +0x08 at RVA 0x98E40. It treats those bits as an unsigned 64-bit integer, takes the remainder on division by 100,000, and passes that value at RVA 0x98E82 to the script formatter at RVA 0x1694E0. The formatter saves the low 32 bits of its third argument at RVA 0x169520. The modulo happens at full ID width before the 32-bit argument is taken. The range is 0 to 99,999 inclusive, including zero.

This value belongs to the formatting invocation. Its only input at the call site is the selected speaker's current entity ID. There is no draw, counter advance, or seed salt from the player, time, name, world, or connection in that calculation. The call supplies the dictionary on the game object at +0x50, the script, an initially empty output list, and an empty argument string. At RVA 0x98EA8 the caller submits the produced pages with the speaker and the local player as listener. RVA 0xA3170 stores their full IDs at +0x210 and +0x218, appends speech pages to the speaker entry, and routes pages carrying response keys to the response widget. It is the pages and IDs that are retained. The fresh Talk path also queues interaction type 3 with the full speaker ID through RVA 0x98040 at call site 0x98EBE, even when the script is empty. It does so after the optional formatting call.

## Script choice before the formatter

RVA 0x2D9480 has special cases that still pass through the ordinary formatter. Class 0x9B builds the trainer script using the keys hello and how_can_i_help_you, defines the specialization using the player's class and one minus the player's specialization byte, then includes change_specialization? and goodbye?. Class 0x84 builds the inn script with the number 10, hello and a new page. From 18:00 through 06:00 inclusive, the player's gold count below 10 selects you_dont_have_enough_gold_to_rest_here. Sufficient gold selects how_can_i_help_you, rest_inn? and goodbye?. During the intervening daytime it uses you_can_rest_here_between_six_and_six. The world time field at +0x0C is compared against the original float values 21,600,000 and 64,800,000. The player's gold field is at +0xAAC. These conditions select script entries and arguments while the formatter still receives the ordinary speaker remainder.

The other class branch prepares mission context at RVAs 0x2ADA20 and 0x115DF0 using the world and the speaker's reference coordinates at +0x1B8 and +0x1C0, then invokes the mission dialogue builder at RVA 0x12A6F0 at site 0x2D9AF4. It owns a separate local selection seed. At RVAs 0x12A740–0x12A785, it takes the unsigned 64-bit speaker ID remainder by 333,333 and adds 13 times the 32-bit world day at world offset +0x08 with 32-bit wrap. It applies the same 32-bit xorshift described below to initialize its local seed. The world reference comes from the mission context at RVA 0x115DF0. The day is independently evidenced by the inn-rest processing at RVA 0x2C3710, which increments that field and sets the time field.

Two concrete mission branches establish the distinction. When speaker byte +0x128 has bit 0x02 set, the builder at RVA 0x128570 uses the low bit of the xorshift on the current mission seed to decide whether to append !alert and uses the next seed to decide whether to append hey_you followed by new_page. Each bit decision takes the old seed and advances the local word by one. It then appends help and the caller returns that script. If that flag branch is skipped and the 32-bit model at speaker +0x64 is 0x101 or 0x102, this builder returns just hello. Its arena, mission and rumour branches can use other actor and mission state and perform additional script-local selections. One reached script-building branch explicitly reseeds the CRT at RVA 0x12E96D before its model-selection helpers. The ordinary formatter's input is recomputed from the speaker ID after script building returns. Its value is independent of any script-local draw or CRT state.

The queued type-3 interaction can separately change world state. For example, RVA 0x2C3710 can set the target state at +0x19C to 0xFF and clear its +0x128 bit 0x0100 on the corresponding unset-state branch. The following conditional world action includes CRT draws. This processing is downstream of the local paragraph choice. It can alter inputs to a later script even when the speaker's phrase seed is the same.

## Phrase and nested choice

The formatter at RVA 0x1694E0 processes the script in order with a new local formatting context. Definition commands fill variables and tags, and new_page sets a page boundary. Each ordinary phrase key it forwards at RVA 0x16A68F gets the same saved 32-bit call seed. The full key and current context still matter. For example, a key ending with a question mark can attach a response key to the generated page. Page construction, definition commands, and calling the next key do not advance the saved phrase seed.

The choice operations in RVAs 0x167C80 and 0x166CB0 use unsigned 32-bit xorshift with shifts 13, 17 and 5. First XOR the word with itself shifted left 13 bits. Use that result for an XOR with its logical right shift by 17 bits. Then XOR that result with its left shift by 5 bits. Each operation is on the low 32 bits. Any seed increment wraps at 32 bits. Selection uses the unsigned scrambled word modulo the relevant ordered alternative count.

- At the phrase entry lookup in RVA 0x167C80, a missing entry or null text yields no phrase. If the found entry has a nonempty stored alternative list, it selects from that list using the scramble of the call seed and enters the selected root with the original seed plus one. If the list is empty, it enters the primary root with the incoming seed. The increment stays local to that phrase formatting call. The top-level literal and control forms beginning with * or ! follow their respective output paths before ordinary lookup.
- At RVA 0x166CB0, the recursive seed is passed by value. The native parser at RVA 0x16D530 gives a brace group its choice node and a bracket group its optional node. In a brace group, tagged children are tried in stored order against the current context. A matching conditional child can terminate the walk and suppress the untagged alternatives. The tag gate accepts a match against any of the node's required tags. If the tagged walk does not stop the group, it chooses among the accumulated untagged children by scrambling the local seed and taking the remainder by their count. The chosen child receives that same local seed.
- A bracket group's optional child walk uses the low bit of the scramble of the group's incoming seed. Even omits the optional children. Odd enters them with the incoming seed plus one. This advance stays in that recursive call. A sibling elsewhere in the parent still receives the parent's value. A child choice never returns an advanced phrase seed to the parent.
- A reached macro or parameterized dictionary reference inside a phrase recursively enters its resolved root with the current local seed. The substitution can bind a new variable or tag context. The recursive call does not rerun the Talk caller's entity-ID calculation or the top-level alternative selector. Text substitutions can change output independently of the seed.

There is a concrete Name-related template reached from the mission script builder. A branch in RVA 0x12A6F0 emits define_mob, then the 32-bit scramble of its current local mission seed and a model argument, before subsequent speech tokens. RVA 0x1694E0 reads the two decimal operands, passes the model and name-generation input at RVA 0x169845 to RVA 0x15DC80 and installs the resulting name variable. RVA 0x611D0 consumes the supplied name input and model. The outer ordinary phrase call retains its saved seed. Literal define_name handling in the formatter decodes an explicit string into the name variable. An independently invoked literal name command in the selected ordinary scripts was not established.

## Response and repeated interaction

A player answer follows a different call site. RVA 0x965E0 resolves the response widget's recorded speaker ID against the world's entity table, obtains the selected answer key, and dispatches at RVA 0x96809 to RVA 0x89CB0. The change_specialization? response toggles the player's specialization and builds a confirmation with the key your_specialization_is_now. Its formatter call at RVA 0x89F60 reads only the 32-bit word at speaker +0x08 and passes those raw bits. There is no divide by 100,000 at this response call. The rest_inn? response instead debits 10 gold and queues type 5 for the innkeeper when the time and gold checks pass. The reached rest response has no ordinary phrase seed submission.

Repeated use during active speech only advances the existing presentation. Fresh use of the same speaker repeats the seed computation. With the same speaker ID, script, dictionary and context, it makes the same selections without needing counter continuity. Another speaker can change the 64-bit ID and all the script inputs specific to that speaker. If two IDs have the same unsigned remainder by 100,000 they start phrase formatting with the same value. Their mission seeds, selected scripts, or context can still differ.

After a reconnect, the ordinary call uses the runtime entity it resolves at that time. If the ID is the same, the phrase seed is the same. A different ID may change the remainder even for a visually identical NPC. A changed day, role, flags, location context, quest progress, player data, language, or dictionary can change the script or rendered line despite the same phrase seed. The cited paths establish the call's dependency on the ID and its use of current state. They do not establish an unconditional guarantee that the network or save system restores every speaker ID or all of that state, or that active speech survives reconnect. They also do not establish a universal seeding rule for every dialogue or UI entry point.
