# Steam ordinary GUI wheel delivery: bounded original-evidence contract

FINAL / STABLE / HELD. This contract concerns the original Steam x64 image with preferred base 0x140000000, PE timestamp 0x5D93AB0D, and SHA256 7AF18CB28C8BF848F355287428C6390B2EA2A682CA466190F5EB9859C5D6F244. The image hash was rechecked for this assignment. Evidence is limited to individually identified original decompiler files and their original assembly listing. The proved route is window procedure RVA 0x133C70 to game wheel routine RVA 0x97CC0, with retained-pointer query RVA 0x333E70, picker RVA 0x333F60, the directly selected panel-step pair at RVAs 0x27F7A0 and 0x280270, and narrow ordering reads from input-loop RVA 0x1355A0 and pointer-update RVAs 0x97880, 0x101160, and 0x3418D0. Base Widget and Button wheel virtual bodies have no individually established original RVAs in this assignment and remain outside scope. No slot or override census is inferred.

The ordinary WM_MOUSEWHEEL branch is message 0x20A in the window procedure at RVA 0x133C70. Beginning at RVA 0x133EBD, it takes bits 16 through 31 of the message's value argument and interprets those bits as a signed 16-bit quantity. Every negative quantity becomes minus one, every positive quantity becomes plus one, and zero remains zero. The result is sign-extended to a signed 32-bit argument and passed directly to RVA 0x97CC0 at call site RVA 0x133EDA, together with the stored game pointer. The window procedure returns 1 after the call. This is sign normalization per delivered message, not division by 120 or preservation of raw wheel magnitude: different nonzero magnitudes with the same sign produce the same argument in this entry path.

The wheel branch does not read or forward the message's coordinate argument. The ordinary fourth window-procedure argument is unused by the inspected procedure. The low 16 bits of the wheel message's value argument are also discarded by this branch; they are not used to reconstruct held buttons or modifier state here. Message 0x200, ordinary pointer movement, returns directly in this same procedure rather than updating the retained GUI coordinates. Thus neither a wheel message's own physical coordinates nor an earlier pointer-move message's coordinates are substituted into the wheel query by this procedure.

RVA 0x97CC0 accepts a signed 32-bit scalar and retains it by value for the duration of the call. Its body does not enforce the minus-one-to-plus-one range. This distinguishes the ordinary message entry's normalized argument from the callee's accepted input. The routine contains a fixed-priority panel route followed by fallback game-state changes. In the inspected entry and router there is no intermediate generic GUI-engine wheel dispatch, owner wheel virtual-hook call, registered wheel-event lookup, or global notification traversal. This is a statement about this direct route, not a claim that such facilities cannot exist elsewhere in the image.

The panel candidates are tested in this exact order by their pointer fields in the game object: offset 0x330, then 0x350, then 0x340, then 0x658, then 0x388. For each candidate, the routine takes that panel object's node pointer at offset 0x178 and first requires the node's selected 32-bit style entry to be nonzero. The selected entry is reached through the node's record pointer at offset 0x68, that record's signed 32-bit index at offset 0xAC, and the array pointer at offset 0xE0. Only after that style test succeeds does it call retained-pointer query RVA 0x333E70 on the panel's node.

RVA 0x333E70 obtains the associated engine pointer from the supplied node's offset 8, copies the engine's retained 32-bit floating-point coordinates at offsets 0x180 and 0x184 into a local pair, and calls picker RVA 0x333F60 with the supplied panel node as the subtree root, that coordinate pair, and zero options. Assembly confirms that the supplied node remains the picker's first argument despite an inaccurate argument rendering in this small helper's decompilation. The query returns whether the picker found any node. It does not return a widget owner to the wheel routine and does not require that the found node be the panel node itself.

This wheel query does not consult the capture override at engine offset 0x168, the focused-widget pointer at engine offset 0x170, or the held-button mask at engine offset 0x1A8. It performs an ordinary subtree pick using retained GUI coordinates. The wheel-entry branch and game wheel router do not directly set or release capture, change that focused-widget pointer, clear the separate auxiliary target, or change the held-button mask. Their direct panel-node offset-0x178 reads must not be confused with a read of the engine's separate offset-0x178 auxiliary slot. These statements do not assign effects to uninspected consumer helpers or to the picker's indirect hit-test implementations.

The first panel passing both its selected-style test and retained-coordinate subtree query wins. Later candidates and fallback game changes are skipped even if that panel's step method subsequently cannot change its state. For the first three panel fields, a negative argument selects RVA 0x27F7A0 and a positive argument selects RVA 0x280270. For the fourth field, the corresponding direct targets are RVAs 0x276EA0 and 0x276F10; for the fifth they are RVAs 0x27B360 and 0x27B470. Their identities are proved from the router, but the latter four method bodies were not expanded in this audit. Zero causes no panel-step call on an eligible panel and still leaves that panel as the winning route, without falling through to the next candidate.

The inspected first-three-panel step pair receives the panel object only; it receives neither a raw wheel quantity nor a pointer to a delta object. After its own initial helper call, RVA 0x27F7A0 can increment a selected stored 32-bit item by exactly one, subject to its upper-bound checks. RVA 0x280270 can decrement that item by exactly one when it is positive. Their initial direct prerequisite includes a nonnull panel field at offset 0x1E8; the item is selected through the array pointer at panel offset 0x288 and index at offset 0x2B4, with the array end at offset 0x290. This minimum consumer evidence establishes direction-only single-step semantics for that pair. It does not establish every side effect of their later direct helper calls or imply identical internals for the other consumer pairs.

If none of the five panels qualifies, the game wheel routine uses the same signed argument in fallback arithmetic without repeating the window entry's sign normalization. With game byte 0x1A7D clear, the argument is subtracted from the 32-bit map-zoom index at game offset 0x1E04 and the result is bounded to 0 through 6; a changed index can trigger further map-position updates within the routine. With that byte nonzero, the routine instead subtracts twice the argument from the floating-point value at game offset 0x1DB8 and applies its bounds checks. Consequently a larger accepted argument can matter to fallback arithmetic even though the ordinary WM_MOUSEWHEEL entry supplies only minus one, zero, or plus one. This contract does not expand the downstream map or camera pipeline, nor does it claim that an arbitrary out-of-range 32-bit input has overflow-free mathematical behavior.

The inspected main input loop at RVA 0x1355A0 drains queued window messages through TranslateMessage and DispatchMessage before its ordinary pointer/device polling block. The foreground-window admission check for that polling block is also after the message-draining loop. Therefore a queued wheel message encountered in that loop is delivered through the direct window/game route before that outer pass's later ordinary polling checks. After the drain, an eligible pass calls GetCursorPos and related coordinate conversion, then the keyboard and 16-byte physical mouse-state polls, whose original call sites include RVAs 0x13665C and 0x136672. In the normal action-processing branch it invokes the game mouse handler at RVA 0x13683E and only afterward polls XInput at RVA 0x136881.

When the game mouse handler at RVA 0x97880 admits GUI processing, it passes integer-converted pointer coordinates to RVA 0x101160. That helper converts them to 32-bit floating-point coordinates and calls engine pointer update RVA 0x3418D0 at call site RVA 0x101195. The engine update saves the old coordinates at offsets 0x188 and 0x18C and writes the new values at offsets 0x180 and 0x184. This establishes a concrete later update of the state read by the wheel query. It does not establish that this is the only writer, that every input-loop pass reaches it, or that the retained coordinates are always exactly one frame old. At wheel delivery, the query uses whatever retained coordinate values are present then; it does not wait for the upcoming poll in this loop.

The input routine also has a later controller-derived call to the same game wheel routine at RVA 0x136B60, passing minus one or plus one under its own branch conditions. It follows the ordinary mouse-handler and XInput call sites in the inspected control flow. That is a separate input source and does not change the WM_MOUSEWHEEL normalization or prove a shared event-buffer policy. No broader controller repeat scheduling is specified here.

For a single ordinary wheel delivery, the window procedure invokes the game wheel routine directly and resumes only after that call returns. The router makes its selected direct consumer call within that call chain. The delta is a by-value scalar; no registered-callback packet containing a borrowed delta pointer is constructed in the inspected route. The retained-coordinate query's local pair is temporary stack storage passed to the picker during that query. These direct argument forms do not establish any Widget/Button wheel callback lifetime, retention right, deferred-delivery guarantee, or ownership protocol. The source ordering likewise does not establish operating-system coalescing, reentrant message ordering, losslessness, multithreaded delivery, or application buffering beyond the explicitly observed calls. Picker recursion is hit selection, not the global callback traversal used by other mouse-button paths.
