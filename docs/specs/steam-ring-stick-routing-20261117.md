# Steam Ring selector left-stick routing

This contract covers the unpacked x64 Steam image `cubeworld.original.exe.unpacked.exe` with preferred image base `0x140000000` and SHA-256 `7af18cb28c8bf848f355287428c6390b2ea2a682ca466190f5eb9859c5d6f244`. Addresses below are image-relative RVAs. The evidence is static and scoped to the traced input and Ring update paths.

## Input ownership and frame order

Game owns the processed left-stick X and Y as consecutive binary32 fields at Game offsets `+0x1D6C` and `+0x1D70`. The constructor clears both to positive zero at `0x7ED1E`. The Ring consumers read these Game fields. The hardware read occurs in the frame loop at `0x136881`, which calls the `XInputGetState` import thunk at `0x31DBB8` for controller index 0. The loop supplies the Game pointer from RVA `0x551A80` to the left-stick setter at `0xA38C0`.

The digital inputs are separate Game bytes. Move Forward, Move Backward, Move Left and Move Right are action slots 5 through 8 at offsets `+0x1A75` through `+0x1A78` respectively. The action names are identified by the switch at `0x42670`. On the regular input pass, the loop clears the mapped action bytes and then sets each from its configured keyboard or mouse input, where applicable, before calling XInput (`0x136734`–`0x1367D7`, writer at `0xA36C0`). The fixed controller button mappings on the traced success paths address other action slots. A failed XInput call therefore leaves any movement byte already set by the keyboard and mouse pass available to the Ring.

The frame loop continues to the frame wrapper at `0x137B8E` after input processing or a bypass. The wrapper calls Game Update at `0x134558` with Game in RCX, which Game Update retains in R13 at `0xA5AED`. Within that update, vertical auto-close runs first, Interface Update is called at `0xAB5CE`, and the horizontal selection block follows at `0xAC756`. Interface is embedded at Game offset `+0x118` and stores a back-pointer to Game at Interface offset `+0x5C0` (construction at `0x7EB14`–`0x7EB1E` and `0xF87AC`). Its Update retains the Interface receiver in R13 at `0x10327F`. The open-state handle at Interface offset `+0x1F8` is the same handle as Game offset `+0x310`.

## Processed values at the end of the input pass

- **Successful gameplay or map route.** The result is successful when XInput returns zero. The selector at `0x136A1A`–`0x136A35` uses the Interface menu-open result from `0x1014F0` and the Game map-open byte at `+0x668`. Gameplay input is admitted when the menu-open result is false or the map-open byte is nonzero at this decision. The Ring by itself uses this route. At `0x1373DE`–`0x137414`, signed 16-bit X and Y from sample offsets `+0x08` and `+0x0A` are converted to binary32, multiplied by the `1/65536` constant in XMM11 (loaded at `0x13641A` from `0x42E510`), then doubled. Each axis is exactly its signed input divided by 32768. X arrives in XMM1 and Y in XMM2 at `0xA38C0`. The setter stores the pair and measures squared radius using two binary32 squares and their binary32 sum. If the sum is strictly below the binary32 constant at `0x437F7C` (bits `0x3D23D70B`, about 0.04000000283), it replaces both axes with positive zero. Equality retains the scaled pair. Outside the dead zone the scaled magnitudes are preserved.
- **Successful ordinary menu route.** A true menu-open result with the map-open byte zero takes the call at `0x136A41`. Both left-stick setter arguments come from XMM6, initialized to positive zero at `0x135E5F`. This publishes a zero pair even with a deflected stick.
- **Failed poll.** A nonzero result from XInput branches at `0x136888` to `0x137ADE`. The call at `0x137AEB` supplies the same positive zero to both left-stick setter arguments and overwrites the prior pair.
- **Skipped regular poll.** If the input-enable byte at `0x536CE8` is zero, or the window returned by `GetForegroundWindow` differs from the game window stored at `0x551AC8`, the branch at `0x136632` or `0x136645` bypasses the mapped-action refresh and all XInput paths. It goes through the 16 ms sleep at `0x137B83`–`0x137B88` to the same frame wrapper. The prior Game pair and movement bytes carry forward through that branch. The separate binding-capture branch at `0x13667C`–`0x13672F` likewise bypasses the regular action refresh and XInput, then rejoins the frame path at `0x137B04`. This covers these specific bypasses and frames that reach Game Update. The frame wrapper can return early at its initialization guards (`0x134433`–`0x134449`).

## Vertical auto-close

At `0xAB46D`–`0xAB4B8`, Game Update checks the Ring open state through the handle at Game `+0x310`. An open selector closes if the Move Forward byte is nonzero, if processed Y is strictly greater than `+0.25`, if the Move Backward byte is nonzero, or if processed Y is strictly below `-0.25`, checked in that order. The Y operand in XMM1 is the binary32 field at Game `+0x1D70`. The upper threshold comes from `0x4AC95C`, and the lower threshold comes from `0x42E804` through XMM0. Equality at either threshold leaves the analog close condition false. The close writes the open state to false through `0xA3A20`, before Interface Update and the later selection check.

## Arrow publication

Within Interface Update (entry `0x103200`), a nonzero map-open byte at Interface `+0x550` closes the Ring at `0x106152`. The Ring open-state test at `0x10615E` gates both arrow publications. This test uses the state after the Game auto-close and the Interface map-close check.

For an open Ring, `0x10616B`–`0x1061F7` publishes the visual value for the child named `left`. It is active when Move Left is nonzero or processed X is strictly below the binary32 value of `-0.2` (bits `0xBE4CCCCD`). At `0x10618B`, XMM0 holds that threshold from `0x42E800`, and the other operand is the stored binary32 X at Game `+0x1D6C` reached through the Interface back-pointer. At `0x106209`–`0x106289`, the child named `right` is active when Move Right is nonzero or processed X is strictly above the binary32 value of `+0.2` (bits `0x3E4CCCCD`). At `0x106221`, XMM0 holds the same Game X and XMM6 holds the threshold from `0x42E700`.

The directions are evaluated independently. The four-float value published to each child is 1, 0, the binary32 value of 0.2, 1 when active, and 1, 1, 1, 1 otherwise. The 1 comes from XMM7 via `0x105117` and constant RVA `0x4AC980`, and the active value's zero comes from XMM12 initialized at `0x10328E`. The two publications occur before the selection repeat block.

## Horizontal selection repeat

The open-state check at `0xAC756` precedes the selection block. For an open Ring with candidates, the actual direction tests are at `0xACB9D`–`0xACBD4`. Left is requested when Move Left is nonzero or processed X is strictly below zero. Right is requested when Move Right is nonzero or processed X is strictly above zero. The shared zero is the low scalar lane of XMM12, cleared at `0xA689B` and carried to both comparisons. The left comparison reads Game `+0x1D6C` directly and yields the request in DL. The right comparison uses the same field through XMM0 and yields the request in BL.

The repeat-ready byte at RVA `0x551554` is cleared when the selector is closed at the selection check (`0xACDA8`). The open, nonempty branch arms repeat on a pass with neither direction requested. Each unrequested direction clears its own signed 32-bit countdown, at RVA `0x551558` for left and `0x55155C` for right. Once armed, a requested direction with a countdown at or below zero steps the signed 32-bit selection index at Game `+0x20C0`, by minus one for left or plus one for right, and reloads its countdown to 200 ms. The left check precedes the right check. Both can step in the same pass if the digital inputs request both and the respective timers are ready. On the timing path the countdowns are aged after the step decisions, by subtracting the current Game Update interval in milliseconds in double precision, truncating toward zero to a signed integer and flooring negative results at zero (`0xACBD6`–`0xACCD5`). Game Update caps the incoming interval at 1000 ms at `0xA5AFC`–`0xA5B0A`. The open empty branch bypasses the repeat logic.

Signed zero is neutral in each analog comparison. At the exact positive or negative arrow threshold the corresponding analog highlight is false while the sign still requests selection. Under masked floating-point invalid exceptions, an unordered axis fails the analog comparisons and the digital inputs can still supply the corresponding actions. A signed-16-bit XInput sample and the traced setter produce finite values.

## Distinguishing cases

Assume the Ring is already open, it has candidates, its repeat is armed with the relevant countdown ready, and the four movement bytes are clear unless stated otherwise. Each result assumes the corresponding consumer is reached.

- A successful gameplay sample of raw X 6553 and Y 0 stores two positive zeros. Raw X 6554 and Y 0 stores X 0.20001220703125 and Y 0, highlights the right arrow and requests a right step.
- Raw X 4096 and Y 6554 on the same route stores X 0.125 and Y 0.20001220703125. It requests a right step and leaves both arrows idle. The vertical check leaves the Ring open.
- With raw X zero, raw Y of either 8192 or -8192 stores the corresponding signed 0.25 boundary and leaves the Ring open. Raw Y of either 8193 or -8193 crosses the applicable boundary and closes it before arrow publication and horizontal selection.
- With a prior Game pair of X 0.5 and Y 0, a successful ordinary-menu poll or failed XInput poll stores two positive zeros. A skipped regular poll on either window gate carries forward X 0.5 and Y 0. If the Ring reaches its open checks with that pair, the right arrow is active and right repeat is requested, independent of the current physical stick position.
- A successful map-route poll with raw X 16384 and Y 0 can store X 0.5 and Y 0. If the map-open byte is still nonzero at the Interface check, that check closes the Ring and skips arrow publication. The subsequent selection check sees it closed.
