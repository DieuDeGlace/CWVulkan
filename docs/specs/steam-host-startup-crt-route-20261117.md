# Steam host simulation worker startup and CRT random order

## Supported image and result

The address references are RVAs in the x64 Steam image with preferred base 0x140000000. The admitted unpacked image is cubeworld.original.exe.unpacked.exe, 5,757,952 bytes, SHA-256 7AF18CB28C8BF848F355287428C6390B2EA2A682CA466190F5EB9859C5D6F244. Its packed counterpart is cubeworld.original.exe, 5,939,072 bytes, SHA-256 A1EFBBD41EEB8DF08395C4D6511194D416CB70A14054B2A2000B9F5CDBCFA65B. The imports, address tables, callsites and branch conditions below come from this original executable and its static exports.

The inspected normal launch and first ordinary simulation tick contain zero reachable game-image calls to the imported rand or srand while the authority world and its work queues stay empty. There is no first game-side draw or seed to assign to that empty tick. This result requires a successful worker start, the ordinary tick admission gate, no packet or local request admitted during the tick, empty peer and staged event collections, no authority actors or selected loaded zones, and no pre-existing world projectile work. A host with no remote guest can already have local input or world work. Network, system and CRT calls have the bounds below.

The PE import table names api-ms-win-crt-utility-l1-1-0.dll for both rand and srand. Their image import slots are at RVAs 0x42CD28 and 0x42CD38, respectively. These slots identify the requested API-set imports. The loaded provider and CRT state at the worker entry are unobserved.

## Worker launch and tick admission

The outer session at 0x7EA80 embeds the host object at outer offset 0x6E8. The authority world starts at host offset 0x08. The world constructor 0x29A130 initializes an empty actor list at world offset 0x40, an empty actor index at 0x450, a null local actor pointer at 0x448, and a zero mode byte at 0x358. The host constructor 0xF17A0 initializes the peer trees and the inbound and event lists before launching its service worker. Emptiness at a later tick remains a condition on the live collections.

At 0x7F879 the creator calls the simulation launch helper 0x75D10. The allocation at 0x7D560 supplies a single eight-byte outer-session pointer. At 0x75DD0 the helper calls MSVCP140.dll _Thrd_start with the executable's common entry 0x3C7D0 and a launch record. The fixed dispatch slot at 0x437EC8 contains the trampoline at 0x87BB0, which enters 0x88EE0. The latter takes ownership of the payload, acquires the launch mutex, sets the ready byte, signals the condition variable and releases the mutex. The creator waits on that byte. The worker reaches 0x83E60 at 0x88F52 after successful synchronization. Launch and synchronization errors route to the C++ thread error handler. The common entry broadcasts at thread exit after the dispatch returns.

This game-side handoff carries an object pointer and synchronization data. No CRT state value is copied into the start record, and the inspected wrapper and worker prologues contain no call to rand or srand. On the creating thread, host construction at 0xF17A0 calls world initialization at 0x2B5F20, which stores terrain seed 123 at world offset 0x220 and calls srand at 0x2B5F9A before building the world's seed-derived data. That creator call is distinct from a seed on the simulation worker. The startup route supplies no observed game-side operation that reads back the creator's CRT state or transfers it into this worker.

The host service and generation worker launches through 0xF0150, the same common entry, dispatch slot 0x43FD18 and trampoline 0xF3070. Its wrapper 0xF3220 calls 0xF2340. It uses the host run byte at 0x550, scans authority actors for positions used in selecting work, and calls 0x2AE0C0 at 0xF2CBE for selected zone generation requests. The seed at 0x2AE13D is on that service path. The independent AI worker starts through 0x75E80, dispatch slot 0x437EE8, trampoline 0x87BC0 and wrapper 0x88F80. Its entry 0x83F20 calls 0x13830 with the AI object at outer offset 0x768 on a 40 ms target loop. Eligible actors can reach AI random decisions through 0x14E00 and 0xBAC0. These two entries run independently of 0x83E60. Their calls establish no game-side order of CRT advancement on the simulation worker.

The simulation entry 0x83E60 samples timeGetTime, then tests the byte at outer offset 0x2068. The constructor sets it to one. A clear byte sends execution to 0xF4FF0 for shutdown, which can send a disconnect message for an existing nonlocal peer. Each running iteration checks 0x3E2D0 at outer offset 0xD18. The checked 64-bit identity is at offset 0x70 of that object, or outer offset 0xD88. The ordinary host tick is admitted if that identity is invalid under 0x3BE00 or equals the local Steam identity stored at RVA 0x54DDC8 by 0x3AA10. A valid different identity bypasses the tick and sleeps 33 ms, keeping the previous time sample. The validator accepts universe values 1 through 4 and type values 1 through 10. Types 1, 3 and 7 require a nonzero account number, and types 1 and 7 additionally require instance at most four and instance zero, respectively.

The admitted iteration samples timeGetTime again and passes the 32-bit elapsed difference to 0xF5520 at 0x83EC6. It uses that tick's start time for the next elapsed calculation. After the call it sleeps for the remaining part of 32 ms if tick execution took less than 32 ms. The bypass and pacing calls contain no game-image seed or draw. A delayed admission can change the first elapsed argument and the number of simulation substeps.

## Work before the first world substep

1. At 0xF5520 the elapsed argument is capped at 1,000 ms on the signed comparison and the tick enters the host critical section at offset 0x5F8. The Steam receive pass precedes the world substeps. SteamInternal_ContextInit at 0xF559A receives the descriptor at 0x5314F0. Its game-image initializer 0x3BEA0 obtains and stores the SteamNetworking005 interface through Steam imports. The indirect availability check at 0xF55B0 uses channel 1. It has to return false to skip the receive loop. A true result allows an indirect read at 0xF5633, and a successful read reaches host message dispatch at 0xF5646 to 0xF4490. The availability check repeats at 0xF56A9. The external Steam bodies are outside the resolved game-image route, even when availability returns false.
2. A receive interval over 8 ms can enter an iostream diagnostic even with an empty receive. Its stream-buffer calls are indirect. The tick then takes the host queue lock at offset 0x5D0, copies and clears the local inbound queue at 0x620, releases that lock and dispatches each copied entry through 0xF4490. This is a second source of work independent of the Steam receive result. A dispatch can create an authority actor or queue an event before the first world substep.
3. The TLS epoch guard at 0xF585A can enter 0x392DC8 and 0x392D68 around a timeGetTime initialization of the timer at RVA 0x551730. The possible wait and notify calls in 0x392E8C and 0x392E30 use synchronization targets resolved by 0x392BF0 from kernel32.dll, or its event fallback. The initialized value here is a timer. The visible initialization contains no game-image rand or srand call.
4. The secondary peer tree at 0x578 can trigger an indirect send at 0xF59B1 for a peer absent from the table at 0x568 after more than 5,000 ms since its recorded time. The connected-peer pass at 0x568 can admit additional per-peer processing and sends via 0xF4F50. For the empty route both trees are empty. The local outbound dispatch installed by 0x7D140 can route a local-peer send through 0x8A360 to 0x3CB50, whose inspected target queues a client-side message.
5. The tick creates an event bundle and 0xF3FD0 drains the lists at host offsets 0x588, 0x5B8, 0x598 and 0x5A8 in that order. It enters the world lock at world offset 0x3C8 through 0x2ABB70, then calls 0x29D980 at 0xF68DD. The damage list from host offset 0x588 can reach 0x29DCF0 at 0x29DA45 before any 0x2DA6C0 substep. The target has to resolve and pass the hit gates. A path reaching death can call 0x2A6860 and, when enabled by the target's flags, 0x2A7CA0, both with random branches. The empty damage list skips this whole route. The empty inputs also leave no new world projectile entries.
6. The tick calls 0x2DA6C0 at 0xF6917 for each 16 ms slice while the remainder exceeds 16 ms, then always calls at 0xF692D with the remainder, including zero. The world lock stays held across this work. The first call's order is governed by the admitted data and by its elapsed slice. For the empty condition the count of slices does not introduce an unconditional CRT advance.

## World substep and the first conditional CRT sites

The first three calls of 0x2DA6C0 are 0x2E2E80, 0x2ADFE0 and 0x2E3510. The clock pass at 0x2E2E80 advances the world clock. A named fresh world initialized by 0x2B5F20 starts with day 1 and 36,000,000 ms in the day when no saved clock is restored. The day transition requires a clock value above 86,400,000 ms. A world with an empty name length at world offset 0x210 instead gets the fixed clock value 32,400,000 ms. Saved-state load through 0x2B98B0 and 0x148E90 can restore the day and clock. On a rollover in authority mode, 0x2E2E80 can call 0x2D2EB0 at 0x2E300D before zone work. Its indirect destruction call at 0x2D2FA5 requires a nonnull actor drawn from the list at world offset 0x40 whose actor byte at 0x60 is nonzero. That call is bypassed for an empty actor list even if the clock rolls over. 0x2ADFE0 rebuilds an actor subset from the same list.

The first resolved draw candidate within the world substep is 0x2E49DE in 0x2E3510. That pass builds its selected-zone collection using actors whose byte at 0x60 is zero and nonnull loaded zone entries looked up via world offset 0x460. For this pass it searches up to three zones in each coordinate direction around such an actor. A selected zone needs an entry in its effect range at zone offsets 0x30 and 0x38, a positive timer at record offset 0xC8 that reaches zero or below on the slice, and a zero world mode byte at 0x358 for this call. It draws for the expiration event. The subsequent zone effects at 0x2E5CF5, which can reach rand through 0x29EB60, and at 0x2E5D32 also require selected zone records and applicable actors. An empty authority actor list leaves the zone collection empty. Absent zone entries also prevent these calls, even if a qualifying actor exists.

The next authority-only group is enabled by the zero byte at world offset 0x358. Its first call at 0x2DA8DF goes to 0x2E17D0, which builds a loaded-zone set from eligible actors in the list at world offset 0x40. For each selected zone it calls 0x31C540 at 0x2E1D7C. That routine returns if the zone's remembered day at offset 0x4F8 matches the parent day. On a changed day it seeds at 0x31C72F using the day and zone coordinates. Its first draw at 0x31C77C additionally requires a nonempty position array at zone offsets 0x500 and 0x508. A later spawn path at 0x2E2686 can also draw. An empty selection bypasses the zone seed itself, regardless of world day. When the preceding zone-effect pass has no draw and a selected zone needs its day refresh, this seed can precede any of the remaining actor or projectile draws.

Within the same authority group, 0x2A56C0 can call a virtual actor destructor at 0x2A5959 only for a nonnull actor selected for removal. 0x2A45E0 then visits actors before its draw-bearing effects and hits. Its first direct draw at 0x2A4CCC requires a dead non-player actor, a zero value at actor offset 0x6C, creature type 0x90 and a successful terrain-change branch. Its other draw branches likewise require actor work. The removal and draw paths are bypassed with no actors.

The next call, 0x2E0DB0, can seed through 0x2B67B0 at the pet-change and spawn callsites 0x2E1067 and 0x2E12BD. That pass requires a nonempty world name and a qualifying actor whose byte at 0x60 is zero and whose pet record begins with 0x14 at offset 0x8B8. The helper at 0x2B67D1 seeds from the pet's 32-bit creature type at offset 0x64. Actor-free execution skips those sites. The later simulation routines 0x2BB8E0, 0x2C3710 and 0x2DE4C0 can draw only after entry into the actor loop. 0x2DBA40 is called even without actors, but its draw-bearing projectile loop requires a nonempty world list at offset 0x60.

After the substeps, the empty path through 0x2B68E0, 0x2E30B0, 0xF33B0, the event drains and the lock releases adds no resolved rand or srand call. The no-draw result covers the complete first ordinary game-image tick under the stated queue, actor and zone conditions. Relaxing the conditions can admit a seed without a draw, a draw without a seed on the inspected route, or a pre-substep damage draw. The first such call is data-dependent.

## Static evidence limits

The launch table dispatch and the clock guard synchronization targets are resolved to the extent described above. The unpacked PE TLS callback list is empty at RVA 0x42DBC8. This only describes that executable's static TLS callback table. External thread creation, loader notifications, CRT initialization and the effects of DLL calls, including the Steam interface and iostream dispatches, are outside this observation. Indirect actor destruction, message and compression callbacks on populated paths require their own target and state evidence. No dynamic binding, CRT default seed, previous draw count, or cross-thread CRT state relationship is established by this inspection. The original was never run or instrumented for this contract.
