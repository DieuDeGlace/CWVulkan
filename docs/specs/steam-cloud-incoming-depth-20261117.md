# Steam WORLD depth offset at cloud submission

## Supported image and scope

This contract uses the original 64-bit Steam Cube World executable. The installed cubeworld.exe and both packed copies in the original export have 5,939,072 bytes and SHA-256 a1efbbd41eeb8df08395c4d6511194d416cb70a14054b2a2000b9f5cdbcfa65b. The unpacked original underlying the export has 5,757,952 bytes and SHA-256 7af18cb28c8bf848f355287428c6390b2ea2a682ca466190f5eb9859c5d6f244, preferred image base 0x140000000, and PE timestamp 0x5d93ab0d. Addresses below are RVAs in that image. The scope starts with the in-world call at 0xad9d4 into 0xe2e00 and ends with its mode 10 cloud submissions. Offsets refer to bytes from their stated object or record base.

## Shared vertex state

Mode 10 selects the common world vertex shader and the cloud pixel shader through 0xc3dc0, the case at 0xc40c7, and 0xc5e50. The vertex shader bytecode at 0x4387b0 is loaded at 0xc6235. Its embedded reflection data names DepthOffset at vertex constant-buffer slot 8. The buffer is 16 bytes and contains a single 32-bit float at byte 0. The binding through 0xc68c0, specifically 0xc69ac, uses the same buffer handle that the depth setter updates. This is the same vertex shader and slot used by the opaque and faded model modes.

The setter at 0xc6a80 is reached through world virtual slot 0x90 in table 0x4385e8 and the receiver adjustment at 0xc59c0. Its receiver is the renderer subobject at world renderer offset 0x558. It compares the requested float against the cached float at subobject offset 0x3dc, also world renderer offset 0x934. An ordered equal comparison returns without a transfer, including equality of signed zeros. An unequal or unordered comparison records the supplied float and updates the buffer at subobject offset 0x430, also world renderer offset 0x988. The updated 16 bytes contain the supplied float followed by twelve zero bytes. The cache starts with a -1.0 sentinel at 0xc6721. In this frame family, 0xe39f4 requests +0.0 before drawing the world, with the zero sourced at 0xe35e4. When the cache is already zero, this request preserves the already resident zero.

The mode 10 draw uses the scalar resident in that buffer when the indexed submission is made. Mode selection binds the existing buffer. The model traversal can update it even when the draw immediately afterward produces no submission or no fragments. Each reached cloud submission observes the result of the final effective setter update in the preceding ordered traversal, or the resident zero established by the frame reset when no later unequal value is supplied.

## Traversal before mode 10

The frame clears both world model collections at renderer offsets 0x138 and 0x1d0 before filling them. Reset calls at 0xe30be and 0xe30ca reach 0xeef30, which empties both facing groups in each of the opaque and faded portions. These are resets of the collections. The independent shader scalar is reset at 0xe39f4.

1. After the scalar reset, the frame supplies other render state before collecting geometry and effects through 0xd3170 and 0xce5f0 at 0xe3bd1 and 0xe3bdd. The optional mode 8 background at 0xc5120 runs through the 0xe3ad4 hook. Its call at 0xc529b uses the Direct3D context's vertex-input binding slot, whose byte offset happens to be 0x90. The model and effect collectors put data in queues. The shader buffer receives the per-record offsets during the draw traversal.
2. Terrain at 0xe3c3e enters 0xe5070, initially in mode 0. Chunk records with no mesh groups and mesh records with the relevant missing index resource skip their affected geometry. The terrain submissions through 0xe52ae, 0xe53d8, 0xe5502, and 0xe567e require successful vertex and index resource binds. The branch that temporarily changes lighting restores the preceding lighting afterward. Terrain keeps the existing DepthOffset.
3. Opaque draw routine 0xe6e60 runs on the collection at renderer offset 0x138 at call site 0xe3c5c, then on the collection at 0x1d0 at 0xe3c71. Each traversal uses mode 0 for its first facing group and mode 1 for its second. Each reached descriptor has its own DepthOffset request immediately before the draw helper. A skipped group or descriptor contributes no request under the guards below.
4. The collection at 0x1d0 runs through the entire faded routine 0xe7980 at 0xe3c86, including color. The order within this call is depth mode 3 for the first facing, depth mode 4 for the second facing, color mode 6 for the first facing, then color mode 7 for the second facing. Every nonempty visit requests its own stored offset in both sweeps.
5. At 0xe3c97, 0xe6270 draws queued effects through 0xdc610, 0xdad40, 0xde7a0, 0xdba60 and 0xde3d0. At 0xe3ca7 the conditional 0xe6840 pass can draw additional models in mode 2 following its range and frustum check at 0xe6957 and resource checks through 0x16ec60. These draws use their own transforms and other constants with the offset left by the earlier model traversals. The lighting call at 0xe3cc8 updates the light buffer.
6. The water routine 0xe85e0 at 0xe3cd2 runs its mode 5 depth sweep followed by mode 9 color. Both loops require a populated mesh group and the water index resource at mesh offset 0x18. The vertex resource at mesh offset 0x08 and the water index resource must both bind successfully for the indexed submits at 0xe87ef and 0xe89b9. Its final state change at 0xe89df updates the separate scalar reached through world virtual slot 0x70. Both water sweeps retain the current DepthOffset.
7. The separate effect draw at 0xe3ce6 resolves to 0xc43d0. It uses another vertex shader through 0xc5ec0 and sets the other pass's constants. Its vertex-input bind at 0xc4378, via 0xc4250, is a Direct3D context method. The explicit mode 3 selection at 0xe3cf5 and the projection update at 0xe3d06 prepare the next pass. The projection is addressed at world renderer offset 0x3dc, a different base from the depth cache. The next reached model retains the incoming scalar until its own request.
8. The entire faded routine 0xe7980 now runs on the collection at 0x138 at 0xe3d1a. It makes the same depth 3, depth 4, color 6 and color 7 sweep in that order. This is the last possible pre-cloud writer in the traced world frame. If this collection contains any faded records, its final nonempty color group supplies the final request, even if its last record fails submission. With both faded groups empty in this collection, the last reached writer from the earlier stages supplies the value.

The two ordinary opaque calls and the two ordinary faded calls pass draw flags 2. Their bit-1 path selects per-position point lights for opaque and faded color work. A missing light lookup selects empty light data and still reaches the offset request. The bit-0 per-instance projection adjustment belongs to other caller paths. Both model routines return directly after their traversal, preserving the final offset request. Mode changes, light restoration, per-record light selection, and viewport or matrix updates have separate state ownership.

## Descriptors, guards, and reached producers

Each collection has opaque model trees at offsets 0x00 and 0x10. The second tree's count is at 0x18. Model tree entries keep the model pointer at node offset 0x20 and the instance-list sentinel pointer at 0x28. The traversal follows increasing model pointer keys and linked instance-list order within a key. The opaque instance node has a two-pointer list header followed by its descriptor payload. The four-byte DepthOffset field is at 0x70 from the node start, or 0x60 from the payload start. Setters are 0xe7381 for mode 0 and 0xe788c for mode 1. Their loads are at 0xe737c and 0xe7887. The transform begins at node offset 0x10.

Opaque model eligibility is checked before the instance loop. Calls at 0xe6f40 and 0xe7470 enter 0x16eba0, which requires both model resource pointers at 0x70 and 0x78 and success from both resource bind methods, in that order. Failure skips every instance of that model in that group. Empty trees and empty instance lists make no per-instance depth request. Mode 1 additionally requires the second tree count to be nonzero at 0xe7429. Once a record is reached, the offset request precedes the fast draw helper at 0x16ecc0. That helper checks the two resource pointers again, then dispatches through the model's draw gateway.

The corresponding faded arrays have begin and end pointer pairs at collection offsets 0x20 and 0x28 for the first facing, and 0x38 and 0x40 for the second. The arrays are visited in forward record order with a 0x78-byte stride. A record holds its model pointer at 0x00, transform at 0x08 and its four-byte DepthOffset at 0x68. Both depth requests load that field directly, at 0xe7b47 and 0xe7ca7, and call the setter at 0xe7b4c and 0xe7cac. The color requests use the same field, at 0xe812c and 0xe856a, with setters at 0xe8132 and 0xe8570. Their addressing base is record offset 0x14, so the displacement in those two loads is 0x54. An empty range skips that facing in both sweeps. Every visited faded record requests its DepthOffset before the checked draw helper at 0x16ec60, including records whose two resource pointers or binds subsequently fail. The helper requires both pointers, then first bind success, then second bind success. Its draw gateway receives the model's two 32-bit draw arguments at offsets 0x80 and 0x84, through the interface at model offset 0x60. With both binds accepted, this helper forwards the draw arguments directly, including a zero count.

Facing is selected per group before drawing, and front-face rejection happens in the rasterizer after the request and resource checks. The original rasterizer descriptors at 0xc326e and 0xc3290 start from data at 0x438710, select front-face culling and differ in front winding. Modes 0, 3, 6 and 10 use the state at world renderer offset 0x9d0 with clockwise front winding in render-target coordinates. Modes 1, 4 and 7 use the state at 0x9d8 with counterclockwise front winding in render-target coordinates. The surviving triangles have the opposite winding in each case. A submitted record that is entirely face-culled still contributes its request. From the offset request, the model loop proceeds directly to the resource helper. The depth modes 3 and 4 use a zero render-target write mask, while modes 6 and 7 use the blended color state. The state creations are in 0xc3150 and the selections in 0xc3dc0.

The producers at 0xee2f0 and 0xee990 receive the same offset for either storage format. A finite opacity at least 1 goes to the opaque tree and a value strictly between 0 and 1 goes to the faded array. Nonpositive opacity never appends. The former routine populates the first facing and the latter the second facing. The world collector at 0xd3170 can send map object descriptors to either collection at 0xd3f09, using map object flag 0x08 to select the 0x1d0 collection and supplying a zero descriptor offset. The first and second facing groups are independent of this selection between collections.

The same world collector calls the actor model producer at 0xd67b2 with the 0x138 collection and base offset +0.0. That path assembles the instance opacity from distance and actor state before the producer's opaque or faded selection. It reaches the alternate-facing queue routine at 0x2a8f9 and 0x2af2d for its mirrored components when their branches admit them. These are ordinary world paths into the second facing group of collection 0x138. Their nearby component mask tests at 0x2a738 and 0x2ad89 can skip those components before queuing. The world entry's actor producer call supplies a zero component mask at 0xd6770. The collector's traced route into collection 0x1d0 uses the first-facing producer. Both traversals still have the generic second-facing branches described above.

One explicit nonzero producer lies in 0x17ab0. A component present at actor draw-object offset 0xe0 passes the guard at 0x27ead. The first-facing submission at 0x2813a then queues the base offset plus the single-precision constant at 0x4ac954, bits 0x38d1b717, nominally +0.0001. The base for this world call is zero, reloaded for the producer at 0x2625a. The component can carry the nonzero value into either the opaque node or the faded record according to the opacity presented to 0xee2f0. The usual zero-offset requests from other descriptors can follow and supersede it. Exact traversal order within an opaque group depends on its model keys and instance order, and within a faded group on append order.

## Camera branches and cloud draw boundary

With render flags bit 0x80 clear at 0xe3d31, the frame calls 0xe5730 at 0xe3d60. A set bit skips that consumer as well as the earlier optional model pass at 0xe3ca7 and the optional background hooks beginning at 0xe3ad4. This flag can also skip map-object collection in 0xd3170. The main opaque, faded, water and effect calls still precede the branch.

The type-2 camera cell branch comes from the sampled world cell at 0xe3389 and the byte at returned cell offset 0x04. It changes the frame tint and selects the direction (0, 0, -1) for the camera-dependent upload at 0xe3aac. It also suppresses the optional follow-up hook at 0xe3aed. When render bit 0x80 is clear, type 2 still reaches mode 10 through the same setter sequence and descriptor gates. Camera values can change which records are collected via range and frustum gates such as 0xe0680 and 0xe08c0.

Cloud mode is selected at 0xe57e0. Cloud setup writes the separate White and Glow constants, clears point-light data, and sets material and camera matrices before iterating. The corresponding zero requests at 0xe57f1 and 0xe5801 target White and Glow, respectively. The cloud candidate route can reject a cell by its procedural availability test, reject an instance through the range and frustum test at 0xe5aca, or skip on low opacity. For accepted cloud candidates, squared distance at least 32,400 reaches the direct draw at 0xe6098. The near branch computes opacity from distance, with a threshold of 0.01 for submission and a two-sweep deferred list for qualifying opacity below 1. It can also converge on the direct draw. The later two submission calls at 0xe6181 and 0xe61bf iterate that local deferred list. An empty list reaches neither of those draws. Every cloud submission uses the checked resource helper at 0x16ec60. The per-cloud work adjusts transform and other shader state while all three submission sites keep the incoming slot 8 value.

The reset at 0xe4e3a belongs to later screen-space model work in the same entry, after the cloud call. The independent reset paths at 0xdb801, 0xde1c6, 0xde22e, 0xdf12e and 0xdf61d occur in other callers outside this world-to-cloud interval.

## Numeric examples at reached branches

- When the frame requests 0.0 and all eligible model writes are 0.0 or the groups are empty, a submitted cloud reads 0.0. If the cache entered at -1.0, the frame request uploads once. Repeated zero requests compare equal.
- In an opaque traversal where the last qualifying instance has the +0.0001 component and the following groups are empty, the requests finish at +0.0001 and a submitted cloud reads +0.0001. An opaque model pre-bind rejection on that instance removes its request. If the earlier request was 0.0 and the following groups are empty, the resulting cloud value is 0.0.
- With an admitted +0.0001 faded component as the final record of the final nonempty color group, a resource rejection inside its checked helper still leaves +0.0001 for the cloud. If a later reached faded record requests 0.0, its request supplies 0.0 even when its resource helper rejects it. The lighting and water work carries the last request through to the next model traversal.

The examples specify executable branch inputs and record order. The inventory and frequency of nonzero final records across stock saves and the frequency of particular caller frame flags in live play remain unresolved. The trace ends at indexed submission. GPU or driver failure and fragment visibility are outside that boundary.
