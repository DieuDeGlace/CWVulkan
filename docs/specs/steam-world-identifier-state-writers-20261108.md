The two World sets contain 64-bit identifier values, not actor pointers. Their counts are 64-bit fields at +0x28 and +0x38. Insertion helper 0x37A40 compares the full keys in signed 64-bit order. The inspected runtime invocations use its unique-key mode: an existing equal identifier returns the existing entry without adding another membership. The new-node path through 0x373B0 and 0x37280 copies the identifier value into node+0x20. These facts distinguish the retained identifier from the lifetime of an actor object whose +0x8 field supplied it. No positive-ID-only or zero-ID exclusion is added by these selected call sites.

The directly proved local death-set producer is 0x2A45E0. Its ordinary World-step caller 0x2DA6C0 admits this routine only when byte World+0x358 is zero. Within that admitted group, the step calls 0x2E17D0, then live-resident retention/removal 0x2A56C0, then 0x2A45E0 at 0x2DA8F3. The latter iterates the live actor-pointer list at World+0x40. For an actor whose float +0x180 is ordered at most zero and whose category byte +0x60 is nonzero, it inserts that actor's own 64-bit identifier from actor+0x8 into World+0x20 at 0x2A4749. The insertion occurs before the following death-timer, special-case and eventual actor-removal work. The returned new/existing membership indication does not gate the rest of this dead-actor branch.

Consequently, an actor remaining in the dead-actor processing list can encounter this insertion again; the set deduplicates its identifier. This does not append one retained membership per visit or per credited attacker. At the reached later destruction tail, 0x2A45E0 removes the actor from the live list, erases its identifier from the distinct actor lookup map at World+0x450 through 0x2AC530 at 0x2A55F2, and invokes the actor's destruction hook at 0x2A5602. That reached removal tail does not erase the corresponding membership from World+0x20. This is a bounded retention fact about that tail, not proof that no other route can erase the identifier.

The directly proved reward-marker producer is an interaction branch of 0x2C3710. The ordinary step calls this routine at 0x2DB6BA only for an iterated actor whose float +0x180 is ordered positive. The routine itself returns immediately when World+0x358 is nonzero, with its test at 0x2C379B. It processes the acting actor's action-node list at +0xAB8. In the selected branch, the iterated node's byte +0xD4 is 3, and its 64-bit target identifier at node+0xC0 is resolved through 0xE720. A missing target produces no marker insertion.

Earlier target-type/flag and subtype branches must be distinguished from the reward-marker branch. Target type +0x64 equal to 0xF5, or target flag +0x80 containing bit 0x200000, takes an earlier branch. The earlier target subtype byte +0x14C equal to 0xA1 also intercepts the relevant non-0xFF state values; a target of that subtype with state 0xFF fails the later zero-state test. On the path that reaches the marker test at 0x2C3900, target word +0x128 must contain bit 0x100, and target byte +0x19C must be zero.

The order is observable: target byte +0x19C is first set to 0xFF at 0x2C391F, and bit 0x100 is cleared from target word +0x128 at 0x2C392B.
