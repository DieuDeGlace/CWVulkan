# Steam guest pickup of a dropped item

**FINAL / STABLE / HELD**

## Image and scope

This contract covers a guest using the normal pickup interaction on an item already present in a loaded world zone. The installed Steam cubeworld.exe and the reference cubeworld.original.exe have identical SHA-256 A1EFBBD41EEB8DF08395C4D6511194D416CB70A14054B2A2000B9F5CDBCFA65B. The original decompiler export identifies cubeworld.original.exe.unpacked.exe as its input, SHA-256 7AF18CB28C8BF848F355287428C6390B2EA2A682CA466190F5EB9859C5D6F244. All RVAs refer to that unpacked native image. The installed and reference packaged images match byte for byte by hash. Sampled instruction bytes in the packaged image differ from the unpacked instruction bytes at the same RVAs.

## Request and authority

The guest looks up the selected zone coordinate pair and signed slot index. Each drop occupies 0xE0 bytes. A nonzero reservation ID on the drop must match the local player's 64-bit identity field at +0x968 for the normal input to proceed. An unavailable reservation displays “Reserved”. The interaction also checks carrying limits and bag capacity. A successful input queues action 7 with the selected item description, zone coordinates and slot index. The guest makes no inventory or currency award at input. See lookup RVA 0x2B8FD0, reservation comparison 0x8E1B5, capacity checks 0x8E4EA and 0x8E58F, and action enqueue 0x8E775.

The guest sends the queued action in message 9. The host looks up the incoming peer, resolves its assigned creature ID and places the action on that creature's queue. This identifies the player who can receive the award independently of the item description. See RVAs 0x3F4F0, 0x3FD92, 0xF4490, 0xF4A3D, 0xF4A49 and 0xF4A70.

The host's world tick processes that creature's action. It requires a present zone, an index inside the current drop array, three-dimensional distance of at most four blocks between player and drop, and an item matching the current slot under the native item comparison. The squared threshold is 16 and one block is 65,536 position units. A successful decision queues positional sound 0x30 at the player, or sound 0x2D for item category 0x0B, subtype 0x25. It then queues a pickup notice with the acting creature's 64-bit ID and the current world drop's item, unsigned 16-bit count, three signed 64-bit position components and flags. The host takes the count and position from the drop. This branch writes neither participant's inventory, gold or experience. See RVAs 0x2DB6BA, 0x2C3C57 through 0x2C3D36, 0x4DF60, 0x2C3D4E through 0x2C3DC4 and 0x2C3E48 through 0x2C3EF2.

## Notice and player-local award

The host copies the pickup list into each registered peer's outgoing world update. The list copy has no per-pickup player or distance filter. Message 7 carries it in the ninth counted section, counting the first section as one. The section has a 32-bit count and 0xD0-byte records. Record offsets are 0x00 for the player ID, 0x08 for the item, 0xA8 for the stack count, 0xB0, 0xB8 and 0xC0 for position, and 0xC8 for the 32-bit flags derived from the drop's signed flag byte. See host RVAs 0xF5520, 0xF69B4 and 0xF370D, and reader/copy RVAs 0x3F078, 0x39AF0, 0x3AC10, 0x3F220 and 0xA87C2.

A receiver resolves the notice's creature ID. An unresolved ID skips the entire notice. The receiver resolves the effective item for that creature. The normal item is copied unchanged and category 0x1E takes a special conversion path. Only a notice resolving to the receiver's own local player reaches the award. Thus a guest earns their own pickup on receipt, while the host and observing peers can show who received an item. For ordinary items the chat formatter displays “You receive” to the recipient and the character's name followed by “receives” to an observer who knows that character. Category 0x0C skips that chat formatter's output. A separate local popup exists for certain special item categories. See RVAs 0xAA620 through 0xAA657, 0x10A720, 0xAA7EA through 0xAA8FB, 0xAAD94 through 0xAADA9 and 0x9D6F0.

For a normal bag item, the receiver passes the effective item and the announced stack count to its local player's inventory at +0x9F0 with automatic bag selection. A gold coin (category 0x0C, material 0x0B) adds the stack count to local gold at +0xAAC. A platinum coin (category 0x0C, material 0x0D) adds the stack count to the local player's platinum account for their **current** region coordinate pair at +0x150/+0x154. The platinum key comes from the recipient rather than the drop position. Effective category 0x1F instead adds its computed gold value once. Category 0x0E reaches a separate counter at player +0xAB0. Its gameplay name is unresolved here. An ordinary inventory-item award has no separate XP increment in these routines. See RVAs 0xAA721 through 0xAA7C5, 0x4E810, 0x109070, 0x60EC0 and 0x16B8A0. The gold and platinum gain indicators use those balances at 0xAD251 and 0xAD445.

## Repeated interaction and limits

For a regular drop with flag mask 0x02 clear, the host marks the containing zone for update and overwrites that slot with an empty item immediately after queuing the notice. A second normal request for the old nonempty item fails the slot comparison. For a drop with mask 0x02 set, the host keeps the world slot. On its first matching notice, the recipient records the drop's integer block-coordinate triple in its own collected-position set. A later matching notice at an already recorded position skips both the award and that recipient's chat handling. This set belongs to the local character. Other characters can collect the same flagged world drop independently. See RVAs 0x2C3EF8 through 0x2C3FB6, 0x837E0, 0xAA65D through 0xAA721 and 0x93870.

The regular-drop award loop has no per-notice transaction ID check. The ordinary duplicate suppression established here is consumption of the host world slot and the creature action queue. Only mask 0x02 takes the recorded-position check. This evidence does not establish transport-level exactly-once delivery, save timing, reconnect behavior, the lifetime of reservations, or the rule for reusing an emptied zone slot. Combat rewards, quest and chest awards, and trading are outside the scope of this contract.
