# Steam pickup chat and ground landing sounds

FINAL / STABLE / HELD · Original Steam Windows x64 · 2026-11-14

The installed Steam executable and the archived original each contain 5,939,072 bytes and have SHA-256 `a1efbbd41eeb8df08395c4d6511194d416cb70a14054b2a2000b9f5cdbcfa65b`. RVAs refer to the 5,757,952-byte unpacked image, SHA-256 `7af18cb28c8bf848f355287428c6390b2ea2a682ca466190f5eb9859c5d6f244`, with preferred image base `0x140000000`. English spelling comes from the bundled `dict_en.xml`. The evidence bounds the Game pickup-receipt lane, its chat formatter, and the ordinary ground landing sound through playback. In the offsets below, G is Game, W is the World pointed to by G + `0x08`, and C is that World’s local creature pointer at W + `0x448`. Offsets on list entries include the list links unless stated otherwise.

## Receipt admission and order

- During Game update `0xA5A50`, staged sounds at G + `0x1980` and staged pickup receipts at G + `0x19F0` are appended to their World lists at W + `0xA0` and W + `0x110`. Each retains its own list order. Game visits sounds before pickup receipts. The append sites are `0xA86DB` and `0xA87C2`, the sound playback call is `0xAA58F`, and pickup traversal begins at `0xAA608`.
- A receipt’s recipient ID is 64 bits at entry + `0x10`. Its item begins at + `0x18`. Quantity is unsigned 16-bit at + `0xB8` and is zero-extended to 32 bits for chat. Position is three signed 64-bit fixed-point components at + `0xC0`, `0xC8`, and `0xD0`. The low byte of the 32-bit flags at + `0xD8` carries the local position-deduplication bit `0x02`.
- Game resolves the recipient in the current World first. An unresolved ID skips the entire receipt. For a resolved actor, Game resolves the item using that actor before checking whether the actor is C. Ordinary coins and mana cubes pass through the item resolver unchanged. The generated-reward category `0x1E` can instead resolve to another item using its seed and the recipient’s class. Chat uses the resolved item. Evidence is `0xAA628`, `0xAA647`, and `0x10A720`.
- For C only, flag `0x02` checks the saved set at the local player-data pointer’s + `0x88`, with that pointer at C + `0x1528`. The key is three signed 32-bit block coordinates, each floored from the signed position component divided by 65,536. A match skips the whole receipt, including chat. A new flagged position is entered before the grant. Unflagged local receipts proceed directly to the grant. Other resolved actors skip this local position check and grant, then proceed to chat. Evidence is `0xAA650–0xAA721`, with the floor conversion at `0x93870`.
- For accepted local records, the inventory or currency grant and inventory UI refresh precede chat. Normal coin uses category `0x0C` with material byte `0x0B` at item + `0x1C`, adding receipt quantity to the 32-bit currency counter at C + `0xAAC`. The `0x0D` material variant of category `0x0C` adds receipt quantity to the 32-bit regional platinum total for the current region, using the player-data table at + `0xF8`. Category `0x0E` adds receipt quantity to the 32-bit mana-cube counter at C + `0xAB0`. The ordinary inventory grant at `0x4E810` skips quantity zero and category zero. These inventory rules are independent of the chat admission below. See `0xAA721–0xAA7E5`.
- The original category `0x1E` or a resolved category `0x17`, `0x18`, or `0x1D` can also take the local reward presentation before chat. That path includes a CRT draw at `0xAAC5B` and a success-music timer write at `0xAAD54`. Ordinary coin and mana-cube receipts bypass that presentation. The later local crafting-panel refresh can run before chat at `0xAAD8F` when the panel check admits it. With the inventory precondition met, the refresh at `0xB2180` seeds the CRT from the local region and may reseed and draw for eligible crafting tabs. This panel-dependent activity is separate from composing chat. At `0xAADA9` Game supplies the resolved item, the widened quantity, and the actual resolved recipient, then advances to the next receipt. The host copies the pickup-receipt lane to each connection at `0xF33B0` and `0xEFA40`. The receiving update imports it into G + `0x19F0` at `0x3E450`. The recipient lookup in Game therefore admits any resolved actor, including another player.

## Exact text and colors

The formatter `0x9D6F0` returns immediately for resolved category byte `0x0C` at `0x9D733–0x9D739`. Ordinary coins and regional platinum produce zero chat segments for every quantity and recipient. The later coin quantity/name branch at `0x9D9C5–0x9DB7E` lies behind that first return and is unreachable for the stable item passed by this caller. The category `0x1F` Bag of Gold belongs to the ordinary text path if admitted, including when the local grant converts its value to gold.

Every admitted non-coin record appends the following three segments, in order, to the chat widget at G + `0x398`.

| Segment | Exact contents | RGB bytes |
| --- | --- | --- |
| Recipient | Local C gets `You receive ` with one space after the verb. Another actor gets its current name followed by ` receives ` with one space on either side of the verb. | `127, 255, 255` except local resolved category `0x16`, which uses `255, 204, 76`. |
| Item | Optional count and separator, then the native item display name, then any equipment marks described below. | Resolved item color from `0x10A600`, using the viewing creature’s region where relevant. |
| End | One period followed by one U+000A LINE FEED. | `127, 255, 255`. |

- The local/other test is pointer equality with C. The other actor’s name is read from its NUL-terminated byte field at actor + `0x958`. Each signed byte is widened to a 16-bit code unit at `0x349C30` and `0x31B30`. ASCII casing and spelling are preserved, and an empty name leaves the literal leading space before `receives`. This conversion has no UTF-8 decoding step. The prefix literals are at `0x437B68` and `0x437B88`.
- The optional count is the signed 32-bit formatter argument rendered as decimal when it is positive and the resolved category byte is one of `0x01`, `0x0A`, `0x0B`, `0x0D`, `0x16`, or `0x1C`. The positive value one is rendered too. The count is followed by the exact separator ` X `, containing a capital X and two spaces. At quantity zero or outside these categories the segment begins with the item name. The formatter’s category check and count condition do not make quantity zero or category zero an early-exit condition. The category mask is `0x10402C02` and the separator literal is at `0x437BA0`.
- The display name comes from `0x1628B0` using the resolved item and active dictionary at G + `0x50`. The chat layer preserves that name’s spelling and casing, adds no article, and passes no quantity or actor name into it. The name lookup can use item-specific composition, such as `Formula: ` followed by the represented item’s display name, `Glyph of ` followed by the associated name, or `Pet: ` followed by its creature name. It also normalizes certain class-specific `0x16` item subtypes for the name lookup at `0x1092B0`. The chat count, prefix, and body tint use the resolved item’s own category.
- Equipment marks apply to resolved categories `0x03` through `0x09` and `0x1A`. If the unsigned 32-bit seed at item + `0x08` is divisible by ten times one plus the unsigned quality byte at item + `0x14`, append `+` immediately after the name. If the 32-bit Game setting at G + `0x1BC8` is nonzero, append one space, then one more U+00B1 PLUS-MINUS SIGN than the region-adjusted quality index, with no spaces between signs. At an adjusted index of −1, that option appends the space alone. The viewer’s region has two signed 32-bit coordinates at C + `0x150` and C + `0x154`. The item’s region is at item + `0x0C` and + `0x10`. Region adjustment keeps the quality in the same region. Equipment meeting the divisibility test also keeps it when both coordinate differences have magnitude at most one. Other regions give −1. The adjustment is at `0x109720`.

The body color uses the same viewing region for both local and other recipients. Category `0x17` or `0x18` has fixed RGB `255, 153, 63`. Category `0x15` uses `178, 255, 63`, category zero uses white, and category `0x0D` uses `127, 25, 255`. Category `0x16` and category `0x01` with 32-bit subtype `0x0D` use `127, 255, 255`. Of the remaining categories, `0x02–0x09`, `0x0F`, `0x1A`, and `0x1E` use the region-adjusted index and the others use the raw quality byte. The palette at `0x64680` clamps the index to −1 through 4.

| Index | RGB bytes |
| --- | --- |
| −1 | `204, 204, 204` |
| 0 | `255, 255, 255` |
| 1 | `0, 255, 0` |
| 2 | `76, 114, 255` |
| 3 | `140, 51, 255` |
| 4 | `255, 255, 0` |

Fixed prefix colors are at `0x4380C0` and `0x4381D0`. The conversion at `0x26BF10` multiplies each of the first three binary32 components by binary32 255, truncates toward zero, and stores the resulting RGB bytes on the styled runs. The widget at `0x26B670` treats spaces and line controls as separate layout tokens and can wrap the logical line. The explicit final period and newline are both supplied by the cyan segment from `0x42FF3C`.

For an ordinary mana cube, the default record here is category `0x0E`, 32-bit subtype zero, and zero material and quality bytes. The registration at `0x155C0F–0x155C33` selects the `ManaCube` dictionary entry. Its default English noun at `dict_en.xml` lines 1602–1604 is `Mana Cube`. The separate plural is tagged in the dictionary. This receipt calls the default form through `0x16AF30` and `0x16BE20`. Category `0x0E` is outside the count set and the equipment mark set. The local text is exactly `You receive Mana Cube.` followed by LF, even when the received quantity exceeds one. An actor named `Ada` gives `Ada receives Mana Cube.` followed by LF. The words `Mana Cube` are white. Prefix and period are cyan.

The direct formatter has no clock gate, timer write, CRT seed, or CRT draw. The ordinary mana-cube dictionary expansion uses the fixed noun, and the coin path exits before name lookup. Other actor identity affects the prefix and can affect generated reward resolution. Current viewing-region data and the equipment-display setting can affect item tint or marks. Each admitted receipt appends its own line during that visit, including consecutive receipts for the same name and item.

## Ground landing sound

The World tick `0x2DA6C0` calls the ground pass `0x2E3510` at `0x2DA73C` before the per-creature interaction phase at `0x2DB6BA`. For an ordinary drop visit, a positive signed 32-bit delay at ground item + `0xCC` is decremented first by the current step, with binary32 subtraction, integer truncation toward zero, and a lower bound of zero. Independently, a strictly positive binary32 landing timer at ground item + `0xC8` is decremented by that step. When the new value reaches or crosses zero, the field is set to positive zero and landing sound eligibility is evaluated at that visit. Each positive-to-zero crossing admits one landing test. The ordinary spawn path at `0x2A5B70` uses one CRT draw at `0x2A5CB3` to set an initial landing timer from 500 through 799 by taking the remainder modulo 300 and adding 500. The sound draw is separate from that initial timer draw.

- The normal landing chime requires the **World’s byte at + `0x358` to be zero** on the landing transition. That test admits the authoritative host World and skips the joined Game World’s copy. The World constructor `0x29A130` initializes the byte to zero. The Game owns a separate in-process host at G + `0x6E8`, whose embedded World is at host + `0x08` via `0xF17A0`. Connection setup `0x3D820` sets the *Game World’s* byte to one after either the in-process connection or Steam transport branch. Disconnect handling at `0x911E0` resets it on the relevant paths. World role determines ordinary emission even when host and participant share a process.
- On a qualifying crossing, the sound position is the ground item’s three signed 64-bit coordinates at + `0xA0`, `0xA8`, and `0xB0`. Sound code is `0x3D` (`drop-coin.wav`) for category `0x0C` and `0x3E` (`drop-item.wav`) for every other category, including `0x0E`. The ordinary gate uses neither the local creature nor the item’s reserved owner, the item’s quantity, the per-item flags, or a picker. The sound carries a 64-bit owner/exclusion value of zero. The binary32 gain is 1.0, and the binary32 playback rate is 1.0 plus a single CRT draw multiplied by 0.1 and divided by 32,767 in that order. The draw is at `0x2E49DE` and the sound is appended to the emitting World’s + `0xA0` list at `0x2E4A25`. From the sound payload start, XYZ occupy + `0x00`, + `0x08`, + `0x10`, the 32-bit sound code is at + `0x18`, rate at + `0x1C`, gain at + `0x20`, and owner/exclusion at + `0x28`. The sound-to-asset lookup is at `0xA3A40`.
- The same crossing has an extra equipment chime at `0x2E4AB6`. It checks that the World has a local creature, the category is `0x03–0x09` or `0x1A`, and the 64-bit ground field at + `0xD8` equals the 64-bit local creature field at + `0x968`. It can run under either World flag value and follows the ordinary chime when both qualify. It uses `0x5D` (`craft-proc.wav`) at the ground position with rate and gain 1.0, owner/exclusion zero, and no CRT draw. Coin and mana-cube categories do not qualify for this extra chime.

Host update `0xF5520` distributes the World’s events after its World ticks. The sound branch at `0xF33B0` checks each connection’s hosted actor. It includes the sound when the actor is within 256 blocks in three dimensions, inclusive, and the sound’s owner/exclusion ID differs from the connection’s actor ID. The range check at `0xF3E20` converts coordinate differences by 1/65,536 and uses a squared-distance comparison. The zero owner/exclusion on ordinary landing therefore permits delivery to eligible players without singling out a picker or an item owner. The receiving update at `0x3E450` routes the sound into G + `0x1980`. Game plays it from the World sound list through `0xAA58F` and `0xA0420` using its transmitted position, gain, and rate. Playback has a separate 64-block inclusive spatial cutoff around G’s current listening position at + `0x1DC0`, + `0x1DC8`, and + `0x1DD0`, a distance-dependent gain and camera-relative pan, and the Game’s sound-volume setting. Playback of these codes uses no second CRT draw.

An accepted ordinary ground pickup separately appends `0x30` (`pickup.wav`) at the picker’s current position with exclusion zero and its own CRT rate draw, then append the receipt. These are `0x2C3D4E` and `0x2C3DC4` in `0x2C3710). This also applies to ordinary coin and mana-cube pickups. The ground landing chime originates during the landing timer visit and can happen without a pickup. The Game’s sound-list visits precede receipt chat when both are present in one update. This ordering does not fix when separate host deliveries or audible playback reach a particular player.

## Evidence limits

This is a static contract for the identified Steam image. It fixes the authored English literals and ordinary English mana-cube expansion. Other dictionary translations, arbitrary generated item names, separate chat-formatter callers, wall-clock delivery latency, and device playback timing are outside this trace. The rare reward branch and panel refresh are included only where their ordering or CRT activity borders the ordinary receipt path.
