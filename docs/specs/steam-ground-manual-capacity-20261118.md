# Steam ground-item targeting, capacity and manual input

**FINAL / STABLE / HELD**

## Scope

This is the stock offline code path for an eligible ground item, from local target selection through a queued pickup request. RVAs refer to the original unpacked Steam image, SHA-256 7AF18CB28C8BF848F355287428C6390B2EA2A682CA466190F5EB9859C5D6F244. The packaged reference and installed executable both have SHA-256 A1EFBBD41EEB8DF08395C4D6511194D416CB70A14054B2A2000B9F5CDBCFA65B. Input timing below is expressed in eligible game updates. No live session was observed.

## Candidate and route

1. The game update resets the selected drop to an invalid zone before scanning. Its call to the interaction pass requires a nonzero world field at +0x210, a local-player action other than 0x9C or 0x9D, and inactive UI states for the three objects at game +0x118, +0x130 and +0x170. The pass examines loaded zones intersecting the player's horizontal position plus or minus eight blocks. Scan order is increasing zone X, then zone Y, then slot index. One zone spans 64 blocks per horizontal axis. RVAs 0xA5A50, 0xA9B2C, 0x9AF00, 0x8AE50 and 0x16E50.
2. A slot must have a nonzero item category and a nonzero 32-bit value at drop +0xD4. The world eligibility routine allows the item if there is no local player, but the normal selection pass uses a player. With a player, a nonzero reservation at drop +0xD8 must equal the player's 64-bit identity at +0x968. Category 17 hexadecimal is excluded when at least one equal artifact is already held across inventory tabs. Category 1E is excluded when personal data contains the drop's horizontal 16-block cell. Category 18 subtype 4 is always excluded. Other category 18 subtypes are excluded when a matching canonical special item in the player's current region is already held. RVAs 0x8D4DE, 0x2B8140, 0x5E780, 0x5E890 and 0x137E0.
3. The three-dimensional player-to-drop distance must be at most four blocks on both routes. The test uses squared distance at most 16 after converting fixed-point deltas to single-precision block units. Unflagged categories 0C and 0E take the automatic route. An automatic candidate with a nonzero time field at drop +0xC8 is skipped on that pass. Other candidates, including drops with mask 0x02 set, enter manual targeting. An additional manual squared-distance test of 100 lies inside the preceding test of 16 and cannot extend pickup reach. RVAs 0x8D57C–0x8D5AF and 0x8D7C9.
4. For manual selection, stock computes one score from player distance and another from camera distance. Failing the carrying-limit test adds 16 to each squared-distance score. It can therefore still show the player a full item. A strictly better player score becomes the proximity fallback. A strictly better camera candidate also needs line of sight, an available item model and projected model bounds spanning both sides of screen-center X and Y using positive-depth corners. A successful aim candidate sets the selected zone and slot and clears competing target state. The fallback supplies a ground slot only if one is still unset. Equal scores do not displace an earlier candidate. An already-handled world interaction or the alternate item-selection UI can consume the use action before the manual ground branch. RVAs 0x8D87A–0x8D8FC, 0x2B5D90, 0x173B10, 0x8AE50 and 0x98180.

## Automatic requests

A qualifying automatic item requires no key or button edge. Its request carries kind 7, the copied item, zone X, zone Y, slot index and a request quantity of one. The eventual award count comes from the authoritative world drop. Before appending at the tail of the creature's pending-action queue, the scan looks for a pending action with the same kind, all three target integers and an equal item. An existing match suppresses the additional request. Other eligible slots can append during the same scan. The tested list is the pending-action queue. The scan does not consult an already-sent request ledger. These facts describe queue behavior and do not establish the number of requests delivered in any particular network session. The automatic branch does not run the manual bag or carrying-limit check. RVAs 0x8D590–0x8D701, 0x4DF60 and 0x2C3E48–0x2C3E95.

## Ordinary manual prompt and press

The manual branch re-resolves zone and signed slot index. A missing zone or invalid index ends processing. It copies the selected item to the displayed-item field and rechecks reservation. If the reservation now conflicts, it displays “Reserved” and leaves the action queue untouched. This second check matters because the earlier candidate test already filters reservations. RVAs 0x2B8FD0 and 0x8E182–0x8E2EC.

For a permitted reservation, the prompt first applies the carrying limit. If that passes, it applies the bag check for a single unit. Success displays “Pick up”. Failure of either check displays “Full”. The ordinary manual request requires a rising edge on logical action 11, named Use/Interact. The game remembers the current state for the next interaction pass. Holding the action leaves a normal item target eligible for display but does not issue another manual request. A later release and new press is a new input. RVAs 0x8E304–0x8E48E, 0x8E4AD–0x8E4BB, 0x8EB38–0x8EB40 and 0x42670.

On a new press, stock determines the automatic tab, repeats the carrying-limit test, and then checks the bag for one unit. A carrying-limit failure prints “You can't carry more of these items.” and queues error sound 0x34. A bag-check failure queues the same sound and has a specific bag-full message for Equipment, Items, Ingredients and Pets. No tab-specific line was found there for Specials or Artifacts. Success creates a fresh kind-7 request, copies the item and selected target triple, and inserts it at the **front** of the creature's action queue. The generic constructor initializes the request count to one. The manual insertion helper does not look for an equivalent pending action. An ordinary input queues a request and leaves bag insertion for the recipient's later notice. RVAs 0x8E4DD–0x8E775, 0x9660 and 0xA2130.

In focused gameplay, configured keyboard and mouse bindings feed the same action state. The two binding fields distinguish a keyboard state index from a mouse button index. The stock mouse reader accepts four button indices. The settings lookup maps ButtonUse to action 11. In the ordinary XInput gameplay branch, controller zero's A button (button mask 0x1000) also sets action 11. Controller UI navigation can instead consume that button. The ground-item press branch reads the shared logical state and does not select a different capacity or award rule for mouse versus controller. RVAs 0x42B30, 0x136745–0x1367C2, 0x137764–0x137790 and 0xA36C0.

## Two distinct capacity checks

All category and subtype IDs in this section are hexadecimal. The first check counts matching items only for categories 01, 0B, 15 and 18. It includes the quantity in the player's additional slot at +0xA08 if the item at +0xA0C matches, then sums equal items across every inventory tab. Other categories pass this check without a quantity scan. The comparison uses native item identity, including subtype, seed, region, rarity, material and active customization data. The drop's incoming stack count is not added when evaluating the limit. RVAs 0x50670 and 0x4DF60.

| Category and subtype | Existing matching count that blocks the request |
| --- | --- |
| 15 or 18 | 1 or more |
| 01, subtype 0C or 0E | 5 or more |
| 0B, subtypes 27 through 29 | 10 or more |
| Remaining cases within 01 or 0B | 50 or more |

For example, four matching category-01/subtype-0C items pass the carrying test, even if some are in the additional slot. A fifth already held makes it fail. Nine matching category-0B/subtype-28 ingredients pass and ten fail. These are limits on what is already held, not a maximum receive-stack size.

The second check selects the tab by category. Equipment is tab 0 for categories 03–09, 0F, 19 and 1A. Specials is tab 1 for 16, 18 and 1D. Ingredients is tab 3 for 02 and 0B. Pets is tab 4 for 14 and 15. Artifacts is tab 5 for 17. Other categories map to Items, tab 2. A zero category fails. The required tab must exist in the inventory's array of 24-byte tab descriptors. For a normal item in an existing tab, the helper scans its 0xA4-byte entries and can succeed early on an equal mergeable item. Reaching the end also succeeds, including when the tab contains no vacant slot. There is no ordinary fixed slot-count ceiling, screen-row calculation or inventory-full result simply because all existing entries are occupied. A missing tab is a real bag-check failure. RVAs 0x5F100, 0x8A381–0x8A3D2 and 0x8A470–0x8A4EF.

The native bag check has exceptional counter writes. Its accounting unit is one on the manual interaction, independently of drop quantity. Category 0C/material 0B addresses player gold, and category 0D addresses player +0xAB0, the counter also used for Mana Cubes. This differs from the normal receipt treatment of category 0D as a stackable item. For example, a category 0E Mana Cube receipt for four adds four to +0xAB0; a category 0D receipt for four can add four to its Items-tab stack. An ordinary four-unit ingredient receipt adds four to inventory and does not change either currency counter. These examples describe individual receipt effects. The native source does not establish a live session-total balance from receipt counts alone. RVAs 0x8A370, 0x4E810 and 0xAA721–0xAA7C5.

## Validation and limits

The original calls the world-eligibility, native carrying-limit and bag-presence routines directly. No optional callback for approval, tab size or pickup authorization appears in these branches. The host independently resolves the zone and current slot, checks distance and item identity, and emits the tagged recipient notice from the authoritative drop. The regular world slot is emptied on acceptance. With mask 0x02 set, the host retains the slot and the receiving local character has a separate collected-block check. The receipt check is independent of the client queue's automatic pending-duplicate comparison. RVAs 0x2C3C57–0x2C3D36, 0x2C3E48–0x2C3FB6 and 0xAA65D–0xAA721.

The audit does not assign stock semantics to external plugin hooks, establish default key bindings from a particular installation, reproduce exceptional counter accumulation, or measure frame cadence or transport retry timing. Other UI and creature interactions that can consume Use/Interact are outside the ground-item contract.
